# 8장. 클라이언트 구현

## 1. TCP 클라이언트 구현

### 1.1 기본 TCP 클라이언트

```rust
use tokio::net::TcpStream;
use tokio::io::{AsyncReadExt, AsyncWriteExt};
use std::error::Error;

struct TcpClient {
    host: String,
    port: u16,
    connection: Option<TcpStream>,
}

impl TcpClient {
    fn new(host: String, port: u16) -> Self {
        TcpClient {
            host,
            port,
            connection: None,
        }
    }

    async fn connect(&mut self) -> Result<(), Box<dyn Error>> {
        let addr = format!("{}:{}", self.host, self.port);
        match TcpStream::connect(addr).await {
            Ok(stream) => {
                self.connection = Some(stream);
                Ok(())
            }
            Err(e) => Err(Box::new(e)),
        }
    }

    async fn send(&mut self, data: &[u8]) -> Result<(), Box<dyn Error>> {
        if let Some(stream) = &mut self.connection {
            stream.write_all(data).await?;
            Ok(())
        } else {
            Err("Not connected".into())
        }
    }

    async fn receive(&mut self) -> Result<Vec<u8>, Box<dyn Error>> {
        if let Some(stream) = &mut self.connection {
            let mut buffer = vec![0; 1024];
            let n = stream.read(&mut buffer).await?;
            buffer.truncate(n);
            Ok(buffer)
        } else {
            Err("Not connected".into())
        }
    }
}
```

### 1.2 비동기 클라이언트 구현

```rust
use tokio::time::{timeout, Duration};

struct AsyncClient {
    client: TcpClient,
    timeout_duration: Duration,
}

impl AsyncClient {
    fn new(host: String, port: u16, timeout_secs: u64) -> Self {
        AsyncClient {
            client: TcpClient::new(host, port),
            timeout_duration: Duration::from_secs(timeout_secs),
        }
    }

    async fn send_with_timeout(&mut self, data: &[u8]) -> Result<Vec<u8>, Box<dyn Error>> {
        // 타임아웃과 함께 요청 전송
        match timeout(self.timeout_duration, async {
            self.client.send(data).await?;
            self.client.receive().await
        }).await {
            Ok(result) => result,
            Err(_) => Err("Operation timed out".into()),
        }
    }
}
```
  

## 2. 연결 풀링

### 2.1 연결 풀 구현

```rust
use std::collections::VecDeque;

struct ConnectionPool {
    connections: VecDeque<TcpStream>,
    host: String,
    port: u16,
    max_size: usize,
}

impl ConnectionPool {
    fn new(host: String, port: u16, max_size: usize) -> Self {
        ConnectionPool {
            connections: VecDeque::with_capacity(max_size),
            host,
            port,
            max_size,
        }
    }

    async fn get_connection(&mut self) -> Result<TcpStream, Box<dyn Error>> {
        if let Some(conn) = self.connections.pop_front() {
            Ok(conn)
        } else if self.connections.len() < self.max_size {
            let addr = format!("{}:{}", self.host, self.port);
            let conn = TcpStream::connect(addr).await?;
            Ok(conn)
        } else {
            Err("Connection pool exhausted".into())
        }
    }

    async fn return_connection(&mut self, conn: TcpStream) {
        if self.connections.len() < self.max_size {
            self.connections.push_back(conn);
        }
    }
}
```

### 2.2 연결 풀 관리자

```rust
struct PoolManager {
    pool: ConnectionPool,
    min_connections: usize,
}

impl PoolManager {
    async fn initialize(&mut self) -> Result<(), Box<dyn Error>> {
        // 최소 연결 수만큼 미리 연결 생성
        while self.pool.connections.len() < self.min_connections {
            let addr = format!("{}:{}", self.pool.host, self.pool.port);
            let conn = TcpStream::connect(addr).await?;
            self.pool.connections.push_back(conn);
        }
        Ok(())
    }

    async fn cleanup_idle_connections(&mut self) {
        // 오래된 연결 정리
        let idle_timeout = Duration::from_secs(300); // 5분
        self.pool.connections.retain(|conn| {
            // 연결 상태 확인 로직
            true
        });
    }
}
```

## 3. 재연결 전략

### 3.1 지수 백오프 재시도

```rust
struct RetryStrategy {
    max_retries: u32,
    initial_delay: Duration,
    max_delay: Duration,
}

impl RetryStrategy {
    async fn connect_with_retry(&self, client: &mut TcpClient) -> Result<(), Box<dyn Error>> {
        let mut retries = 0;
        let mut delay = self.initial_delay;

        while retries < self.max_retries {
            match client.connect().await {
                Ok(_) => return Ok(()),
                Err(e) => {
                    println!("Connection failed, attempt {}/{}: {}",
                        retries + 1, self.max_retries, e);
                    retries += 1;

                    if retries < self.max_retries {
                        tokio::time::sleep(delay).await;
                        delay = std::cmp::min(delay * 2, self.max_delay);
                    }
                }
            }
        }

        Err("Max retries exceeded".into())
    }
}
```

### 3.2 연결 상태 모니터링

```rust
struct ConnectionMonitor {
    heartbeat_interval: Duration,
    client: TcpClient,
}

impl ConnectionMonitor {
    async fn monitor(&mut self) {
        loop {
            tokio::time::sleep(self.heartbeat_interval).await;

            if let Err(_) = self.send_heartbeat().await {
                println!("Heartbeat failed, attempting reconnection...");
                if let Err(e) = self.client.connect().await {
                    println!("Reconnection failed: {}", e);
                }
            }
        }
    }

    async fn send_heartbeat(&mut self) -> Result<(), Box<dyn Error>> {
        self.client.send(b"ping").await?;
        let response = self.client.receive().await?;
        if response != b"pong" {
            return Err("Invalid heartbeat response".into());
        }
        Ok(())
    }
}
```
  

## 4. 요청/응답 처리

### 4.1 요청/응답 핸들러

```rust
#[derive(Debug)]
struct Request {
    id: String,
    method: String,
    data: Vec<u8>,
}

#[derive(Debug)]
struct Response {
    id: String,
    status: u16,
    data: Vec<u8>,
}

struct RequestHandler {
    client: AsyncClient,
}

impl RequestHandler {
    async fn send_request(&mut self, request: Request) -> Result<Response, Box<dyn Error>> {
        // 요청 직렬화
        let serialized = self.serialize_request(&request)?;

        // 요청 전송 및 응답 수신
        let raw_response = self.client.send_with_timeout(&serialized).await?;

        // 응답 역직렬화
        self.deserialize_response(&raw_response)
    }

    fn serialize_request(&self, request: &Request) -> Result<Vec<u8>, Box<dyn Error>> {
        // 실제 구현에서는 JSON, Protocol Buffers 등을 사용
        Ok(format!("{}:{}:{}", request.id, request.method,
            String::from_utf8_lossy(&request.data)).into_bytes())
    }

    fn deserialize_response(&self, data: &[u8]) -> Result<Response, Box<dyn Error>> {
        // 응답 파싱 구현
        Ok(Response {
            id: "test".to_string(),
            status: 200,
            data: data.to_vec(),
        })
    }
}
```
  

## 5. 타임아웃과 재시도 로직

### 5.1 타임아웃 처리

```rust
struct TimeoutHandler {
    operation_timeout: Duration,
    retry_strategy: RetryStrategy,
}

impl TimeoutHandler {
    async fn execute_with_timeout<F, T>(&self, operation: F) -> Result<T, Box<dyn Error>>
    where
        F: Future<Output = Result<T, Box<dyn Error>>>,
    {
        match timeout(self.operation_timeout, operation).await {
            Ok(result) => result,
            Err(_) => Err("Operation timed out".into()),
        }
    }
}
```

### 5.2 재시도 로직

```rust
struct RetryableOperation<T> {
    operation: Box<dyn Fn() -> Future<Output = Result<T, Box<dyn Error>>>>,
    retry_strategy: RetryStrategy,
}

impl<T> RetryableOperation<T> {
    async fn execute(&self) -> Result<T, Box<dyn Error>> {
        let mut retries = 0;
        let mut delay = self.retry_strategy.initial_delay;

        loop {
            match self.execute_with_timeout().await {
                Ok(result) => return Ok(result),
                Err(e) => {
                    if retries >= self.retry_strategy.max_retries {
                        return Err(e);
                    }

                    println!("Operation failed, retrying in {:?}: {}", delay, e);
                    tokio::time::sleep(delay).await;

                    retries += 1;
                    delay = std::cmp::min(delay * 2, self.retry_strategy.max_delay);
                }
            }
        }
    }

    async fn execute_with_timeout(&self) -> Result<T, Box<dyn Error>> {
        timeout(self.retry_strategy.initial_delay * 2, (self.operation)()).await?
    }
}
```

이 장에서는 TCP 클라이언트 구현의 주요 구성 요소들을 다루었다. 특히 다음 내용을 살펴보았다.

1. 기본적인 TCP 클라이언트 구조와 비동기 처리
2. 효율적인 연결 관리를 위한 연결 풀링
3. 안정적인 연결 유지를 위한 재연결 전략
4. 구조화된 요청/응답 처리
5. 안정성을 위한 타임아웃과 재시도 처리

구현 시 주의사항은 다음과 같다.

- 연결 풀의 크기는 애플리케이션의 요구사항에 맞게 조정
- 재연결 전략은 네트워크 환경을 고려하여 설정
- 타임아웃 값은 실제 운영 환경에 맞게 설정
- 재시도 로직은 무한 루프에 빠지지 않도록 주의

이러한 요소들을 적절히 조합하면 안정적이고 효율적인 네트워크 클라이언트를 구현할 수 있다.
