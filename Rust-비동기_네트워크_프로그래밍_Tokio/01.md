# 1장. Tokio 소개

## 비동기 프로그래밍의 기초
비동기 프로그래밍은 현대 네트워크 애플리케이션에서 필수적인 패러다임이다. 전통적인 동기식 프로그래밍과 달리, 비동기 프로그래밍은 작업이 완료되기를 기다리는 동안 다른 작업을 수행할 수 있게 해준다.

### 동기식 vs 비동기식 프로그래밍

```rust
// 동기식 코드
fn sync_read_file(path: &str) -> String {
    std::fs::read_to_string(path).unwrap()
}

// 비동기식 코드
async fn async_read_file(path: &str) -> String {
    tokio::fs::read_to_string(path).await.unwrap()
}
```

동기식 코드에서는 파일을 읽는 동안 스레드가 블록되지만, 비동기식 코드에서는 파일 읽기를 기다리는 동안 다른 작업을 수행할 수 있다.

### Future와 Promise
Rust의 비동기 프로그래밍은 Future 트레이트를 중심으로 구성된다. Future는 나중에 완료될 수 있는 작업을 표현한다.

```rust
use std::future::Future;

async fn example() -> i32 {
    // 비동기 작업 수행
    42
}

// Future를 반환하는 함수
fn returns_future() -> impl Future<Output = i32> {
    async {
        let result = example().await;
        result + 1
    }
}
```

## Tokio가 필요한 이유
Tokio는 Rust 생태계에서 가장 널리 사용되는 비동기 런타임이다. 다음과 같은 이유로 Tokio가 필요하다.

1. 효율적인 리소스 사용
   - 적은 수의 스레드로 많은 동시 연결 처리
   - 시스템 리소스의 최적화된 사용

2. 고성능
   - 이벤트 기반 아키텍처
   - 최소한의 오버헤드
   - 효율적인 작업 스케줄링

3. 안정성
   - 타입 안전성
   - 메모리 안전성
   - 스레드 안전성

예제 코드: tokio_01

```rust
use tokio::net::TcpListener;
use tokio::io::{AsyncReadExt, AsyncWriteExt};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let listener = TcpListener::bind("127.0.0.1:8080").await?;

    loop {
        let (mut socket, _) = listener.accept().await?;

        tokio::spawn(async move {
            let mut buf = [0; 1024];

            loop {
                let n = match socket.read(&mut buf).await {
                    Ok(n) if n == 0 => return,
                    Ok(n) => n,
                    Err(_) => return,
                };

                if let Err(_) = socket.write_all(&buf[0..n]).await {
                    return;
                }
            }
        });
    }
}
```

이 코드는 Rust로 작성된 TCP 에코 서버이다.

**1. 의존성 및 임포트:**

```rust
use tokio::net::TcpListener;
use tokio::io::{AsyncReadExt, AsyncWriteExt};
```

- `TcpListener`: TCP 연결을 수신하기 위한 리스너
- `AsyncReadExt`, `AsyncWriteExt`: 비동기 입출력 작업을 위한 트레이트

**2. 메인 함수 선언:**

```rust
#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>>
```

- `#[tokio::main]`: 비동기 런타임을 설정하는 매크로
- 함수는 `Result` 타입을 반환하며, 에러는 동적 디스패치(`Box<dyn Error>`)를 사용

**3. TCP 리스너 설정:**

```rust
let listener = TcpListener::bind("127.0.0.1:32451").await?;
```

- 로컬호스트(127.0.0.1)의 32451 포트에서 TCP 연결을 수신
- `.await?`는 비동기 작업의 결과를 기다리고 에러를 전파

**4. 연결 수신 루프:**

```rust
loop {
    let (mut socket, _) = listener.accept().await?;
```

- 무한 루프로 새로운 연결을 계속 수신
- `accept()`는 새로운 TCP 연결을 수락하고 소켓과 주소를 반환
- `_`는 클라이언트 주소 정보를 무시

**5. 각 연결에 대한 비동기 태스크 생성:**

```rust
tokio::spawn(async move { ... });
```

- 각 클라이언트 연결을 별도의 태스크로 처리
- `spawn`은 새로운 비동기 태스크를 생성

**6. 데이터 처리 루프:**

```rust
let mut buf = [0; 1024];
loop {
    let n = match socket.read(&mut buf).await {
        Ok(n) if n == 0 => return,
        Ok(n) => n,
        Err(_) => return,
    };
```

- 1024 바이트 크기의 버퍼 생성
- `socket.read()`로 데이터를 비동기적으로 읽음
- `n == 0`은 연결이 종료됨을 의미
- 에러 발생 시 태스크 종료

**7. 에코 응답:**

```rust
if let Err(_) = socket.write_all(&buf[0..n]).await {
    return;
}
```

- 읽은 데이터를 그대로 클라이언트에게 다시 전송
- 쓰기 실패 시 태스크 종료

**이 서버의 특징:**

- 비동기 I/O를 사용하여 효율적인 리소스 사용
- 다중 클라이언트 동시 처리 가능
- 각 클라이언트 연결을 독립적인 태스크로 처리
- 에러 처리가 포함된 안전한 구현
- 간단한 에코 서버 기능 (받은 데이터를 그대로 반환)
  

## Tokio의 주요 특징

1. 멀티스레딩 지원
   - 작업을 여러 스레드에 분산
   - 워커 스레드 풀 관리

2. 비동기 I/O
   - 네트워크 작업
   - 파일 시스템 작업
   - 타이머와 시간 관리

3. 채널 기반 통신

```rust
use tokio::sync::mpsc;

async fn channel_example() {
    let (tx, mut rx) = mpsc::channel(100);

    tokio::spawn(async move {
        for i in 0..10 {
            tx.send(i).await.unwrap();
        }
    });

    while let Some(i) = rx.recv().await {
        println!("received: {}", i);
    }
}
```

### Rust의 async/await 문법
async/await는 비동기 코드를 동기 코드처럼 작성할 수 있게 해주는 문법적 기능이다.

```rust
async fn fetch_data(url: &str) -> Result<String, Box<dyn std::error::Error>> {
    let response = reqwest::get(url).await?;
    let body = response.text().await?;
    Ok(body)
}

async fn process_data() -> Result<(), Box<dyn std::error::Error>> {
    let data = fetch_data("https://example.com").await?;
    println!("받은 데이터: {}", data);
    Ok(())
}
```

### 주요 개념
- async 키워드: 비동기 함수나 블록을 정의
- .await: Future의 완료를 기다림
- Pin: Future의 메모리 위치를 고정
  

## 동시성과 병렬성의 이해

### 동시성 (Concurrency)
- 여러 작업을 번갈아가며 실행
- 단일 코어에서도 가능
- I/O 바운드 작업에 효과적

### 병렬성 (Parallelism)
- 여러 작업을 실제로 동시에 실행
- 멀티 코어가 필요
- CPU 바운드 작업에 효과적

```rust
// 동시성 예제
async fn concurrent_tasks() {
    let task1 = async {
        // I/O 작업
        tokio::time::sleep(tokio::time::Duration::from_secs(1)).await;
        println!("Task 1 완료");
    };

    let task2 = async {
        // I/O 작업
        tokio::time::sleep(tokio::time::Duration::from_secs(1)).await;
        println!("Task 2 완료");
    };

    // 두 작업을 동시에 실행
    tokio::join!(task1, task2);
}

// 병렬성 예제
fn parallel_tasks() {
    // 멀티스레드 런타임 사용
    let runtime = tokio::runtime::Runtime::new().unwrap();

    runtime.block_on(async {
        let handle1 = tokio::spawn(async {
            // CPU 집중 작업
            heavy_computation().await;
        });

        let handle2 = tokio::spawn(async {
            // CPU 집중 작업
            heavy_computation().await;
        });

        // 두 작업이 완료될 때까지 대기
        let _ = tokio::join!(handle1, handle2);
    });
}
```

위 코드 중 `runtime.block_on(` 부분에 대한 설명이다.

```rust
let runtime = tokio::runtime::Runtime::new().unwrap();
runtime.block_on(async {
    let handle1 = tokio::spawn(async {
        // CPU 집중 작업
        heavy_computation().await;
    });
```

1. 런타임 생성:

```rust
let runtime = tokio::runtime::Runtime::new().unwrap();
```

- `tokio::runtime::Runtime::new()`: Tokio의 기본 멀티스레드 런타임을 생성
- `.unwrap()`: 런타임 생성 실패시 패닉 발생
- 이 런타임은 기본적으로 워커 스레드 풀, I/O 이벤트 루프, 타이머, 스케줄러를 포함

2. 비동기 실행 블록:

```rust
runtime.block_on(async {
    // 비동기 코드
});
```

- `block_on`: 비동기 코드를 동기적으로 실행하는 메서드
- 현재 스레드를 블록하고 비동기 작업이 완료될 때까지 대기
- 주로 프로그램의 진입점에서 사용

3. 태스크 생성:

```rust
let handle1 = tokio::spawn(async {
    // CPU 집중 작업
    heavy_computation().await;
});
```

- `tokio::spawn`: 새로운 비동기 태스크를 생성
- 반환값은 `JoinHandle`로, 태스크의 완료를 기다리거나 취소할 수 있음
- 이 태스크는 런타임의 워커 스레드 풀에서 실행됨

이 패턴의 주요 사용 사례는 다음과 같다.

1. CPU 집중 작업의 비동기 실행
2. 여러 작업의 동시 실행
3. 백그라운드 작업 처리
4. 네트워크 요청 처리

주의사항은 다음과 같다.

1. `block_on` 내부에서 현재 스레드를 블록하는 작업은 피해야 함
2. CPU 집중 작업은 `spawn_blocking`을 사용하는 것이 좋음
3. 메인 함수에서는 `#[tokio::main]` 매크로를 사용하는 것이 더 일반적

### spawn_blocking 이 CPU 집중 작업에 더 적합한 이유

1. 기본 `tokio::spawn`과 `spawn_blocking`의 차이:

```rust
// 1. 일반적인 tokio::spawn 사용
tokio::spawn(async {
    // 이 작업은 비동기 런타임의 워커 스레드에서 실행됨
    // 다른 비동기 작업들과 같은 스레드 풀을 공유
    cpu_intensive_work();
});

// 2. spawn_blocking 사용
tokio::task::spawn_blocking(|| {
    // 이 작업은 별도의 전용 스레드 풀에서 실행됨
    cpu_intensive_work();
});
```

예시 코드로 차이점을 설명한다.

```rust
use tokio;
use std::time::Duration;

// CPU 집중 작업을 시뮬레이션하는 함수
fn cpu_intensive_work() -> u64 {
    let mut result = 0u64;
    for i in 0..1000000000 {  // 무거운 계산
        result = result.wrapping_add(i);
    }
    result
}

#[tokio::main]
async fn main() {
    // 1. 잘못된 방법: tokio::spawn 사용
    let handle1 = tokio::spawn(async {
        // 이는 비동기 런타임의 워커 스레드를 차단할 수 있음
        cpu_intensive_work()
    });

    // 2. 올바른 방법: spawn_blocking 사용
    let handle2 = tokio::task::spawn_blocking(|| {
        // 별도의 스레드 풀에서 실행되어 비동기 작업에 영향을 주지 않음
        cpu_intensive_work()
    });

    // 동시에 다른 비동기 작업 실행
    let async_task = tokio::spawn(async {
        for i in 0..5 {
            println!("Async task working: {}", i);
            tokio::time::sleep(Duration::from_millis(100)).await;
        }
    });

    // 결과 대기
    let result1 = handle1.await.unwrap();
    let result2 = handle2.await.unwrap();
    async_task.await.unwrap();
}
```

2. `spawn_blocking`의 장점:

```rust
use tokio;
use std::time::Duration;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 여러 개의 작업을 동시에 처리하는 예제
    let mut handles = vec![];

    // 1. CPU 집중 작업들
    for i in 0..3 {
        let handle = tokio::task::spawn_blocking(move || {
            println!("Starting CPU-intensive task {}", i);
            let result = cpu_intensive_work();
            println!("Completed CPU-intensive task {}", i);
            result
        });
        handles.push(handle);
    }

    // 2. 일반적인 비동기 I/O 작업들
    for i in 0..5 {
        let handle = tokio::spawn(async move {
            println!("Starting async I/O task {}", i);
            tokio::time::sleep(Duration::from_millis(100)).await;
            println!("Completed async I/O task {}", i);
        });
        handles.push(handle);
    }

    // 모든 작업 완료 대기
    for handle in handles {
        handle.await?;
    }

    Ok(())
}

// CPU 집중 작업과 I/O 작업의 성능 비교를 위한 벤치마크
#[cfg(test)]
mod tests {
    use super::*;
    use std::time::Instant;

    #[tokio::test]
    async fn benchmark_tasks() {
        // 1. spawn_blocking 사용
        let start = Instant::now();
        let handle1 = tokio::task::spawn_blocking(|| {
            cpu_intensive_work();
        });

        // 2. 일반 spawn 사용
        let handle2 = tokio::spawn(async {
            cpu_intensive_work();
        });

        // 결과 대기
        handle1.await.unwrap();
        handle2.await.unwrap();

        println!("Total time: {:?}", start.elapsed());
    }
}
```

3. 실제 사용 사례:

```rust
use tokio;
use std::fs;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 1. 파일 처리 작업 (CPU 집중)
    let file_processing = tokio::task::spawn_blocking(|| {
        // 큰 파일 읽기 및 처리
        let contents = fs::read_to_string("large_file.txt")?;
        process_file_contents(&contents)
    });

    // 2. 동시에 다른 비동기 작업 실행
    let async_work = tokio::spawn(async {
        // 네트워크 요청 등의 비동기 작업
        tokio::time::sleep(Duration::from_secs(1)).await;
        Ok::<_, std::io::Error>(())
    });

    // 둘 다 완료될 때까지 대기
    let (file_result, async_result) = tokio::join!(file_processing, async_work);

    Ok(())
}
```

주요 이점은 다음과 같다.

1. **스레드 풀 분리**:
   - CPU 집중 작업이 비동기 이벤트 루프를 차단하지 않음
   - I/O 작업의 응답성 유지

2. **리소스 최적화**:
   - CPU 집중 작업을 위한 전용 스레드 풀 사용
   - 비동기 워커 스레드의 효율적인 사용

3. **성능 향상**:
   - 더 나은 작업 분배
   - 전체 시스템 처리량 개선

4. **예측 가능한 동작**:
   - CPU 집중 작업과 I/O 작업의 명확한 분리
   - 리소스 경쟁 감소

주의사항은 다음과 같다.

1. 너무 많은 `spawn_blocking` 작업은 시스템 리소스를 고갈시킬 수 있음
2. 작은 CPU 작업의 경우 일반 `spawn`이 더 효율적일 수 있음
3. 블로킹 작업의 크기와 빈도를 고려하여 적절히 사용
