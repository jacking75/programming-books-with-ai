# 📚 1부: 기초 이론

## 1.1 메모리 모델이란?

### 왜 메모리 모델이 필요한가?

현대의 멀티코어 시스템에서 여러 스레드가 동시에 실행될 때, 각 스레드가 메모리를 어떻게 읽고 쓰는지에 대한 명확한 규칙이 필요하다. 메모리 모델은 바로 이러한 규칙을 정의한다.

간단한 예제를 살펴보자:

```cpp
#include <iostream>
#include <thread>

// 전역 변수 (문제가 있는 코드)
int data = 0;
bool ready = false;

void producer() {
    data = 42;        // (1) 데이터 저장
    ready = true;     // (2) 준비 완료 플래그 설정
}

void consumer() {
    while (!ready) {  // (3) 준비될 때까지 대기
        // 대기 중...
    }
    std::cout << "Data: " << data << std::endl;  // (4) 데이터 읽기
}

int main() {
    std::thread t1(producer);
    std::thread t2(consumer);
    
    t1.join();
    t2.join();
    
    return 0;
}
```

이 코드는 언뜻 보면 정상적으로 동작할 것 같지만, 실제로는 다음과 같은 문제가 발생할 수 있다:

1. **데이터 레이스**: `data`와 `ready` 변수에 대한 동시 접근
2. **예상치 못한 출력**: `Data: 0`이 출력될 수 있음
3. **무한 루프**: `ready`의 변경사항이 consumer 스레드에 보이지 않을 수 있음

```
Thread 1 (Producer)          Thread 2 (Consumer)
    |                             |
    | data = 42                   |
    |                             |
    | ready = true                |
    |                             | while (!ready) {...}
    |                             | // ready가 여전히 false로 보일 수 있음!
    |                             |
```

메모리 모델은 이러한 문제를 해결하기 위한 도구를 제공한다.

### CPU 캐시와 메모리 일관성 문제

현대 CPU는 성능 향상을 위해 여러 단계의 캐시를 사용한다.

```
CPU 아키텍처 구조:

Core 0                          Core 1
┌─────────────┐                ┌─────────────┐
│   Thread    │                │   Thread    │
│   ┌─────┐   │                │   ┌─────┐   │
│   │ ALU │   │                │   │ ALU │   │
│   └─────┘   │                │   └─────┘   │
│      ↕      │                │      ↕      │
│   L1 Cache  │                │   L1 Cache  │
│   (32 KB)   │                │   (32 KB)   │
└──────┬──────┘                └──────┬──────┘
       │                              │
       └──────────┬───────────────────┘
                  ↓
           ┌─────────────┐
           │  L2 Cache   │
           │   (256 KB)  │
           └──────┬──────┘
                  ↓
           ┌─────────────┐
           │  L3 Cache   │
           │   (8 MB)    │
           └──────┬──────┘
                  ↓
           ┌─────────────┐
           │ Main Memory │
           │   (RAM)     │
           └─────────────┘
```

각 코어가 자신의 캐시를 가지고 있기 때문에 메모리 일관성 문제가 발생한다:

```cpp
#include <iostream>
#include <thread>
#include <chrono>

int x = 0;
int y = 0;

void thread1() {
    x = 1;  // Core 0의 L1 캐시에만 쓰일 수 있음
    std::cout << "y = " << y << std::endl;
}

void thread2() {
    y = 1;  // Core 1의 L1 캐시에만 쓰일 수 있음
    std::cout << "x = " << x << std::endl;
}

int main() {
    // 이 프로그램은 다음의 출력을 모두 생성할 수 있다:
    // y = 0, x = 1
    // y = 1, x = 0
    // y = 1, x = 1
    // y = 0, x = 0  <- 놀랍게도 이것도 가능!
    
    std::thread t1(thread1);
    std::thread t2(thread2);
    
    t1.join();
    t2.join();
    
    return 0;
}
```

**캐시 일관성 시나리오:**

```
시간 →

T0: Core 0: x = 1 (L1 캐시에만 저장됨)
T1: Core 1: y = 1 (L1 캐시에만 저장됨)
T2: Core 0: y 읽기 (아직 0으로 보임)
T3: Core 1: x 읽기 (아직 0으로 보임)
T4: 캐시 동기화 발생

결과: x = 0, y = 0 출력!
```

### 컴파일러 최적화와 명령어 재배치

컴파일러와 CPU는 성능을 위해 명령어 순서를 재배치할 수 있다.

**원본 코드:**
```cpp
int compute() {
    int a = expensive_function1();
    int b = expensive_function2();
    return a + b;
}
```

**컴파일러가 최적화한 코드:**
```cpp
int compute() {
    // 두 함수가 서로 독립적이므로 순서를 바꿀 수 있음
    int b = expensive_function2();
    int a = expensive_function1();
    return a + b;
}
```

멀티스레드 환경에서 이는 문제가 될 수 있다:

```cpp
#include <thread>

int data = 0;
bool ready = false;

void producer() {
    data = 42;
    ready = true;
}

// 컴파일러가 재배치할 수 있음:
void producer_optimized() {
    ready = true;   // 순서가 바뀜!
    data = 42;
}
```

**재배치 예제:**

```
원래 의도한 순서:              실제 실행 순서:
┌─────────────┐                ┌─────────────┐
│ data = 42   │                │ ready = true│
└──────┬──────┘                └──────┬──────┘
       │                              │
       ↓                              ↓
┌─────────────┐                ┌─────────────┐
│ready = true │                │ data = 42   │
└─────────────┘                └─────────────┘
```

**올바른 구현 (atomic 사용):**

```cpp
#include <iostream>
#include <thread>
#include <atomic>

int data = 0;
std::atomic<bool> ready(false);

void producer() {
    data = 42;
    ready.store(true, std::memory_order_release);  // 명시적 메모리 순서
}

void consumer() {
    while (!ready.load(std::memory_order_acquire)) {
        // 대기
    }
    std::cout << "Data: " << data << std::endl;  // 항상 42 출력
}

int main() {
    std::thread t1(producer);
    std::thread t2(consumer);
    
    t1.join();
    t2.join();
    
    return 0;
}
```

## 1.2 순차 일관성(Sequential Consistency)의 이해

### 단일 스레드 vs 멀티 스레드 실행

**단일 스레드 환경:**

단일 스레드에서는 프로그램이 작성된 순서대로 실행되는 것처럼 보인다 (as-if 규칙).

```cpp
#include <iostream>

void single_threaded() {
    int a = 1;        // (1)
    int b = 2;        // (2)
    int c = a + b;    // (3)
    std::cout << c;   // (4) 항상 3 출력
}

// 컴파일러는 내부적으로 최적화할 수 있지만,
// 결과는 항상 (1) → (2) → (3) → (4) 순서로 실행한 것과 같다
```

**멀티 스레드 환경:**

멀티 스레드에서는 실행 순서가 복잡해진다.

```cpp
#include <iostream>
#include <thread>

int x = 0, y = 0;
int r1 = 0, r2 = 0;

void thread1() {
    x = 1;      // (A)
    r1 = y;     // (B)
}

void thread2() {
    y = 1;      // (C)
    r2 = x;     // (D)
}

int main() {
    std::thread t1(thread1);
    std::thread t2(thread2);
    
    t1.join();
    t2.join();
    
    // 가능한 결과:
    // r1 = 0, r2 = 1
    // r1 = 1, r2 = 0
    // r1 = 1, r2 = 1
    // r1 = 0, r2 = 0  (!)
    
    std::cout << "r1 = " << r1 << ", r2 = " << r2 << std::endl;
    
    return 0;
}
```

### 프로그램 순서와 실행 순서의 차이

**프로그램 순서 (Program Order):** 소스 코드에 작성된 순서

**실행 순서 (Execution Order):** 실제로 하드웨어에서 실행되는 순서

```
프로그램 순서:                실제 실행 순서 (가능한 경우):

Thread 1:                     Thread 1:
  A: x = 1                      B: r1 = y  (재배치!)
  B: r1 = y                     A: x = 1

Thread 2:                     Thread 2:
  C: y = 1                      D: r2 = x  (재배치!)
  D: r2 = x                     C: y = 1

결과: r1 = 0, r2 = 0
```

**실행 순서 시각화:**

```
시간 →

가능한 인터리빙 1:
T1: ─A─────B─────→
T2: ───C─────D───→
결과: r1=0, r2=1

가능한 인터리빙 2:
T1: ───A─────B───→
T2: ─C─────D─────→
결과: r1=1, r2=0

가능한 인터리빙 3 (재배치 발생):
T1: ──B──A───────→
T2: ──D──C───────→
결과: r1=0, r2=0 (!!)
```

**순차 일관성을 보장하는 코드:**

```cpp
#include <iostream>
#include <thread>
#include <atomic>

std::atomic<int> x(0);
std::atomic<int> y(0);

void thread1() {
    x.store(1, std::memory_order_seq_cst);
    int r1 = y.load(std::memory_order_seq_cst);
    std::cout << "r1 = " << r1 << std::endl;
}

void thread2() {
    y.store(1, std::memory_order_seq_cst);
    int r2 = x.load(std::memory_order_seq_cst);
    std::cout << "r2 = " << r2 << std::endl;
}

int main() {
    std::thread t1(thread1);
    std::thread t2(thread2);
    
    t1.join();
    t2.join();
    
    // r1 = 0, r2 = 0은 이제 불가능!
    // 가능한 결과: (0,1), (1,0), (1,1)
    
    return 0;
}
```

### ASCII 다이어그램으로 보는 메모리 가시성

**메모리 가시성 문제:**

```
일반 변수 사용 시:

Core 0 (Thread 1)              Core 1 (Thread 2)
┌──────────────┐              ┌──────────────┐
│              │              │              │
│  x = 1 ────┐ │              │              │
│            │ │              │              │
│            ↓ │              │              │
│  [L1: x=1]  │              │  [L1: x=0]  │← 여전히 옛날 값!
│            │ │              │     ↑        │
│            │ │              │     │        │
│  r1 = y ←──┼─┼──────────────┼─────┘        │
│            │ │              │              │
└────────────┼─┘              └──────────────┘
             │
             ↓ (나중에 동기화)
      [Main Memory: x=1]
```

**Atomic 변수 사용 시:**

```
std::atomic 사용 시:

Core 0 (Thread 1)              Core 1 (Thread 2)
┌──────────────┐              ┌──────────────┐
│              │              │              │
│x.store(1)──┐ │              │              │
│            │ │              │              │
│            ↓ │              │              │
│  [L1: x=1]──┼─┼──────────┐  │              │
│             │ │          │  │              │
│             │ │          ↓  │              │
└─────────────┼─┘   [Memory Fence]           │
              │              │  │              │
              └──────────────┼──┼→ 즉시 동기화│
                             │  │              │
                             ↓  │              │
                      [Main Memory: x=1]      │
                             │  │              │
                             │  └→[L1: x=1]   │
                             │       ↓         │
                             │   y.load() ←────┘
                             │                 │
                             └─────────────────┘
```

**순차 일관성 보장:**

```
Sequential Consistency 모델:

모든 스레드가 동일한 실행 순서를 관찰

Thread 1    Thread 2    전역적으로 보이는 순서
   │           │        
   A           │        Global: A
   │           │        
   │           C        Global: A → C
   │           │        
   B           │        Global: A → C → B
   │           │        
   │           D        Global: A → C → B → D

모든 스레드가 A → C → B → D 순서로 관찰
```

**비순차적 실행 (Relaxed 모델):**

```
Relaxed Memory Model:

Thread 1이 보는 순서:  A → B → C → D
Thread 2가 보는 순서:  C → A → D → B
Thread 3이 보는 순서:  A → C → B → D

각 스레드마다 다른 순서로 이벤트를 관찰할 수 있음!
```

## 1.3 C++ 메모리 순서의 6가지 타입

C++11부터 제공되는 6가지 메모리 순서는 성능과 정확성 사이의 트레이드오프를 제어한다.

### 메모리 순서 계층 구조

```
강한 보장 (느림)
    ↑
    │
    ├─ memory_order_seq_cst    (순차 일관성)
    │
    ├─ memory_order_acq_rel    (획득-방출)
    │
    ├─ memory_order_release    (방출)
    ├─ memory_order_acquire    (획득)
    ├─ memory_order_consume    (소비 - deprecated)
    │
    └─ memory_order_relaxed    (완화)
    │
    ↓
약한 보장 (빠름)
```

### 1. memory_order_relaxed

가장 약한 메모리 순서로, 원자성만 보장하고 순서는 보장하지 않는다.

```cpp
#include <iostream>
#include <thread>
#include <atomic>
#include <vector>

std::atomic<int> counter(0);

void increment_relaxed() {
    for (int i = 0; i < 100000; ++i) {
        counter.fetch_add(1, std::memory_order_relaxed);
    }
}

int main() {
    std::vector<std::thread> threads;
    
    for (int i = 0; i < 10; ++i) {
        threads.emplace_back(increment_relaxed);
    }
    
    for (auto& t : threads) {
        t.join();
    }
    
    std::cout << "Counter: " << counter.load(std::memory_order_relaxed) << std::endl;
    // 항상 1000000 출력 (원자성은 보장됨)
    
    return 0;
}
```

**특징:**
- 원자성만 보장
- 다른 메모리 연산과의 순서 보장 없음
- 가장 빠름
- 단순 카운터에 적합

```
Relaxed 순서의 동작:

Thread 1:                Thread 2:
counter += 1 (A)         counter += 1 (C)
data = 42 (B)            result = data (D)

가능한 실행 순서:
A → C → B → D
C → A → B → D
A → B → C → D
C → D → A → B  (!)
```

### 2. memory_order_consume (C++17에서 deprecated)

`memory_order_acquire`의 약한 버전으로, 의존성이 있는 로드만 순서를 보장한다.

```cpp
#include <atomic>
#include <thread>
#include <string>

std::atomic<std::string*> ptr(nullptr);
int data;

void producer() {
    std::string* p = new std::string("Hello");
    data = 42;
    ptr.store(p, std::memory_order_release);
}

void consumer() {
    std::string* p;
    while (!(p = ptr.load(std::memory_order_consume))) {
        // 대기
    }
    // p를 통한 접근은 동기화됨
    // data는 동기화 보장 없음 (의존성 없음)
}
```

**주의:** C++17부터 deprecated 되었으므로 `memory_order_acquire` 사용을 권장한다.

### 3. memory_order_acquire

로드 연산에 사용되며, 이 연산 이후의 모든 읽기/쓰기가 재배치되지 않도록 보장한다.

```cpp
#include <iostream>
#include <thread>
#include <atomic>

std::atomic<bool> ready(false);
int data = 0;

void producer() {
    data = 42;
    ready.store(true, std::memory_order_release);
}

void consumer() {
    while (!ready.load(std::memory_order_acquire)) {
        // 대기
    }
    // 여기서 data는 항상 42
    std::cout << "Data: " << data << std::endl;
}

int main() {
    std::thread t1(producer);
    std::thread t2(consumer);
    
    t1.join();
    t2.join();
    
    return 0;
}
```

**동작 방식:**

```
Acquire 의미:

  acquire 지점
       ↓
  ╔═══════╗
  ║ LOAD  ║ ← acquire load
  ╚═══╤═══╝
      │ 
      ↓ (이후의 모든 연산은 위로 올라갈 수 없음)
  ┌───────┐
  │ READ  │
  ├───────┤
  │ WRITE │
  └───────┘
```

### 4. memory_order_release

스토어 연산에 사용되며, 이 연산 이전의 모든 읽기/쓰기가 재배치되지 않도록 보장한다.

```cpp
#include <iostream>
#include <thread>
#include <atomic>

std::atomic<int> sync(0);
int data[5];

void writer() {
    data[0] = 1;
    data[1] = 2;
    data[2] = 3;
    data[3] = 4;
    data[4] = 5;
    
    sync.store(1, std::memory_order_release);  // 모든 쓰기가 완료됨을 알림
}

void reader() {
    while (sync.load(std::memory_order_acquire) == 0) {
        // 대기
    }
    
    // 모든 data 값을 안전하게 읽을 수 있음
    for (int i = 0; i < 5; ++i) {
        std::cout << data[i] << " ";
    }
    std::cout << std::endl;
}

int main() {
    std::thread t1(writer);
    std::thread t2(reader);
    
    t1.join();
    t2.join();
    
    return 0;
}
```

**동작 방식:**

```
Release 의미:

  ┌───────┐
  │ WRITE │
  ├───────┤
  │ READ  │
  └───┬───┘
      ↓ (이전의 모든 연산은 아래로 내려갈 수 없음)
  ╔═══╧═══╗
  ║ STORE ║ ← release store
  ╚═══════╝
      ↓
  release 지점
```

### 5. memory_order_acq_rel

읽기-수정-쓰기 연산에 사용되며, acquire와 release를 모두 적용한다.

```cpp
#include <iostream>
#include <thread>
#include <atomic>
#include <vector>

std::atomic<int> data(0);
std::atomic<int> flag(0);

void modify() {
    int expected = 0;
    int desired = 1;
    
    // compare_exchange는 읽기와 쓰기를 모두 수행
    if (data.compare_exchange_strong(expected, desired, 
                                     std::memory_order_acq_rel)) {
        // 성공: acquire 의미로 읽고, release 의미로 씀
        flag.store(1, std::memory_order_release);
    }
}

int main() {
    std::vector<std::thread> threads;
    
    for (int i = 0; i < 10; ++i) {
        threads.emplace_back(modify);
    }
    
    for (auto& t : threads) {
        t.join();
    }
    
    std::cout << "Data: " << data.load() << std::endl;
    std::cout << "Flag: " << flag.load() << std::endl;
    
    return 0;
}
```

**사용 케이스:**
- `fetch_add`, `fetch_sub`
- `exchange`
- `compare_exchange_strong/weak`

### 6. memory_order_seq_cst (기본값)

순차 일관성을 제공하는 가장 강력한 메모리 순서다.

```cpp
#include <iostream>
#include <thread>
#include <atomic>

std::atomic<bool> x(false);
std::atomic<bool> y(false);
std::atomic<int> z(0);

void write_x() {
    x.store(true, std::memory_order_seq_cst);
}

void write_y() {
    y.store(true, std::memory_order_seq_cst);
}

void read_x_then_y() {
    while (!x.load(std::memory_order_seq_cst)) {}
    
    if (y.load(std::memory_order_seq_cst)) {
        ++z;
    }
}

void read_y_then_x() {
    while (!y.load(std::memory_order_seq_cst)) {}
    
    if (x.load(std::memory_order_seq_cst)) {
        ++z;
    }
}

int main() {
    std::thread t1(write_x);
    std::thread t2(write_y);
    std::thread t3(read_x_then_y);
    std::thread t4(read_y_then_x);
    
    t1.join(); t2.join(); t3.join(); t4.join();
    
    std::cout << "z = " << z.load() << std::endl;
    // z는 항상 1 또는 2 (절대 0이 아님)
    
    return 0;
}
```

**특징:**
- 모든 seq_cst 연산이 전역적으로 일관된 순서를 가짐
- 가장 느림
- 가장 안전함
- 명시하지 않으면 기본값

**비교 예제:**

```cpp
#include <iostream>
#include <thread>
#include <atomic>

// Seq_cst vs Relaxed 비교
std::atomic<int> x(0), y(0);
int r1, r2;

void test_seq_cst() {
    // Thread 1
    auto t1 = std::thread([]() {
        x.store(1, std::memory_order_seq_cst);
        r1 = y.load(std::memory_order_seq_cst);
    });
    
    // Thread 2
    auto t2 = std::thread([]() {
        y.store(1, std::memory_order_seq_cst);
        r2 = x.load(std::memory_order_seq_cst);
    });
    
    t1.join();
    t2.join();
    
    // r1 == 0 && r2 == 0은 불가능!
}

void test_relaxed() {
    x.store(0); y.store(0);
    
    // Thread 1
    auto t1 = std::thread([]() {
        x.store(1, std::memory_order_relaxed);
        r1 = y.load(std::memory_order_relaxed);
    });
    
    // Thread 2
    auto t2 = std::thread([]() {
        y.store(1, std::memory_order_relaxed);
        r2 = x.load(std::memory_order_relaxed);
    });
    
    t1.join();
    t2.join();
    
    // r1 == 0 && r2 == 0도 가능!
}
```

### 메모리 순서 선택 가이드

```
사용 시나리오                     권장 메모리 순서
─────────────────────────────────────────────────
단순 카운터/통계                  memory_order_relaxed
플래그 기반 동기화                memory_order_acquire/release
Lock 구현                        memory_order_acquire/release
일반적인 원자 연산                memory_order_seq_cst (기본값)
복잡한 동기화 (확신 없을 때)      memory_order_seq_cst
```

**Visual Studio 2022에서 테스트:**

```cpp
// 프로젝트 속성 설정:
// C/C++ → 언어 → C++ 언어 표준: ISO C++23 표준(/std:c++23)
// C/C++ → 최적화 → 최적화: 최대 최적화(/O2)

#include <iostream>
#include <thread>
#include <atomic>
#include <vector>
#include <chrono>

void benchmark_memory_orders() {
    const int iterations = 10000000;
    
    // Relaxed
    {
        std::atomic<int> counter(0);
        auto start = std::chrono::high_resolution_clock::now();
        
        for (int i = 0; i < iterations; ++i) {
            counter.fetch_add(1, std::memory_order_relaxed);
        }
        
        auto end = std::chrono::high_resolution_clock::now();
        auto duration = std::chrono::duration_cast<std::chrono::milliseconds>(end - start);
        std::cout << "Relaxed: " << duration.count() << "ms\n";
    }
    
    // Seq_cst
    {
        std::atomic<int> counter(0);
        auto start = std::chrono::high_resolution_clock::now();
        
        for (int i = 0; i < iterations; ++i) {
            counter.fetch_add(1, std::memory_order_seq_cst);
        }
        
        auto end = std::chrono::high_resolution_clock::now();
        auto duration = std::chrono::duration_cast<std::chrono::milliseconds>(end - start);
        std::cout << "Seq_cst: " << duration.count() << "ms\n";
    }
}

int main() {
    benchmark_memory_orders();
    return 0;
}
```

이것으로 1부 기초 이론을 마친다. 다음 2부에서는 각 메모리 순서를 더 깊이 있게 다루고, 실전 예제를 통해 활용법을 배운다.
