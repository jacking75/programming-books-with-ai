# Chapter 01: Goroutine과 Channel
## — 경량 스레드의 기동, Channel에 의한 타입 안전한 통신, select문에 의한 멀티플렉싱

---

**들어가며:**

Go 언어가 현대 백엔드 시스템에서 선택받는 가장 결정적인 이유 중 하나는 바로 **병행 처리(concurrency)** 모델의 우아함입니다. 대부분의 언어에서 병행 처리를 구현하려면 OS 스레드를 직접 다루거나, 복잡한 스레드 풀을 설계하거나, 콜백 지옥에 빠지는 경우가 많습니다. 그러나 Go는 단 두 개의 키워드—`go`와 `chan`—로 수천 개의 작업을 동시에 실행하고 안전하게 통신하는 프로그램을 작성할 수 있습니다.

이 챕터에서는 Go 병행 처리의 핵심인 **goroutine**, **channel**, 그리고 **select문**을 깊이 있게 살펴봅니다. 단순히 사용법을 외우는 것을 넘어, Go 런타임이 내부적으로 어떻게 goroutine을 스케줄링하는지, channel이 왜 타입 안전한지, select가 어떻게 멀티플렉싱을 가능하게 하는지를 이해하는 것을 목표로 합니다.

**1.1 Goroutine — 경량 스레드의 탄생:**

**1.1.1 OS 스레드와 Goroutine의 차이**

Goroutine을 제대로 이해하려면 먼저 전통적인 OS 스레드(thread)와의 차이를 알아야 합니다. OS 스레드는 운영체제 커널이 직접 관리하는 실행 단위입니다. 각 스레드는 기본적으로 **1~8MB의 스택 메모리**를 고정적으로 할당받으며, 스레드 간의 컨텍스트 스위칭(context switching)은 커널 공간에서 일어나기 때문에 상당한 오버헤드가 발생합니다. 일반적인 서버 프로그램에서 수천 개의 OS 스레드를 동시에 운용하는 것은 메모리와 성능 측면에서 현실적으로 어렵습니다.

반면, Go의 goroutine은 **Go 런타임**이 관리하는 **사용자 공간(user-space)** 경량 스레드입니다. 초기 스택 크기가 단 **2KB**에 불과하며, 필요에 따라 동적으로 성장합니다. 컨텍스트 스위칭도 사용자 공간에서 이루어지므로 오버헤드가 극히 작습니다. 덕분에 Go 프로그램은 수십만, 심지어 **수백만 개의 goroutine을 동시에 실행**할 수 있습니다.

```
┌─────────────────────────────────────────────────────────────┐
│                    OS Thread vs Goroutine                   │
├──────────────────────────┬──────────────────────────────────┤
│      OS Thread           │         Goroutine                │
├──────────────────────────┼──────────────────────────────────┤
│  관리 주체: OS 커널       │  관리 주체: Go 런타임             │
│  초기 스택: ~1~8 MB      │  초기 스택: ~2 KB                 │
│  생성 비용: 매우 높음     │  생성 비용: 매우 낮음             │
│  컨텍스트 스위치: 커널    │  컨텍스트 스위치: 사용자 공간     │
│  동시 실행 수: ~수천      │  동시 실행 수: ~수백만            │
│  통신 방식: 공유 메모리   │  통신 방식: channel (권장)        │
└──────────────────────────┴──────────────────────────────────┘
```

**1.1.2 GMP 스케줄러 모델**

Go가 goroutine을 이렇게 효율적으로 운용할 수 있는 비결은 **GMP 스케줄러 모델** 덕분입니다. GMP는 세 가지 핵심 구성 요소의 약자입니다.

- **G (Goroutine):** 실행할 작업의 단위입니다. 스택, 프로그램 카운터, CPU 레지스터, 상태 메타데이터를 포함합니다.
- **M (Machine / OS Thread):** 실제로 Go 코드를 실행하는 OS 스레드입니다. Go 코드를 실행하려면 반드시 P를 하나 획득해야 합니다.
- **P (Processor / 논리 프로세서):** 논리적 실행 컨텍스트입니다. 자신만의 **로컬 런 큐(local run queue)** 를 가지고 있으며, 병렬 실행 수준을 결정합니다. `GOMAXPROCS` 환경변수로 P의 개수를 제어하며, 기본값은 논리 CPU 코어 수입니다.

```
┌───────────────────────────────────────────────────────────────────┐
│                      GMP 스케줄러 구조                              │
│                                                                   │
│  ┌─────────────────────────────────────────────────────────────┐  │
│  │              Global Run Queue (전역 런 큐)                   │  │
│  │        G  G  G  G  G  G  G  G  G  G  G  G                  │  │
│  └─────────────────────────────────────────────────────────────┘  │
│          ↑ (fair scheduling)         ↑ (work stealing)            │
│  ┌───────────────┐       ┌───────────────┐       ┌────────────┐   │
│  │      P0       │       │      P1       │       │     P2     │   │
│  │  Local Queue  │       │  Local Queue  │       │ Local Queue│   │
│  │  [G3][G4][G5] │       │  [G6][G7]    │       │  (empty)   │   │
│  └───────┬───────┘       └───────┬───────┘       └─────┬──────┘   │
│          │                       │                     │          │
│         M0                      M1               M2(steal G6)     │
│    (OS Thread)             (OS Thread)          (OS Thread)       │
│          │                       │                     │          │
│    ┌─────▼──────┐          ┌─────▼──────┐       ┌──────▼─────┐   │
│    │  실행 중 G2 │          │  실행 중 G6 │       │  실행 중 G6│   │
│    │ (Running)  │          │ (Running)  │       │ (Stolen!)  │   │
│    └────────────┘          └────────────┘       └────────────┘   │
└───────────────────────────────────────────────────────────────────┘
```

Go 스케줄러의 핵심 메커니즘 중 하나는 **Work Stealing**입니다. 어떤 P의 로컬 큐가 비어 있으면, 다른 P의 로컬 큐에서 goroutine의 절반을 가져와 실행합니다. 이를 통해 모든 CPU 코어를 최대한 활용할 수 있습니다. 또한, goroutine이 시스템 콜이나 I/O 대기로 **블로킹(blocking)** 상태가 되면, 해당 M은 P를 해제하고, 다른 M이 그 P를 획득하여 나머지 goroutine들이 계속 실행될 수 있도록 합니다.

**Goroutine의 생명주기는 다음과 같습니다:**

```
 생성(Created) ──→ 실행 대기(Runnable) ──→ 실행 중(Running)
                         ↑                       │
                         │           ┌───────────┴────────────┐
                         │           │                        │
                         └── 차단(Blocked)           종료(Terminated)
                             (channel, I/O, syscall)
```

**1.1.3 첫 번째 Goroutine 실행하기**

`go` 키워드 하나만으로 goroutine을 기동할 수 있습니다. 아래 예제를 통해 goroutine의 기본 동작을 확인해 봅시다.

```go
package main

import (
	"fmt"
	"time"
)

func sayHello(name string) {
	fmt.Printf("안녕하세요, %s!\n", name)
}

func main() {
	// go 키워드로 goroutine 기동
	go sayHello("고루틴 1")
	go sayHello("고루틴 2")
	go sayHello("고루틴 3")

	// main이 종료되면 모든 goroutine도 강제 종료됨
	// goroutine들이 실행될 시간을 주기 위해 잠시 대기
	time.Sleep(100 * time.Millisecond)

	fmt.Println("main 함수 종료")
}
```

위 예제에는 중요한 주의점이 있습니다. `time.Sleep`으로 대기하는 방식은 실제 코드에서 절대 사용해서는 안 됩니다. goroutine이 얼마나 걸릴지 알 수 없고, 환경에 따라 실행 결과가 달라질 수 있기 때문입니다. 실제 코드에서는 `sync.WaitGroup`이나 channel을 사용하여 동기화합니다(Chapter 02에서 자세히 다룹니다).

**1.1.4 Goroutine 누수(Goroutine Leak) 주의**

Goroutine이 경량이라고 해서 무한정 만들어도 되는 것은 아닙니다. **goroutine 누수**는 Go 프로그램에서 가장 흔한 메모리 문제 중 하나입니다. 아래는 누수가 발생하는 전형적인 패턴입니다.

```go
// ❌ 잘못된 예: goroutine 누수
func leakyFunc() {
	ch := make(chan int) // 버퍼 없는 channel

	go func() {
		// 이 goroutine은 영원히 차단됨!
		// ch에서 받을 사람이 없기 때문
		val := <-ch
		fmt.Println(val)
	}()

	// ch에 아무것도 보내지 않고 함수가 반환됨
	// goroutine은 메모리에 남아 계속 대기함
}

// ✅ 올바른 예: done 채널로 goroutine 종료 신호 전달
func nonLeakyFunc() {
	ch := make(chan int, 1) // 버퍼 채널 사용
	done := make(chan struct{})

	go func() {
		defer close(done) // goroutine 종료 시 신호 전달
		select {
		case val := <-ch:
			fmt.Println(val)
		case <-time.After(1 * time.Second): // 타임아웃으로 안전하게 종료
			fmt.Println("타임아웃: goroutine 종료")
		}
	}()

	ch <- 42
	<-done // goroutine이 완료될 때까지 대기
}
```

**1.2 Channel — 타입 안전한 통신의 파이프:**

Go의 설계 철학 중 하나는 **"메모리를 공유해서 통신하지 말고, 통신함으로써 메모리를 공유하라(Do not communicate by sharing memory; instead, share memory by communicating)"** 입니다. Channel은 이 철학을 구현하는 핵심 도구입니다.

Channel은 goroutine 사이에서 데이터를 안전하게 주고받는 **타입이 지정된 파이프(typed pipe)** 입니다. 컴파일 시점에 타입이 검사되므로, 잘못된 타입의 데이터를 보내려고 하면 컴파일 오류가 발생합니다.

**1.2.1 Channel의 종류**

Channel에는 크게 두 가지 종류가 있습니다.

```
  언버퍼드 채널 (Unbuffered Channel)
  make(chan T)

  Sender ──→ [  ] ──→ Receiver
             (용량 0)
  • 송신자와 수신자가 반드시 동시에 준비되어야 함
  • 핸드쉐이크(handshake) 방식
  • 동기적(synchronous) 통신

  버퍼드 채널 (Buffered Channel)
  make(chan T, N)

  Sender ──→ [G1][G2][G3] ──→ Receiver
             (용량 N=3)
  • 버퍼가 가득 차지 않으면 송신자는 즉시 반환
  • 버퍼가 비어 있지 않으면 수신자는 즉시 반환
  • 비동기적(asynchronous) 통신
```

```go
package main

import "fmt"

func main() {
	// === 언버퍼드 채널 ===
	unbuffered := make(chan string)

	go func() {
		// 수신자가 준비될 때까지 블로킹
		unbuffered <- "안녕하세요!"
	}()
	msg := <-unbuffered // 송신자가 준비될 때까지 블로킹
	fmt.Println("언버퍼드 수신:", msg)

	// === 버퍼드 채널 ===
	buffered := make(chan int, 3) // 용량 3

	// 버퍼가 가득 차지 않으면 블로킹 없이 전송
	buffered <- 1
	buffered <- 2
	buffered <- 3
	// buffered <- 4  // ❌ 버퍼가 가득 찼으므로 여기서 블로킹 (deadlock 위험!)

	fmt.Println("버퍼드 수신:", <-buffered) // 1
	fmt.Println("버퍼드 수신:", <-buffered) // 2
	fmt.Println("버퍼드 수신:", <-buffered) // 3
}
```

**1.2.2 Channel 방향 지정 (Directional Channels)**

Channel을 함수 파라미터로 넘길 때 **방향을 지정**할 수 있습니다. 이는 코드의 의도를 명확히 하고, 잘못된 사용을 컴파일 타임에 방지합니다.

```go
package main

import "fmt"

// 송신 전용 채널: chan<- T
// 이 함수 안에서는 채널에 값을 보낼 수만 있음
func producer(ch chan<- int, n int) {
	for i := 0; i < n; i++ {
		ch <- i
		fmt.Printf("  [producer] %d 전송\n", i)
	}
	close(ch) // 더 이상 보낼 값이 없음을 알림
}

// 수신 전용 채널: <-chan T
// 이 함수 안에서는 채널에서 값을 받을 수만 있음
func consumer(ch <-chan int) {
	for val := range ch { // close()가 호출될 때까지 반복
		fmt.Printf("  [consumer] %d 수신\n", val)
	}
	fmt.Println("  [consumer] 채널 닫힘, 종료")
}

func main() {
	ch := make(chan int, 5)

	go producer(ch, 5)
	consumer(ch)
}
```

**1.2.3 Channel 닫기와 range를 이용한 수신**

`close(ch)`를 호출하면 채널이 닫힙니다. 닫힌 채널에서 남은 값을 모두 수신한 후, 추가 수신 시 해당 타입의 **제로값(zero value)** 이 반환됩니다. 채널이 닫혔는지 확인하려면 두 번째 반환값을 활용합니다.

```go
package main

import "fmt"

func main() {
	ch := make(chan int, 3)
	ch <- 10
	ch <- 20
	ch <- 30
	close(ch)

	// 방법 1: ok 값으로 닫힘 확인
	for {
		val, ok := <-ch
		if !ok {
			fmt.Println("채널이 닫혔습니다.")
			break
		}
		fmt.Println("수신:", val)
	}

	// 방법 2: range 사용 (닫힌 채널은 자동으로 loop 종료)
	ch2 := make(chan string, 2)
	ch2 <- "Go"
	ch2 <- "Channel"
	close(ch2)

	for msg := range ch2 {
		fmt.Println("range 수신:", msg)
	}
}
```

> **⚠️ 주의:** 이미 닫힌 채널에 값을 보내면 **panic**이 발생합니다. 또한, `nil` 채널에 송수신을 시도하면 영원히 블로킹됩니다. Channel은 항상 `make`로 초기화하고, 닫는 책임은 **송신자** 쪽에 두는 것이 일반적인 관례입니다.

**1.2.4 Channel 내부 동작 원리**

Channel의 내부 구조를 이해하면 올바른 사용 패턴이 자연스럽게 떠오릅니다.

```
Channel 내부 구조 (hchan 구조체 개념도)

┌─────────────────────────────────────────────────────┐
│                    hchan                            │
│                                                     │
│  buf: [slot0][slot1][slot2]...[slotN-1]  ← 링 버퍼  │
│  sendx: 다음 송신 인덱스                              │
│  recvx: 다음 수신 인덱스                              │
│  qcount: 현재 버퍼에 있는 요소 수                     │
│  dataqsiz: 버퍼 용량                                 │
│                                                     │
│  sendq: [G_wait1] → [G_wait2] → ...   ← 송신 대기 큐 │
│  recvq: [G_wait3] → [G_wait4] → ...   ← 수신 대기 큐 │
│                                                     │
│  mutex: 내부 뮤텍스 (스레드 안전)                     │
│  closed: 닫힘 여부                                   │
└─────────────────────────────────────────────────────┘

송신 시나리오:
  1. recvq에 대기 중인 수신자가 있다면 → 직접 전달 (zero-copy)
  2. 버퍼에 공간이 있다면 → 버퍼에 저장
  3. 버퍼가 가득 찼다면 → sendq에 추가하고 goroutine 블로킹

수신 시나리오:
  1. sendq에 대기 중인 송신자가 있다면 → 직접 수신
  2. 버퍼에 데이터가 있다면 → 버퍼에서 읽기
  3. 버퍼가 비어 있다면 → recvq에 추가하고 goroutine 블로킹
```

**1.3 Select문 — 멀티플렉싱의 핵심:**

`select`문은 여러 channel 연산 중 준비된 것을 선택하여 실행하는 Go의 독특한 제어 구조입니다. 마치 네트워크 프로그래밍에서의 `select(2)` 시스템 콜처럼, 여러 channel을 동시에 감시하다가 어느 하나가 준비되면 해당 케이스를 실행합니다.

**1.3.1 select의 기본 문법**

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)

	go func() {
		time.Sleep(1 * time.Second)
		ch1 <- "하나"
	}()

	go func() {
		time.Sleep(2 * time.Second)
		ch2 <- "둘"
	}()

	// 두 채널 중 먼저 준비된 것을 처리
	for i := 0; i < 2; i++ {
		select {
		case msg1 := <-ch1:
			fmt.Println("ch1에서 수신:", msg1)
		case msg2 := <-ch2:
			fmt.Println("ch2에서 수신:", msg2)
		}
	}
}
```

**여러 케이스가 동시에 준비된 경우, Go 런타임은 무작위로 하나를 선택합니다.** 이는 채널 간의 공정성(fairness)을 보장하기 위한 설계입니다.

**1.3.2 default 케이스 — Non-Blocking 채널 연산**

`select`에 `default` 케이스를 추가하면, 준비된 채널이 없을 때 즉시 `default`를 실행합니다. 이를 통해 **Non-Blocking** 방식의 채널 연산이 가능합니다.

```go
package main

import "fmt"

func main() {
	ch := make(chan int, 1)

	// Non-Blocking 송신
	select {
	case ch <- 42:
		fmt.Println("값 전송 성공")
	default:
		fmt.Println("채널이 가득 참, 전송 건너뜀")
	}

	// Non-Blocking 수신
	select {
	case val := <-ch:
		fmt.Println("값 수신:", val)
	default:
		fmt.Println("채널이 비어 있음, 수신 건너뜀")
	}
}
```

**1.3.3 타임아웃 패턴**

실무에서 `select`가 가장 많이 활용되는 패턴 중 하나는 **타임아웃**입니다. `time.After()`는 지정한 시간이 지난 후 값을 보내는 채널을 반환합니다.

```go
package main

import (
	"fmt"
	"time"
)

func fetchData(timeout time.Duration) (string, error) {
	resultCh := make(chan string, 1)

	go func() {
		// 느린 작업 시뮬레이션 (예: 외부 API 호출)
		time.Sleep(2 * time.Second)
		resultCh <- "데이터 조회 완료!"
	}()

	select {
	case result := <-resultCh:
		return result, nil
	case <-time.After(timeout):
		return "", fmt.Errorf("요청 타임아웃: %v 초과", timeout)
	}
}

func main() {
	// 1초 타임아웃 (작업이 2초 걸리므로 타임아웃 발생)
	result, err := fetchData(1 * time.Second)
	if err != nil {
		fmt.Println("오류:", err)
	} else {
		fmt.Println("결과:", result)
	}

	// 3초 타임아웃 (작업이 2초 걸리므로 성공)
	result, err = fetchData(3 * time.Second)
	if err != nil {
		fmt.Println("오류:", err)
	} else {
		fmt.Println("결과:", result)
	}
}
```

**1.3.4 Done 채널 패턴 — Goroutine 종료 신호**

`select`와 `done` 채널을 조합하면, goroutine에게 종료 신호를 보내는 우아한 패턴을 구현할 수 있습니다.

```go
package main

import (
	"fmt"
	"time"
)

func worker(id int, jobs <-chan int, done <-chan struct{}) {
	for {
		select {
		case job, ok := <-jobs:
			if !ok {
				fmt.Printf("[Worker %d] 작업 채널 닫힘, 종료\n", id)
				return
			}
			fmt.Printf("[Worker %d] 작업 %d 처리 중...\n", id, job)
			time.Sleep(500 * time.Millisecond)
		case <-done:
			// done 채널에서 신호 수신 시 즉시 종료
			fmt.Printf("[Worker %d] 종료 신호 수신, 중단\n", id)
			return
		}
	}
}

func main() {
	jobs := make(chan int, 10)
	done := make(chan struct{})

	// 2개의 worker goroutine 기동
	for i := 1; i <= 2; i++ {
		go worker(i, jobs, done)
	}

	// 작업 전송
	for j := 1; j <= 5; j++ {
		jobs <- j
	}

	// 1.2초 후 종료 신호 전달
	time.Sleep(1200 * time.Millisecond)
	close(done) // 모든 worker에게 동시에 종료 신호 전달

	time.Sleep(100 * time.Millisecond) // 정리 시간
	fmt.Println("메인 종료")
}
```

> `close(done)`은 해당 채널을 구독하는 **모든 goroutine**에게 동시에 신호를 보내는 broadcast 효과가 있습니다. 이는 Go에서 goroutine 그룹을 종료시키는 관용적인 패턴입니다. (더 발전된 형태인 `context.Context`는 Chapter 04에서 다룹니다.)

**1.3.5 for-select 루프 패턴**

실제 서버 코드에서 가장 자주 볼 수 있는 패턴은 `for`와 `select`를 결합한 형태입니다. 이벤트 루프(event loop)를 구현할 때 핵심적으로 사용됩니다.

```go
package main

import (
	"fmt"
	"time"
)

func eventLoop(events <-chan string, quit <-chan struct{}) {
	ticker := time.NewTicker(500 * time.Millisecond)
	defer ticker.Stop()

	for {
		select {
		case event, ok := <-events:
			if !ok {
				fmt.Println("[이벤트 루프] events 채널 닫힘")
				return
			}
			fmt.Printf("[이벤트 루프] 이벤트 처리: %s\n", event)

		case t := <-ticker.C:
			// 주기적인 작업 (예: 헬스체크, 통계 수집)
			fmt.Printf("[이벤트 루프] 주기 작업 실행 @ %s\n",
				t.Format("15:04:05"))

		case <-quit:
			fmt.Println("[이벤트 루프] 종료 신호 수신")
			return
		}
	}
}

func main() {
	events := make(chan string, 5)
	quit := make(chan struct{})

	go eventLoop(events, quit)

	events <- "사용자 로그인"
	time.Sleep(600 * time.Millisecond)
	events <- "데이터 조회"
	time.Sleep(600 * time.Millisecond)
	events <- "로그아웃"

	time.Sleep(200 * time.Millisecond)
	close(quit)
	time.Sleep(100 * time.Millisecond)
}
```

**1.4 심화: 채널 패턴 다이어그램:**

지금까지 배운 개념들의 관계를 시각적으로 정리해 봅니다.

```
┌───────────────────────────────────────────────────────────────┐
│              채널 통신 패턴 전체 지도                           │
│                                                               │
│  ① 단방향 파이프 (Unidirectional Pipe)                         │
│     Producer ──[chan]──→ Consumer                             │
│                                                               │
│  ② 결과 수집 (Fan-in)                                          │
│     Worker1 ──┐                                               │
│     Worker2 ──┼──[chan]──→ Aggregator                         │
│     Worker3 ──┘                                               │
│                                                               │
│  ③ 작업 분배 (Fan-out)                                         │
│               ┌──→ Worker1                                    │

│               └──→ Worker3                                    │
│                                                               │
│  ④ 타임아웃 (Timeout)                                          │
│     Worker ──[result chan]──┐                                  │

│                                                               │
│  ⑤ 취소 신호 (Done/Quit)                                       │

│                      └──→ Worker3                             │
└───────────────────────────────────────────────────────────────┘
```

**1.5 응용 프로그램 — 실시간 주식 가격 모니터링 시스템:**

이 챕터에서 배운 goroutine, channel, select문을 모두 활용하여 **실시간 주식 가격 모니터링 시스템**을 구현합니다. 이 시스템은 여러 주식 종목의 가격을 병행하여 시뮬레이션하고, 가격 변동을 실시간으로 감지하여 알림을 보내며, 일정 조건을 만족하면 프로그램을 종료합니다.

```
시스템 구조도

┌───────────────────────────────────────────────────────────────────┐
│                  주식 가격 모니터링 시스템                          │
│                                                                   │
│  ┌──────────────┐   priceCh    ┌────────────────────────────────┐ │
│  │ PriceFeeder  │─────────────→│                                │ │
│  │  (AAPL)      │              │                                │ │
│  └──────────────┘              │    Aggregator (선택자)          │ │
│  ┌──────────────┐   priceCh    │   - 여러 종목 가격 수집         │ │
│  │ PriceFeeder  │─────────────→│   - 가격 변동 계산             │ │
│  │  (GOOG)      │              │   - 알림 조건 평가             │ │
│  └──────────────┘              │                                │ │
│  ┌──────────────┐   priceCh    │                                │ │
│  │ PriceFeeder  │─────────────→│                                │ │
│  │  (TSLA)      │              └──────────────┬─────────────────┘ │
│  └──────────────┘                             │ alertCh           │
│                                               ↓                  │
│                                    ┌──────────────────┐          │
│                                    │  AlertPrinter    │          │
│                                    │  (알림 출력)      │          │
│                                    └──────────────────┘          │
│                                                                   │
│  done 채널: 모든 goroutine의 종료를 조율                           │
└───────────────────────────────────────────────────────────────────┘
```

```go
package main

import (
	"fmt"
	"math/rand"
	"sync"
	"time"
)

// ─── 도메인 타입 정의 ───────────────────────────────────────────────

// PriceUpdate는 주식 가격 업데이트 이벤트를 나타냅니다.
type PriceUpdate struct {
	Symbol    string    // 종목 코드 (예: "AAPL")
	Price     float64   // 현재 가격
	Change    float64   // 이전 가격 대비 변동 (%)
	Timestamp time.Time // 업데이트 시각
}

// Alert는 가격 알림 이벤트를 나타냅니다.
type Alert struct {
	Symbol  string
	Message string
	Level   string // "INFO", "WARN", "ALERT"
}

// ─── 가격 피더 (Producer) ────────────────────────────────────────────

// priceFeeder는 특정 종목의 가격 변화를 시뮬레이션하여 채널로 전송합니다.
// done 채널에서 신호를 받으면 goroutine을 종료합니다.
func priceFeeder(
	symbol string,
	initialPrice float64,
	interval time.Duration,
	priceCh chan<- PriceUpdate,
	done <-chan struct{},
	wg *sync.WaitGroup,
) {
	defer wg.Done()

	currentPrice := initialPrice
	ticker := time.NewTicker(interval)
	defer ticker.Stop()

	fmt.Printf("[피더] %s 가격 피더 시작 (초기가: $%.2f)\n", symbol, initialPrice)

	for {
		select {
		case <-done:
			fmt.Printf("[피더] %s 종료\n", symbol)
			return

		case <-ticker.C:
			// 가격 변동 시뮬레이션: -3% ~ +3% 범위의 랜덤 변동
			changePercent := (rand.Float64()*6 - 3)
			previousPrice := currentPrice
			currentPrice = previousPrice * (1 + changePercent/100)

			update := PriceUpdate{
				Symbol:    symbol,
				Price:     currentPrice,
				Change:    changePercent,
				Timestamp: time.Now(),
			}

			// select로 done 채널도 함께 감시 (채널이 가득 찬 경우 차단 방지)
			select {
			case priceCh <- update:
			case <-done:
				fmt.Printf("[피더] %s 전송 중 종료 신호 수신\n", symbol)
				return
			}
		}
	}
}

// ─── 집계기 (Aggregator) ─────────────────────────────────────────────

// aggregator는 여러 종목의 가격 업데이트를 수신하고,
// 조건에 따라 알림을 생성합니다.
func aggregator(
	priceCh <-chan PriceUpdate,
	alertCh chan<- Alert,
	statsCh chan<- map[string]float64,
	done <-chan struct{},
	wg *sync.WaitGroup,
) {
	defer wg.Done()

	// 종목별 최신 가격 기록
	priceMap := make(map[string]float64)
	updateCount := 0
	statsTimer := time.NewTicker(2 * time.Second)
	defer statsTimer.Stop()

	fmt.Println("[집계기] 가격 집계 시작")

	for {
		select {
		case <-done:
			fmt.Println("[집계기] 종료")
			return

		case update := <-priceCh:
			updateCount++
			priceMap[update.Symbol] = update.Price

			// 가격 변동에 따라 알림 레벨 결정
			var alert Alert
			alert.Symbol = update.Symbol

			absChange := update.Change
			if absChange < 0 {
				absChange = -absChange
			}

			switch {
			case absChange >= 2.5:
				alert.Level = "🚨 ALERT"
				alert.Message = fmt.Sprintf(
					"%s 급격한 가격 변동! $%.2f (%.2f%%)",
					update.Symbol, update.Price, update.Change)
			case absChange >= 1.5:
				alert.Level = "⚠️  WARN"
				alert.Message = fmt.Sprintf(
					"%s 가격 변동 경보: $%.2f (%.2f%%)",
					update.Symbol, update.Price, update.Change)
			default:
				alert.Level = "ℹ️  INFO"
				alert.Message = fmt.Sprintf(
					"%s: $%.2f (%.2f%%)",
					update.Symbol, update.Price, update.Change)
			}

			// 알림 전송 (논블로킹: 알림 채널이 가득 차도 건너뜀)
			select {
			case alertCh <- alert:
			default:
				// 알림 채널이 가득 찬 경우 드롭 (실무에서는 로그 기록 권장)
			}

		case <-statsTimer.C:
			// 현재 가격 스냅샷 전송
			snapshot := make(map[string]float64)
			for k, v := range priceMap {
				snapshot[k] = v
			}
			select {
			case statsCh <- snapshot:
			default:
			}
		}
	}
}

// ─── 알림 출력기 (Alert Printer) ─────────────────────────────────────

// alertPrinter는 알림 채널에서 메시지를 수신하여 출력합니다.
func alertPrinter(
	alertCh <-chan Alert,
	done <-chan struct{},
	wg *sync.WaitGroup,
) {
	defer wg.Done()
	fmt.Println("[알림기] 알림 출력 시작")

	for {
		select {
		case <-done:
			// done 수신 후 남은 알림 모두 처리
			fmt.Println("[알림기] 종료 중, 잔여 알림 처리...")
			for {
				select {
				case alert := <-alertCh:
					fmt.Printf("  %s | %s\n", alert.Level, alert.Message)
				default:
					fmt.Println("[알림기] 완전 종료")
					return
				}
			}

		case alert := <-alertCh:
			fmt.Printf("  %s | %s\n", alert.Level, alert.Message)
		}
	}
}

// ─── 통계 출력기 (Stats Printer) ─────────────────────────────────────

// statsPrinter는 주기적으로 전체 종목 현황을 출력합니다.
func statsPrinter(
	statsCh <-chan map[string]float64,
	done <-chan struct{},
	wg *sync.WaitGroup,
) {
	defer wg.Done()

	for {
		select {
		case <-done:
			fmt.Println("[통계기] 종료")
			return

		case snapshot := <-statsCh:
			fmt.Println("\n  ┌─────────────────────────────┐")
			fmt.Println("  │     📊 현재 주가 현황         │")
			fmt.Println("  ├──────────┬──────────────────┤")
			for symbol, price := range snapshot {
				fmt.Printf("  │ %-8s │  $%12.2f    │\n", symbol, price)
			}
			fmt.Println("  └──────────┴──────────────────┘")
		}
	}
}

// ─── 메인 함수 ────────────────────────────────────────────────────────

func main() {
	fmt.Println("==============================================")
	fmt.Println("   📈 실시간 주식 가격 모니터링 시스템 시작   ")
	fmt.Println("==============================================")

	// 채널 초기화
	priceCh := make(chan PriceUpdate, 50)  // 버퍼드: 순간적 급증 대비
	alertCh := make(chan Alert, 100)       // 버퍼드: 알림 유실 방지
	statsCh := make(chan map[string]float64, 5)
	done := make(chan struct{})            // 종료 신호용 (언버퍼드)

	var wg sync.WaitGroup

	// ── 주식 종목 및 초기 가격 설정 ──
	stocks := []struct {
		symbol       string
		initialPrice float64
		interval     time.Duration
	}{
		{"AAPL", 195.50, 300 * time.Millisecond},
		{"GOOG", 175.20, 400 * time.Millisecond},
		{"TSLA", 250.80, 250 * time.Millisecond},
		{"MSFT", 420.30, 350 * time.Millisecond},
	}

	// ── 가격 피더 goroutine 기동 ──
	for _, stock := range stocks {
		wg.Add(1)
		go priceFeeder(
			stock.symbol,
			stock.initialPrice,
			stock.interval,
			priceCh,
			done,
			&wg,
		)
	}

	// ── 집계기 goroutine 기동 ──
	wg.Add(1)
	go aggregator(priceCh, alertCh, statsCh, done, &wg)

	// ── 알림 출력기 goroutine 기동 ──
	wg.Add(1)
	go alertPrinter(alertCh, done, &wg)

	// ── 통계 출력기 goroutine 기동 ──
	wg.Add(1)
	go statsPrinter(statsCh, done, &wg)

	// ── 5초 동안 모니터링 후 종료 ──
	monitorDuration := 5 * time.Second
	fmt.Printf("\n[메인] %v 동안 모니터링 후 자동 종료\n\n", monitorDuration)

	select {
	case <-time.After(monitorDuration):
		fmt.Println("\n[메인] 모니터링 시간 종료, 시스템 종료 시작")
	}

	// done 채널을 닫아 모든 goroutine에 종료 신호 broadcast
	close(done)

	// 모든 goroutine이 완전히 종료될 때까지 대기
	wg.Wait()

	fmt.Println("\n==============================================")
	fmt.Println("   ✅ 시스템 정상 종료 완료                  ")
	fmt.Println("==============================================")
}
```
