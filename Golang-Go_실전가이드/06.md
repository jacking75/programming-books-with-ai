## **이 챕터에서 배우는 것:**

## **6.1 왜 프레임워크인가? — net/http의 한계와 프레임워크의 역할**

Chapter 05에서 우리는 `net/http` 표준 라이브러리만으로 웹 서버를 구축하는 방법을 배웠습니다. Go의 표준 라이브러리는 놀라울 만큼 강력하여, 많은 프로덕션 서비스가 실제로 `net/http`만으로 운영됩니다. 그러나 API 서버의 규모가 커지고, 팀이 성장하면서 다음과 같은 공통적인 고통이 생깁니다.

표준 라이브러리를 사용할 때는 경로 파라미터 추출 (`/users/:id`), JSON 바인딩 및 유효성 검사, 미들웨어 체이닝, 에러 처리의 일관성 등을 모두 직접 구현해야 합니다. 이는 프로젝트마다 "또 같은 보일러플레이트를 쓰는" 상황을 반복시킵니다. 프레임워크는 이런 반복적인 작업을 추상화하여 개발자가 비즈니스 로직에 집중할 수 있도록 돕습니다.


## **6.2 Gin 프레임워크 — "빠르고, 간단하고, 잘 작동한다"**

### **6.2.1 Gin의 설계 철학과 특징**

Gin은 **Martini** 프레임워크에서 영감을 받았지만, 성능을 극적으로 개선하기 위해 처음부터 재설계되었습니다. Gin의 핵심은 `httprouter`를 기반으로 한 고성능 **Radix Tree** 라우터입니다. 일반적인 HashMap 방식과 달리 Radix Tree는 경로의 공통 접두사를 공유하여 메모리와 속도 모두에서 우수한 성능을 발휘합니다.

Gin의 가장 큰 특징은 **`gin.Context`** 입니다. 이 구조체 하나에 요청 파싱, 응답 렌더링, 미들웨어 흐름 제어가 모두 녹아 있습니다. 단, 표준 `context.Context`를 직접 구현한 것은 아니며, `c.Request.Context()`를 통해 표준 컨텍스트에 접근할 수 있습니다.

```
┌─────────────────────── gin.Context ──────────────────────┐
│                                                          │
│  Request Handling     Response Handling    Flow Control  │
│  ───────────────      ────────────────     ────────────  │
│  c.Param("id")        c.JSON(200, data)   c.Next()      │
│  c.Query("q")         c.String(200, "ok") c.Abort()     │
│  c.PostForm("name")   c.XML(200, data)    c.AbortWith.. │
│  c.Bind(&struct)      c.File("path")                    │
│  c.ShouldBind(&s)     c.Redirect(301, u)                │
│  c.BindJSON(&s)       c.HTML(200, tmpl)                 │
│                                                          │
│  Metadata             Values                             │
│  ────────             ──────                             │
│  c.FullPath()         c.Set("key", val)                 │
│  c.ClientIP()         c.Get("key")                      │
│  c.ContentType()      c.MustGet("key")                  │
└──────────────────────────────────────────────────────────┘
```

### **6.2.2 Gin 설치 및 첫 번째 서버**

```go
// go.mod 초기화 후 설치
// go get github.com/gin-gonic/gin

package main

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

func main() {
    // gin.Default() = Logger + Recovery 미들웨어 포함
    r := gin.Default()

    // 가장 기본적인 GET 핸들러
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{
            "message": "pong",
            "status":  "ok",
        })
    })

    // 서버 시작 (기본 포트 8080)
    r.Run(":8080")
}
```

`gin.Default()`는 `Logger`와 `Recovery` 미들웨어가 이미 등록된 엔진을 반환합니다. `Recovery`는 핸들러에서 `panic`이 발생했을 때 500 에러로 복구하는 역할을 합니다. 반면 `gin.New()`는 아무 미들웨어도 없는 순수한 엔진을 반환하므로, 프로덕션에서는 미들웨어를 세밀하게 제어하고 싶을 때 `gin.New()`를 선호하기도 합니다.

### **6.2.3 라우팅 심화 — 경로 파라미터, 쿼리, 그룹**

Gin의 라우팅은 직관적입니다. 경로 파라미터는 `:param` 형태로 선언하고, 와일드카드는 `*param` 형태를 사용합니다. 관련된 라우트는 **Group**으로 묶어 공통 경로 접두사와 미들웨어를 적용할 수 있습니다.

```go
package main

import (
    "net/http"
    "strconv"

    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    // ─── 경로 파라미터 ───────────────────────────────────
    // :id  → 필수 파라미터, /users/42
    // *action → 와일드카드, /files/img/logo.png
    r.GET("/users/:id", func(c *gin.Context) {
        id := c.Param("id") // "42"
        c.JSON(http.StatusOK, gin.H{"id": id})
    })

    r.GET("/files/*filepath", func(c *gin.Context) {
        path := c.Param("filepath") // "/img/logo.png"
        c.String(http.StatusOK, "파일 경로: %s", path)
    })

    // ─── 쿼리 파라미터 ──────────────────────────────────
    // GET /search?q=golang&page=2
    r.GET("/search", func(c *gin.Context) {
        query := c.Query("q")                    // "golang"
        page, _ := strconv.Atoi(c.DefaultQuery("page", "1")) // 기본값: "1"
        c.JSON(http.StatusOK, gin.H{
            "query": query,
            "page":  page,
        })
    })

    // ─── 라우트 그룹 ────────────────────────────────────
    // /api/v1 접두사를 가지는 그룹
    v1 := r.Group("/api/v1")
    {
        users := v1.Group("/users")
        {
            users.GET("", listUsers)       // GET  /api/v1/users
            users.POST("", createUser)     // POST /api/v1/users
            users.GET("/:id", getUser)     // GET  /api/v1/users/:id
            users.PUT("/:id", updateUser)  // PUT  /api/v1/users/:id
            users.DELETE("/:id", deleteUser) // DELETE /api/v1/users/:id
        }
    }

    r.Run(":8080")
}

// 각 핸들러는 별도 파일에서 정의
func listUsers(c *gin.Context)   { c.JSON(200, gin.H{"users": []string{}}) }
func createUser(c *gin.Context)  { c.JSON(201, gin.H{"created": true}) }
func getUser(c *gin.Context)     { c.JSON(200, gin.H{"id": c.Param("id")}) }
func updateUser(c *gin.Context)  { c.JSON(200, gin.H{"updated": true}) }
func deleteUser(c *gin.Context)  { c.JSON(204, nil) }
```

### **6.2.4 요청 바인딩과 유효성 검사**

Gin의 바인딩 시스템은 매우 강력합니다. 구조체 태그 하나로 JSON, Form, URI, Header 등 다양한 소스에서 데이터를 바인딩하고, `validator` 라이브러리를 통해 유효성 검사까지 한 번에 처리합니다.

`ShouldBind`와 `Bind`의 차이를 이해하는 것이 중요합니다. `Bind`는 유효성 검사 실패 시 자동으로 400 응답을 쓰고 `c.Abort()`를 호출합니다. 반면 `ShouldBind`는 에러만 반환하고, 응답 처리는 핸들러에게 맡깁니다. 프로덕션에서는 에러 처리 흐름을 직접 제어할 수 있는 **`ShouldBind`** 계열 함수 사용을 권장합니다.

```go
package main

import (
    "net/http"
    "time"

    "github.com/gin-gonic/gin"
)

// CreateUserRequest: 사용자 생성 요청 구조체
// binding 태그: 유효성 검사 규칙 (validator 라이브러리)
type CreateUserRequest struct {
    Name     string `json:"name"     binding:"required,min=2,max=50"`
    Email    string `json:"email"    binding:"required,email"`
    Age      int    `json:"age"      binding:"required,min=1,max=150"`
    Role     string `json:"role"     binding:"oneof=admin user guest"`
    Password string `json:"password" binding:"required,min=8"`
}

// UserResponse: 응답 구조체 (password 제외)
type UserResponse struct {
    ID        uint      `json:"id"`
    Name      string    `json:"name"`
    Email     string    `json:"email"`
    Age       int       `json:"age"`
    Role      string    `json:"role"`
    CreatedAt time.Time `json:"created_at"`
}

// ErrorResponse: 에러 응답 공통 구조체
type ErrorResponse struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
}

func createUserHandler(c *gin.Context) {
    var req CreateUserRequest

    // ShouldBindJSON: JSON 파싱 + 유효성 검사
    // 실패 시 에러 반환, 200 이외의 응답은 핸들러가 직접 처리
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(http.StatusBadRequest, ErrorResponse{
            Code:    400,
            Message: err.Error(), // 구체적인 유효성 검사 실패 메시지
        })
        return
    }

    // 비즈니스 로직 (실제로는 서비스 레이어 호출)
    resp := UserResponse{
        ID:        1,
        Name:      req.Name,
        Email:     req.Email,
        Age:       req.Age,
        Role:      req.Role,
        CreatedAt: time.Now(),
    }

    c.JSON(http.StatusCreated, resp)
}

// URI 파라미터 바인딩
type UserURIParam struct {
    ID uint `uri:"id" binding:"required,min=1"`
}

func getUserHandler(c *gin.Context) {
    var param UserURIParam

    // ShouldBindUri: URL 경로 파라미터 바인딩
    if err := c.ShouldBindUri(&param); err != nil {
        c.JSON(http.StatusBadRequest, ErrorResponse{
            Code: 400, Message: "유효하지 않은 ID",
        })
        return
    }

    c.JSON(http.StatusOK, UserResponse{ID: param.ID, Name: "홍길동"})
}

func main() {
    r := gin.Default()
    r.POST("/users", createUserHandler)
    r.GET("/users/:id", getUserHandler)
    r.Run(":8080")
}
```

```
│       │                                                  │

│  ┌────────────────────────────────┐                      │
```

### **6.2.5 Gin 미들웨어 — 체이닝의 기술**

Gin의 미들웨어는 `gin.HandlerFunc` 타입으로, 일반 핸들러와 동일한 시그니처를 가집니다. `c.Next()`를 호출하면 체인의 다음 핸들러로 실행이 넘어가고, `c.Next()` 이후의 코드는 응답이 완료된 후 실행됩니다. 이 패턴을 이용해 요청 전처리와 응답 후처리를 하나의 함수 안에 표현할 수 있습니다.

```go
package main

import (
    "fmt"
    "log/slog"
    "net/http"
    "strings"
    "time"

    "github.com/gin-gonic/gin"
)

// ─── 미들웨어 1: 요청 로깅 ──────────────────────────────
func LoggerMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        path := c.Request.URL.Path

        // c.Next() 이전: 요청 처리 전
        c.Next()
        // c.Next() 이후: 응답 완료 후

        latency := time.Since(start)
        status := c.Writer.Status()

        slog.Info("request",
            "method",  c.Request.Method,
            "path",    path,
            "status",  status,
            "latency", latency,
            "ip",      c.ClientIP(),
        )
    }
}

// ─── 미들웨어 2: API Key 인증 ────────────────────────────
func APIKeyMiddleware(validKeys map[string]bool) gin.HandlerFunc {
    return func(c *gin.Context) {
        apiKey := c.GetHeader("X-API-Key")

        if apiKey == "" {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
                "error": "API 키가 필요합니다",
            })
            return // Abort 이후에도 return 필요
        }

        if !validKeys[apiKey] {
            c.AbortWithStatusJSON(http.StatusForbidden, gin.H{
                "error": "유효하지 않은 API 키",
            })
            return
        }

        // 컨텍스트에 인증 정보 저장 (이후 핸들러에서 사용)
        c.Set("authenticated", true)
        c.Set("api_key", apiKey)

        c.Next() // 다음 핸들러로 진행
    }
}

// ─── 미들웨어 3: CORS 처리 ────────────────────────────────
func CORSMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Header("Access-Control-Allow-Origin", "*")
        c.Header("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
        c.Header("Access-Control-Allow-Headers", "Content-Type, Authorization, X-API-Key")

        // Preflight 요청 처리
        if c.Request.Method == http.MethodOptions {
            c.AbortWithStatus(http.StatusNoContent)
            return
        }

        c.Next()
    }
}

// ─── 미들웨어 4: 요청 크기 제한 ──────────────────────────
func RequestSizeLimiter(maxBytes int64) gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, maxBytes)
        c.Next()
    }
}

func main() {
    r := gin.New() // 빈 엔진 (미들웨어 없음)

    // 전역 미들웨어 등록 (모든 라우트에 적용)
    r.Use(gin.Recovery())      // panic 복구
    r.Use(LoggerMiddleware())   // 요청 로깅
    r.Use(CORSMiddleware())     // CORS
    r.Use(RequestSizeLimiter(1 << 20)) // 1MB 제한

    // 공개 라우트 (인증 불필요)
    public := r.Group("/")
    {
        public.GET("/health", func(c *gin.Context) {
            c.JSON(http.StatusOK, gin.H{"status": "healthy"})
        })
    }

    // 인증이 필요한 라우트
    validKeys := map[string]bool{"secret-key-123": true}
    protected := r.Group("/api")
    protected.Use(APIKeyMiddleware(validKeys)) // 그룹에만 미들웨어 적용
    {
        protected.GET("/me", func(c *gin.Context) {
            key, _ := c.Get("api_key")
            c.JSON(http.StatusOK, gin.H{
                "message": fmt.Sprintf("인증된 요청: %v", key),
            })
        })
        protected.GET("/data", func(c *gin.Context) {
            c.JSON(http.StatusOK, gin.H{"data": []string{"a", "b", "c"}})
        })
    }

    // 미들웨어 체인 실행 순서 시각화:
    // Request → Recovery → Logger → CORS → SizeLimiter → [APIKey] → Handler
    //                                                                    ↓
    // Response ←─────────────────────────────────────────────────────────

    r.Run(":8080")
}

// 커스텀 유효성 검사기 등록 예제
func registerCustomValidators() {

}
```

```
│recover() │    │c.Next()  │    │c.Next()  │    │c.Next()  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                     │
                                                     ▼
                                               ┌──────────┐
                                               │ Handler  │
                                               │(비즈니스  │
                                               │  로직)   │
                                               └──────────┘
                                                     │
                              응답 완료 후 역순 실행  │
                                                     ▼
┌──────────┐    ┌──────────┐
│Recovery  │◀───│ Logger   │◀── (APIKey, CORS는 c.Next() 이후 코드 없음)
│(정상종료) │    │latency   │
│          │    │logging   │
└──────────┘    └──────────┘
```

## **6.3 Echo 프레임워크 — "우아하고, 이디엄적이다"**

### **6.3.1 Echo의 설계 철학**

Echo는 Gin과 유사한 성능을 제공하면서도, Go의 관용적인 스타일에 더욱 충실한 설계를 지향합니다. 가장 눈에 띄는 차이점은 두 가지입니다.

첫 번째로, **핸들러가 `error`를 반환합니다.** Gin의 핸들러는 `func(c *gin.Context)` 형태로 반환값이 없지만, Echo의 핸들러는 `func(c echo.Context) error` 형태를 가집니다. 이는 Go의 에러 처리 관용구와 자연스럽게 어울리며, 핸들러 내에서 에러를 `return`하면 Echo의 에러 핸들러가 이를 처리합니다.

두 번째로, Echo는 **표준 `context.Context`를 더 자연스럽게 활용**할 수 있습니다. `c.Request().Context()`를 통해 표준 컨텍스트에 접근하며, Go 1.22 이후의 생태계와 더 잘 통합됩니다.

```
┌─────────────────────────────────────────────────────────┐
│          Gin vs Echo: 핸들러 시그니처 비교               │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Gin:                                                   │
│  func handler(c *gin.Context) {                         │
│      // 에러를 직접 응답으로 변환해야 함                  │
│      if err != nil {                                    │
│          c.JSON(500, gin.H{"error": err.Error()})       │
│          return  ← return은 함수 종료만, Abort와 다름    │
│      }                                                  │
│  }                                                      │
│                                                         │
│  Echo:                                                  │
│  func handler(c echo.Context) error {                   │
│      if err != nil {                                    │
│          return err  ← Echo의 에러 핸들러가 처리        │
│      }                                                  │
│      return c.JSON(200, data)  ← 이것도 error 반환     │
│  }                                                      │
│                                                         │
│  → Echo의 방식이 Go 표준 에러 처리 패턴에 더 가깝다      │
└─────────────────────────────────────────────────────────┘
```

### **6.3.4 Echo의 바인딩과 유효성 검사**

Echo의 `Bind` 메서드는 Content-Type에 따라 자동으로 JSON, XML, Form 데이터를 바인딩합니다. 유효성 검사는 `echo.Validator` 인터페이스를 구현하여 직접 연결합니다. 이 방식은 유효성 검사 라이브러리를 자유롭게 교체할 수 있는 유연성을 제공합니다.

```go
package main

import (
    "net/http"

    "github.com/go-playground/validator/v10"
    "github.com/labstack/echo/v4"
    "github.com/labstack/echo/v4/middleware"
)

// ─── 커스텀 Validator 구현 ───────────────────────────────
// Echo는 Validator 인터페이스를 직접 구현해야 함
type CustomValidator struct {
    validator *validator.Validate
}

// Validate: echo.Validator 인터페이스 구현
func (cv *CustomValidator) Validate(i interface{}) error {
    if err := cv.validator.Struct(i); err != nil {
        return echo.NewHTTPError(http.StatusBadRequest, err.Error())
    }
    return nil
}

// ─── 요청/응답 구조체 ────────────────────────────────────
type CreateProductRequest struct {
    Name        string  `json:"name"         validate:"required,min=2,max=100"`
    Price       float64 `json:"price"        validate:"required,gt=0"`
    Category    string  `json:"category"     validate:"required,oneof=electronics clothing food"`
    Stock       int     `json:"stock"        validate:"min=0"`
    Description string  `json:"description"  validate:"max=500"`
}

type ProductResponse struct {
    ID       int     `json:"id"`
    Name     string  `json:"name"`
    Price    float64 `json:"price"`
    Category string  `json:"category"`
    Stock    int     `json:"stock"`
}

func main() {
    e := echo.New()
    e.Use(middleware.Logger())
    e.Use(middleware.Recover())

    // 커스텀 Validator 등록
    e.Validator = &CustomValidator{
        validator: validator.New(),
    }

    e.POST("/products", createProductHandler)

    e.Logger.Fatal(e.Start(":8080"))
}

func createProductHandler(c echo.Context) error {
    req := new(CreateProductRequest)

    // Bind: JSON 파싱 (Content-Type 자동 감지)
    if err := c.Bind(req); err != nil {
        return echo.NewHTTPError(http.StatusBadRequest, "잘못된 요청 형식")
    }

    // Validate: 등록된 커스텀 Validator 호출
    if err := c.Validate(req); err != nil {
        return err // HTTPError로 이미 감싸져 있음
    }

    // 비즈니스 로직
    resp := ProductResponse{
        ID:       42,
        Name:     req.Name,
        Price:    req.Price,
        Category: req.Category,
        Stock:    req.Stock,
    }

    return c.JSON(http.StatusCreated, resp)
}
```

### **6.3.5 Echo의 에러 처리 — 집중형 에러 핸들러**

Echo의 가장 강력한 기능 중 하나는 **집중형 에러 핸들러(Centralized Error Handler)** 입니다. 모든 핸들러에서 반환된 `error`는 이 하나의 함수로 모입니다. 덕분에 에러 응답 형식을 애플리케이션 전체에 걸쳐 일관되게 유지할 수 있습니다.

```go
package main

import (
    "errors"
    "net/http"

    "github.com/labstack/echo/v4"
    "github.com/labstack/echo/v4/middleware"
)

// ─── 도메인 에러 정의 ────────────────────────────────────
var (
    ErrNotFound     = errors.New("리소스를 찾을 수 없습니다")
    ErrUnauthorized = errors.New("인증이 필요합니다")
    ErrForbidden    = errors.New("권한이 없습니다")
    ErrConflict     = errors.New("이미 존재하는 리소스입니다")
)

// AppError: 애플리케이션 전용 에러 타입
type AppError struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Detail  string `json:"detail,omitempty"`
}

func (e *AppError) Error() string {
    return e.Message
}

// ─── 집중형 에러 핸들러 ──────────────────────────────────
func customErrorHandler(err error, c echo.Context) {
    // 이미 응답이 완료된 경우 처리하지 않음
    if c.Response().Committed {
        return
    }

    var (
        code     = http.StatusInternalServerError
        response = &AppError{Code: 500, Message: "서버 내부 오류"}
    )

    // 에러 타입에 따른 분기 처리
    var appErr *AppError
    var httpErr *echo.HTTPError

    switch {
    case errors.As(err, &appErr):
        // 애플리케이션 커스텀 에러
        code = appErr.Code
        response = appErr

    case errors.As(err, &httpErr):
        // Echo HTTP 에러 (echo.NewHTTPError로 생성)
        code = httpErr.Code
        response = &AppError{
            Code:    httpErr.Code,
            Message: http.StatusText(httpErr.Code),
        }
        if msg, ok := httpErr.Message.(string); ok {
            response.Message = msg
        }

    case errors.Is(err, ErrNotFound):
        code = http.StatusNotFound
        response = &AppError{Code: 404, Message: "리소스를 찾을 수 없습니다"}

    case errors.Is(err, ErrUnauthorized):
        code = http.StatusUnauthorized
        response = &AppError{Code: 401, Message: "인증이 필요합니다"}
    }

    c.JSON(code, response) //nolint:errcheck
}

func main() {
    e := echo.New()
    e.Use(middleware.Logger())
    e.Use(middleware.Recover())

    // 커스텀 에러 핸들러 등록
    e.HTTPErrorHandler = customErrorHandler

    // 에러를 반환하는 핸들러 예시
    e.GET("/items/:id", func(c echo.Context) error {
        id := c.Param("id")
        if id == "0" {
            // 도메인 에러 반환 → customErrorHandler에서 처리
            return &AppError{
                Code:    http.StatusNotFound,
                Message: "아이템을 찾을 수 없습니다",
                Detail:  "ID 0은 예약된 값입니다",
            }
        }
        if id == "999" {
            return ErrNotFound // sentinel error 반환
        }
        return c.JSON(http.StatusOK, map[string]string{"id": id})
    })

    e.Logger.Fatal(e.Start(":8080"))
}
```

```
Echo 에러 처리 흐름:

Handler 실행
    │
    ├── error == nil ──▶ 정상 응답 반환
    │
    └── error != nil
            │
            ▼
    ┌───────────────────────┐
    │ HTTPErrorHandler 호출  │
    │ (기본 or 커스텀)       │
    └──────────┬────────────┘
               │
    ┌──────────▼────────────────────────────────┐
    │  errors.As(err, &AppError) → 커스텀 응답  │
    │  errors.As(err, &HTTPError) → HTTP 코드  │
    │  errors.Is(err, ErrNotFound) → 404       │
    │  그 외 → 500 Internal Server Error        │
    └────────────────────────────────────────────┘
               │
               ▼
    JSON 응답 { code, message, detail }
```

두 프레임워크는 매우 유사하지만, 세부적인 차이가 있습니다. 아래 비교를 참고하여 팀의 상황에 맞는 선택을 하시기 바랍니다.

```
┌────────────────────────────────────────────────────────────────────┐

├─────────────────────┬──────────────────────┬───────────────────────┤
│       항목          │         Gin           │        Echo           │
├─────────────────────┼──────────────────────┼───────────────────────┤
```

## **6.5 공통 패턴 — 실무에서 자주 쓰이는 기법**

### **6.5.1 JWT 인증 미들웨어**

JWT(JSON Web Token) 기반 인증은 REST API에서 가장 널리 사용되는 인증 방식입니다. 여기서는 Gin을 예시로 JWT 미들웨어를 직접 구현합니다.

```go
package middleware

import (
    "errors"
    "net/http"
    "strings"
    "time"

    "github.com/gin-gonic/gin"
    "github.com/golang-jwt/jwt/v5"
)

// Claims: JWT 페이로드 구조체
type Claims struct {
    UserID   uint   `json:"user_id"`
    Username string `json:"username"`
    Role     string `json:"role"`
    jwt.RegisteredClaims
}

// JWTConfig: JWT 미들웨어 설정
type JWTConfig struct {
    SecretKey     []byte
    TokenExpiry   time.Duration
    RefreshExpiry time.Duration
}

// GenerateToken: JWT 토큰 생성
func (cfg *JWTConfig) GenerateToken(userID uint, username, role string) (string, error) {
    claims := &Claims{
        UserID:   userID,
        Username: username,
        Role:     role,
        RegisteredClaims: jwt.RegisteredClaims{
            ExpiresAt: jwt.NewNumericDate(time.Now().Add(cfg.TokenExpiry)),
            IssuedAt:  jwt.NewNumericDate(time.Now()),
            Issuer:    "golang-guide",
        },
    }

    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    return token.SignedString(cfg.SecretKey)
}

// JWTAuthMiddleware: Gin용 JWT 인증 미들웨어
func (cfg *JWTConfig) JWTAuthMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        // Authorization 헤더에서 토큰 추출
        authHeader := c.GetHeader("Authorization")
        if authHeader == "" {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
                "error": "Authorization 헤더가 없습니다",
            })
            return
        }

        // "Bearer <token>" 형식 파싱
        parts := strings.SplitN(authHeader, " ", 2)
        if len(parts) != 2 || parts[0] != "Bearer" {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
                "error": "잘못된 Authorization 헤더 형식",
            })
            return
        }

        tokenString := parts[1]

        // 토큰 파싱 및 검증
        claims := &Claims{}
        token, err := jwt.ParseWithClaims(tokenString, claims,
            func(t *jwt.Token) (interface{}, error) {
                // 서명 알고리즘 검증 (알고리즘 변조 공격 방지)
                if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
                    return nil, errors.New("예상치 못한 서명 알고리즘")
                }
                return cfg.SecretKey, nil
            },
        )

        if err != nil || !token.Valid {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{
                "error": "유효하지 않은 토큰",
            })
            return
        }

        // 검증된 클레임을 컨텍스트에 저장
        c.Set("userID", claims.UserID)
        c.Set("username", claims.Username)
        c.Set("role", claims.Role)

        c.Next()
    }
}

// RoleMiddleware: 역할 기반 접근 제어 (RBAC)
func RoleMiddleware(allowedRoles ...string) gin.HandlerFunc {
    roleSet := make(map[string]bool)
    for _, r := range allowedRoles {
        roleSet[r] = true
    }

    return func(c *gin.Context) {
        role, exists := c.Get("role")
        if !exists {
            c.AbortWithStatusJSON(http.StatusForbidden, gin.H{
                "error": "역할 정보가 없습니다",
            })
            return
        }

        if !roleSet[role.(string)] {
            c.AbortWithStatusJSON(http.StatusForbidden, gin.H{
                "error": "권한이 없습니다",
            })
            return
```

```go
type BookRepository struct {
    mu      sync.RWMutex
    books   map[uint]*Book
    counter atomic.Uint64

func NewBookRepository() *BookRepository {
    repo := &BookRepository{
        books: make(map[uint]*Book),
    }
    // 초기 데이터
    repo.seed()
    return repo
}

func (r *BookRepository) seed() {
    seeds := []CreateBookRequest{
        {Title: "Go 프로그래밍 언어", Author: "Alan Donovan", ISBN: "9780134190440",
            PublishedAt: "2015-10-26", Price: 45000, Stock: 10},
        {Title: "클린 코드", Author: "Robert C. Martin", ISBN: "9780132350884",
            PublishedAt: "2008-08-01", Price: 38000, Stock: 5},
        {Title: "도메인 주도 설계", Author: "Eric Evans", ISBN: "9780321125217",
            PublishedAt: "2003-08-22", Price: 52000, Stock: 3},
    }
    for _, s := range seeds {
        r.Create(s)
    }
}

func (r *BookRepository) Create(req CreateBookRequest) (*Book, error) {
    r.mu.Lock()
    defer r.mu.Unlock()

    // ISBN 중복 확인
    for _, b := range r.books {
        if b.ISBN == req.ISBN {
            return nil, ErrBookDuplicate
        }
    }

    publishedAt, err := time.Parse("2006-01-02", req.PublishedAt)
    if err != nil {
        return nil, fmt.Errorf("날짜 형식 오류: %w", err)
    }

    r.counter.Add(1)
    id := uint(r.counter.Load())

    book := &Book{
        ID:          id,
        Title:       req.Title,
        Author:      req.Author,
        ISBN:        req.ISBN,
        PublishedAt: publishedAt,
        Price:       req.Price,
        Stock:       req.Stock,
        CreatedAt:   time.Now(),
        UpdatedAt:   time.Now(),
    }
    r.books[id] = book
    return book, nil
}

func (r *BookRepository) FindByID(id uint) (*Book, error) {
    r.mu.RLock()
    defer r.mu.RUnlock()

    book, ok := r.books[id]
    if !ok {
        return nil, ErrBookNotFound
    }
    // 복사본 반환 (원본 보호)
    copied := *book
    return &copied, nil
}

func (r *BookRepository) FindAll(author string, page, limit int) ([]*Book, int) {
    r.mu.RLock()
    defer r.mu.RUnlock()

    var filtered []*Book
    for _, b := range r.books {
        if author == "" || b.Author == author {
            copied := *b
            filtered = append(filtered, &copied)
        }
    }

    total := len(filtered)
    start := (page - 1) * limit
    end := start + limit
    if start >= total {
        return []*Book{}, total
    }
    if end > total {
        end = total
    }
    return filtered[start:end], total
}

func (r *BookRepository) Update(id uint, req UpdateBookRequest) (*Book, error) {
    r.mu.Lock()
    defer r.mu.Unlock()

    book, ok := r.books[id]
    if !ok {
        return nil, ErrBookNotFound
    }

    if req.Title != nil {
        book.Title = *req.Title
    }
    if req.Price != nil {
        book.Price = *req.Price
    }
    if req.Stock != nil {
        book.Stock = *req.Stock
    }
    book.UpdatedAt = time.Now()

    copied := *book
    return &copied, nil
}

func (r *BookRepository) Delete(id uint) error {
    r.mu.Lock()
    defer r.mu.Unlock()

    if _, ok := r.books[id]; !ok {
        return ErrBookNotFound
    }
    delete(r.books, id)
    return nil
}

// ═══════════════════════════════════════════════════════════
//  인증 핸들러
// ═══════════════════════════════════════════════════════════

var jwtSecret = []byte("golang-guide-secret-key-change-in-production")

type AuthClaims struct {
    UserID   uint   `json:"user_id"`
    Username string `json:"username"`
    Role     string `json:"role"`
    jwt.RegisteredClaims
}

// 간단한 인메모리 사용자 저장소
var users = map[string]*User{
    "admin": {ID: 1, Username: "admin", PasswordHash: "admin1234", Role: "admin"},
    "user":  {ID: 2, Username: "user", PasswordHash: "user1234", Role: "user"},
}

func loginHandler(c *gin.Context) {
    var req LoginRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        respondError(c, http.StatusBadRequest, err.Error())
        return
    }

    user, ok := users[req.Username]
    if !ok || user.PasswordHash != req.Password {
        respondError(c, http.StatusUnauthorized, "아이디 또는 비밀번호가 올바르지 않습니다")
        return
    }

    expiresAt := time.Now().Add(24 * time.Hour)
    claims := &AuthClaims{
        UserID:   user.ID,
        Username: user.Username,
        Role:     user.Role,
        RegisteredClaims: jwt.RegisteredClaims{
            ExpiresAt: jwt.NewNumericDate(expiresAt),
            IssuedAt:  jwt.NewNumericDate(time.Now()),
        },
    }

    token := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
    tokenString, err := token.SignedString(jwtSecret)
    if err != nil {
        respondError(c, http.StatusInternalServerError, "토큰 생성 실패")
        return
    }

    resp := LoginResponse{
        Token:     tokenString,
        ExpiresAt: expiresAt,
    }
    resp.User.ID = user.ID
    resp.User.Username = user.Username
    resp.User.Role = user.Role

    c.JSON(http.StatusOK, APIResponse[LoginResponse]{Success: true, Data: resp})
}

//  미들웨어
// ═══════════════════════════════════════════════════════════

// JWTMiddleware: JWT 토큰 검증
func JWTMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        authHeader := c.GetHeader("Authorization")
        if authHeader == "" || len(authHeader) < 8 || authHeader[:7] != "Bearer " {
            c.AbortWithStatusJSON(http.StatusUnauthorized, APIResponse[any]{
                Error: "유효한 Bearer 토큰이 필요합니다",
            })
            return
        }

        tokenString := authHeader[7:]
        claims := &AuthClaims{}

        token, err := jwt.ParseWithClaims(tokenString, claims,
            func(t *jwt.Token) (interface{}, error) {
                if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
                    return nil, fmt.Errorf("예상치 못한 서명 알고리즘: %v", t.Header["alg"])
                }
                return jwtSecret, nil
            },
        )

        if err != nil || !token.Valid {
            c.AbortWithStatusJSON(http.StatusUnauthorized, APIResponse[any]{
                Error: "유효하지 않거나 만료된 토큰",
            })
            return
        }

        c.Set("userID", claims.UserID)
        c.Set("username", claims.Username)
        c.Set("role", claims.Role)
        c.Next()
    }
}

// AdminMiddleware: 관리자 권한 확인
func AdminMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        role, _ := c.Get("role")
        if role != "admin" {
            c.AbortWithStatusJSON(http.StatusForbidden, APIResponse[any]{
                Error: "관리자 권한이 필요합니다",
            })
            return
        }
        c.Next()
    }
}

// RequestLogger: 구조화된 요청 로깅
func RequestLogger(logger *slog.Logger) gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        c.Next()
        logger.Info("HTTP",
            "method",  c.Request.Method,
            "path",    c.Request.URL.Path,
            "status",  c.Writer.Status(),
            "latency", time.Since(start).String(),
            "ip",      c.ClientIP(),
        )
    }
}

func respondError(c *gin.Context, code int, msg string) {

func parseUintParam(c *gin.Context, param string) (uint, error) {
    val, err := strconv.ParseUint(c.Param(param), 10, 64)
    if err != nil {
        return 0, err
    }
    return uint(val), nil
}

func main() {
    logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
        Level: slog.LevelInfo,
    }))

    // 의존성 조립
    bookRepo    := NewBookRepository()
    bookService := NewBookService(bookRepo)
    bookHandler := NewBookHandler(bookService)

    // Gin 엔진 설정
    r := gin.New()

    r.Use(RequestLogger(logger))

    // ─── 공개 라우트 ─────────────────────────────────────
    r.GET("/health", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{
            "status":    "healthy",
            "timestamp": time.Now().Format(time.RFC3339),
            "version":   "1.0.0",
        })
    })

    auth := r.Group("/auth")
    {
        auth.POST("/login", loginHandler)

    // 공개 도서 조회 (인증 불필요)
    r.GET("/books", bookHandler.ListBooks)
    r.GET("/books/:id", bookHandler.GetBook)

    // ─── 인증 필요 라우트 ──────────────────────────────────
    protected := r.Group("/api/v1")
    protected.Use(JWTMiddleware())
    {
        // 로그인한 사용자: 내 정보 조회
        protected.GET("/me", func(c *gin.Context) {
            c.JSON(http.StatusOK, APIResponse[map[string]any]{
                Success: true,
                Data: map[string]any{
                    "user_id":  c.MustGet("userID"),
                    "username": c.MustGet("username"),
                    "role":     c.MustGet("role"),
                },
            })
        })

        // 관리자 전용: 도서 CRUD
        admin := protected.Group("")
        admin.Use(AdminMiddleware())
        {
            admin.POST("/books", bookHandler.CreateBook)
            admin.PUT("/books/:id", bookHandler.UpdateBook)
            admin.DELETE("/books/:id", bookHandler.DeleteBook)
        }
    }

    // 서버 시작
    addr := ":8080"
    logger.Info("서버 시작", "address", addr)
    logger.Info("API 엔드포인트 목록",
        "공개",     "GET /health, GET /books, GET /books/:id, POST /auth/login",
        "인증필요", "GET /api/v1/me",
        "관리자",   "POST /api/v1/books, PUT /api/v1/books/:id, DELETE /api/v1/books/:id",
    )
    if err := r.Run(addr); err != nil {
        logger.Error("서버 오류", "error", err)
        os.Exit(1)
    }
}
```

## **챕터 정리**

이 챕터에서는 Go 웹 프레임워크의 양대 산맥인 **Gin**과 **Echo**를 깊이 있게 살펴보았습니다.

Gin은 거대한 커뮤니티, 풍부한 에코시스템, 직관적인 API를 바탕으로 Go 웹 개발의 사실상 표준으로 자리잡았습니다. `gin.Context`를 중심으로 요청 파싱부터 응답 렌더링까지 모든 것을 처리하며, 강력한 바인딩 및 유효성 검사 시스템이 내장되어 있습니다. 미들웨어 체이닝의 `c.Next()` 패턴은 요청 전처리와 후처리를 하나의 함수로 표현하는 우아한 방법입니다.

Echo는 Go의 관용적인 에러 처리 패턴을 핸들러 시그니처에 녹여낸 프레임워크입니다. 핸들러가 `error`를 반환하고, 집중형 에러 핸들러가 이를 처리하는 구조는 에러 응답 형식의 일관성을 유지하기 매우 쉽게 만듭니다. 또한 유효성 검사 라이브러리를 인터페이스로 주입하는 방식은 더 큰 유연성을 제공합니다.

실전 프로그램에서는 **계층형 아키텍처(Handler → Service → Repository)**, **JWT 기반 인증**, **역할 기반 접근 제어(RBAC)**, **구조화된 응답 형식**, **제네릭을 활용한 `APIResponse[T]`** 를 통합하여 실무에 바로 적용 가능한 수준의 API 서버를 구축했습니다. 다음 챕터에서는 이 서버에 실제 데이터베이스를 연결하는 방법을 배우게 됩니다.

**핵심 요약:**

- **Gin**: `func(c *gin.Context)` 핸들러, 내장 유효성 검사, 최대 커뮤니티, `c.Next()`로 미들웨어 제어
- **Echo**: `func(c echo.Context) error` 핸들러, 집중형 에러 핸들러, 유연한 Validator 인터페이스

- **프로젝트 구조**: Handler / Service / Repository 계층 분리로 테스트 가능하고 유지보수 쉬운 코드
