CHAPTER 06

모던 C++을 활용한 RIO 래퍼 클래스

1장부터 5장까지 우리는 RIORegisterBuffer·RIOCreateRequestQueue 같은 RIO 함수를 거의 매 장 손으로 다시 호출하고, 실패를 검사하고, RAII로 정리했습니다. 이번 장에서는 그 반복을 한 번에 정리해 재사용 가능한 라이브러리로 묶습니다. C++20의 concept, C++23의 std::expected·std::print를 적극 활용해, RIO의 날것 그대로의 C API를 안전하고 읽기 쉬운 C++ 인터페이스로 감쌉니다.

이 장에서 배우는 것

  • 이동 전용(move-only) RAII 클래스로 소켓·버퍼·큐를 감싸는 표준 패턴
  • C++20 concept으로 "바이트로 다룰 수 있는 타입"을 컴파일 타임에 제약하는 법
  • 임의의 구조체를 담는 템플릿 버퍼와, 버퍼를 재사용하는 풀의 함정
  • std::span 기반 버퍼 뷰로 복사 없이 버퍼 일부를 슬라이싱하기
  • std::expected·std::print로 오류 처리와 로깅을 통일하기
  • std::atomic 멤버가 있는 클래스는 왜 이동조차 안 되는지, 그리고 이를 올바르게 설계하는 법
  • 지금까지 만든 모든 조각을 묶은 통합 RIOManager와 에코 서버 완성

6.1 RAII 패턴을 이용한 리소스 관리

소켓, 버퍼 ID, 완료 큐, 요청 큐 — RIO가 다루는 자원 넷을 각각 하나의 클래스로 감쌉니다.

WSA 초기화 및 소켓 관리

WSAManager는 1장부터 반복했던 WSAStartup/WSACleanup 쌍을 생성자·소멸자로 옮긴 가장 단순한 RAII 클래스입니다. 생성 뒤에는 반드시 IsInitialized()를 확인해야 하며, 성공한 인스턴스가 살아있는 동안에만 Winsock 정리 시점을 한 곳에 묶을 수 있습니다.

class WSAManager {
private:
    bool initialized_ = false;

public:
    WSAManager() {
        WSADATA wsa_data{};
        int result = WSAStartup(MAKEWORD(2, 2), &wsa_data);
        if (result == 0) {
            initialized_ = true;
            std::print("WSA 초기화 성공\n");
        } else {
            std::print("WSA 초기화 실패: {}\n", result);
        }
    }

    ~WSAManager() {
        if (initialized_) {
            WSACleanup();
            std::print("WSA 정리 완료\n");
        }
    }

    bool IsInitialized() const { return initialized_; }

    WSAManager(const WSAManager&) = delete;
    WSAManager& operator=(const WSAManager&) = delete;
    WSAManager(WSAManager&&) = delete;
    WSAManager& operator=(WSAManager&&) = delete;
};

std::print — 간결한 형식 기반 출력

이 장부터는 std::cout << std::format(...) 대신 C++23의 std::print()를 씁니다. std::format으로 문자열을 만든 뒤 스트림에 흘려보내는 두 단계를 한 번에 처리합니다. 컴파일 타임 형식 문자열을 사용할 때는 인자와 형식의 호환성도 검사합니다. 다만 iostream보다 항상 빠르다는 성능 보장은 없습니다. 이 예제는 <print>를 지원하는 C++23 표준 라이브러리를 전제로 합니다.

Socket은 소켓 핸들 하나를 감싸는 클래스입니다. 여기서부터 이 장 전체에 반복되는 패턴이 등장합니다 — 복사는 금지하고, 이동만 허용합니다. 

class Socket {
private:
    SOCKET socket_ = INVALID_SOCKET;

public:
    Socket() = default;

    explicit Socket(SOCKET socket) : socket_(socket) {
        std::print("소켓 생성됨: {}\n", static_cast<UINT_PTR>(socket_));
    }

    ~Socket() { Close(); }

    // 이동은 허용 — 소유권만 옮겨감
    Socket(Socket&& other) noexcept : socket_(other.socket_) {
        other.socket_ = INVALID_SOCKET;
    }
    Socket& operator=(Socket&& other) noexcept {
        if (this != &other) {
            Close();
            socket_ = other.socket_;
            other.socket_ = INVALID_SOCKET;
        }
        return *this;
    }

    // 복사는 금지 — 같은 핸들을 두 객체가 "소유"하면 이중 해제(double close) 위험
    Socket(const Socket&) = delete;
    Socket& operator=(const Socket&) = delete;

    std::expected<void, std::string> Create() {
        Close();
        socket_ = WSASocketW(AF_INET, SOCK_STREAM, IPPROTO_TCP, NULL, 0, WSA_FLAG_REGISTERED_IO);
        if (socket_ == INVALID_SOCKET) {
            return std::unexpected(std::format("RIO 소켓 생성 실패: {}", WSAGetLastError()));
        }
        std::print("RIO 소켓 생성 성공: {}\n", static_cast<UINT_PTR>(socket_));
        return {};
    }

    void Close() {
        if (socket_ != INVALID_SOCKET) {
            // RIO 세션에서는 이 전에 새 I/O를 막고 모든 완료를 회수해야 한다.
            closesocket(socket_);
            std::print("소켓 닫힘: {}\n", static_cast<UINT_PTR>(socket_));
            socket_ = INVALID_SOCKET;
        }
    }

    SOCKET Get() const { return socket_; }
    bool IsValid() const { return socket_ != INVALID_SOCKET; }

    std::expected<void, std::string> BindAndListen(uint16_t port, int backlog = SOMAXCONN) {
        if (!IsValid()) return std::unexpected("유효하지 않은 소켓");

        sockaddr_in addr{};
        addr.sin_family = AF_INET;
        addr.sin_addr.s_addr = htonl(INADDR_ANY);
        addr.sin_port = htons(port);

        if (bind(socket_, reinterpret_cast<sockaddr*>(&addr), sizeof(addr)) == SOCKET_ERROR) {
            return std::unexpected(std::format("소켓 바인딩 실패: {}", WSAGetLastError()));
        }
        if (listen(socket_, backlog) == SOCKET_ERROR) {
            return std::unexpected(std::format("리스닝 실패: {}", WSAGetLastError()));
        }
        std::print("소켓 바인드 및 리스닝 시작 - 포트: {}\n", port);
        return {};
    }
};

왜 "복사 금지 + 이동 허용"이 RIO 리소스의 표준 패턴인가

SOCKET, RIO_BUFFERID, RIO_CQ, RIO_RQ는 모두 운영체제가 관리하는 단 하나의 자원을 가리키는 핸들입니다. 이 핸들을 복사하면 두 C++ 객체가 "내가 이 자원의 주인이다"라고 동시에 착각하게 되고, 둘 다 소멸자에서 해제를 시도하면 이미 닫힌 자원을 또 닫는 이중 해제가 발생합니다. 반면 이동은 "소유권을 한쪽에서 다른 쪽으로 넘기고, 원래 쪽은 빈 상태(INVALID_SOCKET 등)로 만든다"는 뜻이라 안전합니다. 이후 나올 RIOBuffer·RIOCompletionQueue· RIORequestQueue도 전부 이 패턴을 따르므로, 한 번 이해해두면 나머지는 같은 구조가 반복될 뿐입니다.

RIO 함수 테이블 관리

RIOFunctionTable은 2~5장에서 반복했던 WSAIoctl() 호출을 감쌉니다. 이번에는 RIO 지원 소켓을 넘겨 함수 테이블을 채웁니다. 함수 테이블은 프로세스에서 재사용할 수 있지만, RIO 요청 큐는 뒤에서 보듯 반드시 실제 통신에 사용할 등록 I/O 소켓마다 만듭니다. 

class RIOFunctionTable {
private:
    RIO_EXTENSION_FUNCTION_TABLE functions_{};
    bool initialized_ = false;

public:
    RIOFunctionTable() = default;

    std::expected<void, std::string> Initialize(SOCKET socket) {
        if (initialized_) return {};

        GUID function_table_id = WSAID_MULTIPLE_RIO;
        DWORD bytes = 0;

        int result = WSAIoctl(
            socket, SIO_GET_MULTIPLE_EXTENSION_FUNCTION_POINTER,
            &function_table_id, sizeof(function_table_id),
            &functions_, sizeof(functions_),
            &bytes, NULL, NULL
        );

        if (result == SOCKET_ERROR) {
            return std::unexpected(std::format("RIO 함수 테이블 초기화 실패: {}", WSAGetLastError()));
        }

        initialized_ = true;
        std::print("RIO 함수 테이블 초기화 성공\n");
        return {};
    }

    const RIO_EXTENSION_FUNCTION_TABLE& Get() const { return functions_; }
    bool IsInitialized() const { return initialized_; }
};

RIO 버퍼 관리

RIOBuffer는 4장의 RIOBufferManager와 같은 역할(등록·해제 RAII)을 하지만, 이동 생성자·이동 대입 연산자까지 갖춰 std::vector나 다른 클래스의 멤버로 자유롭게 담을 수 있도록 다듬었습니다. 또한 CreateRIOBuf()를 오버로드해 "전체 버퍼"와 "부분 구간"을 모두 간단히 RIO_BUF로 변환할 수 있게 했습니다. 

class RIOBuffer {
private:
    std::vector<char> buffer_;
    RIO_BUFFERID buffer_id_ = RIO_INVALID_BUFFERID;
    const RIO_EXTENSION_FUNCTION_TABLE* functions_ = nullptr;

public:
    RIOBuffer() = default;

    RIOBuffer(const RIO_EXTENSION_FUNCTION_TABLE& functions, size_t size)
        : functions_(&functions) {
        if (size == 0 || size > (std::numeric_limits<DWORD>::max)()) {
            throw std::invalid_argument("RIO 버퍼 크기는 1 이상 DWORD 범위여야 합니다");
        }
        buffer_.resize(size);
        std::print("RIO 버퍼 생성: {}바이트\n", size);
    }

    ~RIOBuffer() { Deregister(); }

    RIOBuffer(RIOBuffer&& other) noexcept
        : buffer_(std::move(other.buffer_)), buffer_id_(other.buffer_id_), functions_(other.functions_) {
        other.buffer_id_ = RIO_INVALID_BUFFERID;
        other.functions_ = nullptr;
    }
    RIOBuffer& operator=(RIOBuffer&& other) noexcept {
        if (this != &other) {
            Deregister();
            buffer_ = std::move(other.buffer_);
            buffer_id_ = other.buffer_id_;
            functions_ = other.functions_;
            other.buffer_id_ = RIO_INVALID_BUFFERID;
            other.functions_ = nullptr;
        }
        return *this;
    }

    RIOBuffer(const RIOBuffer&) = delete;
    RIOBuffer& operator=(const RIOBuffer&) = delete;

    std::expected<void, std::string> Register() {
        if (buffer_id_ != RIO_INVALID_BUFFERID) return {};   // 이미 등록됨
        if (!functions_ || buffer_.empty()) {
            return std::unexpected("RIO 함수 테이블이 초기화되지 않았거나 버퍼가 비어있습니다");
        }

        buffer_id_ = functions_->RIORegisterBuffer(buffer_.data(), static_cast<DWORD>(buffer_.size()));
        if (buffer_id_ == RIO_INVALID_BUFFERID) {
            return std::unexpected(std::format("RIO 버퍼 등록 실패: {}", WSAGetLastError()));
        }
        std::print("RIO 버퍼 등록 성공: {} 바이트\n", buffer_.size());
        return {};
    }

    void Deregister() {
        if (buffer_id_ != RIO_INVALID_BUFFERID && functions_) {
            functions_->RIODeregisterBuffer(buffer_id_);   // 4장에서 놓쳤던 해제를 여기서는 항상 수행
            std::print("RIO 버퍼 등록 해제\n");
            buffer_id_ = RIO_INVALID_BUFFERID;
        }
    }

    RIO_BUFFERID GetId() const { return buffer_id_; }
    char* GetData() { return buffer_.data(); }
    const char* GetData() const { return buffer_.data(); }
    size_t GetSize() const { return buffer_.size(); }

    RIO_BUF CreateRIOBuf() const {
        if (buffer_id_ == RIO_INVALID_BUFFERID) {
            throw std::logic_error("등록되지 않은 RIO 버퍼입니다");
        }
        RIO_BUF rio_buf{};
        rio_buf.BufferId = buffer_id_;
        rio_buf.Offset = 0;
        rio_buf.Length = static_cast<ULONG>(buffer_.size());
        return rio_buf;
    }

    RIO_BUF CreateRIOBuf(size_t offset, size_t length) const {
        if (buffer_id_ == RIO_INVALID_BUFFERID) {
            throw std::logic_error("등록되지 않은 RIO 버퍼입니다");
        }
        if (offset > buffer_.size() || length > buffer_.size() - offset) {
            throw std::out_of_range("RIO 버퍼 범위 초과");
        }
        RIO_BUF rio_buf{};
        rio_buf.BufferId = buffer_id_;
        rio_buf.Offset = static_cast<ULONG>(offset);
        rio_buf.Length = static_cast<ULONG>(length);
        return rio_buf;
    }
};

RIO 완료 큐와 요청 큐

RIOCompletionQueue·RIORequestQueue는 5장의 매니저 클래스들을 이동 전용 RAII 형태로 다듬은 버전입니다. RIORequestQueue는 이제 Send()/ Receive() 메서드까지 내장해, 호출하는 쪽이 RIO_BUF를 직접 채우지 않고도 바로 송수신을 요청할 수 있습니다. 

class RIOCompletionQueue {
private:
    RIO_CQ completion_queue_ = RIO_INVALID_CQ;
    const RIO_EXTENSION_FUNCTION_TABLE* functions_ = nullptr;
    HANDLE notification_event_ = NULL;
    bool using_event_notification_ = false;

public:
    RIOCompletionQueue() = default;

    RIOCompletionQueue(const RIO_EXTENSION_FUNCTION_TABLE& functions,
                      DWORD queue_size, bool use_event_notification = false)
        : functions_(&functions), using_event_notification_(use_event_notification) {
        auto result = Create(queue_size);
        if (!result) throw std::runtime_error(result.error());
    }

    ~RIOCompletionQueue() { Close(); }

    RIOCompletionQueue(RIOCompletionQueue&& other) noexcept
        : completion_queue_(other.completion_queue_), functions_(other.functions_),
          notification_event_(other.notification_event_),
          using_event_notification_(other.using_event_notification_) {
        other.completion_queue_ = RIO_INVALID_CQ;
        other.functions_ = nullptr;
        other.notification_event_ = NULL;
    }
    RIOCompletionQueue& operator=(RIOCompletionQueue&& other) noexcept {
        if (this != &other) {
            Close();
            completion_queue_ = other.completion_queue_;
            functions_ = other.functions_;
            notification_event_ = other.notification_event_;
            using_event_notification_ = other.using_event_notification_;
            other.completion_queue_ = RIO_INVALID_CQ;
            other.functions_ = nullptr;
            other.notification_event_ = NULL;
        }
        return *this;
    }

    RIOCompletionQueue(const RIOCompletionQueue&) = delete;
    RIOCompletionQueue& operator=(const RIOCompletionQueue&) = delete;

    std::expected<void, std::string> Create(DWORD queue_size) {
        if (!functions_) return std::unexpected("RIO 함수 테이블이 초기화되지 않았습니다");
        if (queue_size == 0 || queue_size > RIO_MAX_CQ_SIZE) {
            return std::unexpected("완료 큐 크기가 RIO 허용 범위를 벗어났습니다");
        }
        Close();

        if (using_event_notification_) {
            notification_event_ = CreateEvent(NULL, FALSE, FALSE, NULL);
            if (notification_event_ == NULL) {
                return std::unexpected(std::format("이벤트 생성 실패: {}", GetLastError()));
            }
            RIO_NOTIFICATION_COMPLETION notification{};
            notification.Type = RIO_EVENT_COMPLETION;
            notification.Event.EventHandle = notification_event_;
            notification.Event.NotifyReset = TRUE;
            completion_queue_ = functions_->RIOCreateCompletionQueue(queue_size, &notification);
        } else {
            completion_queue_ = functions_->RIOCreateCompletionQueue(queue_size, NULL);
        }

        if (completion_queue_ == RIO_INVALID_CQ) {
            if (notification_event_ != NULL) {
                CloseHandle(notification_event_);
                notification_event_ = NULL;
            }
            return std::unexpected(std::format("RIO 완료 큐 생성 실패: {}", WSAGetLastError()));
        }

        std::print("RIO 완료 큐 생성 성공 - 크기: {}, 알림 방식: {}\n",
                   queue_size, using_event_notification_ ? "이벤트" : "폴링");
        return {};
    }

    void Close() {
        if (completion_queue_ != RIO_INVALID_CQ && functions_) {
            // 이 호출 전에 이 CQ를 쓰는 요청 큐를 멈추고 모든 완료를 회수해야 한다.
            functions_->RIOCloseCompletionQueue(completion_queue_);
            std::print("RIO 완료 큐 닫힘\n");
            completion_queue_ = RIO_INVALID_CQ;
        }
        if (notification_event_ != NULL) {
            CloseHandle(notification_event_);
            notification_event_ = NULL;
        }
    }

    bool RequestNotification() {
        if (!using_event_notification_ || completion_queue_ == RIO_INVALID_CQ || !functions_) return false;
        return functions_->RIONotify(completion_queue_) == ERROR_SUCCESS;
    }

    std::expected<ULONG, std::string> DequeueCompletions(RIORESULT* results, ULONG result_count) {
        if (completion_queue_ == RIO_INVALID_CQ || !functions_) {
            return std::unexpected("완료 큐가 유효하지 않거나 함수 테이블이 초기화되지 않았습니다");
        }
        ULONG num_results = functions_->RIODequeueCompletion(completion_queue_, results, result_count);
        if (num_results == RIO_CORRUPT_CQ) {
            return std::unexpected(std::format("완료 큐 손상됨: {}", WSAGetLastError()));
        }
        return num_results;
    }

    RIO_CQ Get() const { return completion_queue_; }
    HANDLE GetNotificationEvent() const { return notification_event_; }
    bool IsUsingEventNotification() const { return using_event_notification_; }
    bool IsValid() const { return completion_queue_ != RIO_INVALID_CQ; }
};

class RIORequestQueue {
private:
    RIO_RQ request_queue_ = RIO_INVALID_RQ;
    const RIO_EXTENSION_FUNCTION_TABLE* functions_ = nullptr;
    SOCKET socket_ = INVALID_SOCKET;

public:
    RIORequestQueue() = default;

    RIORequestQueue(const RIO_EXTENSION_FUNCTION_TABLE& functions,
                   SOCKET socket, DWORD max_pending_recvs, DWORD max_pending_sends,
                   RIO_CQ completion_queue)
        : functions_(&functions), socket_(socket) {
        auto result = Create(max_pending_recvs, max_pending_sends, completion_queue, completion_queue);
        if (!result) throw std::runtime_error(result.error());
    }

    ~RIORequestQueue() { request_queue_ = RIO_INVALID_RQ; }   // 3장에서 확인했듯 별도 해제 함수가 없음

    RIORequestQueue(RIORequestQueue&& other) noexcept
        : request_queue_(other.request_queue_), functions_(other.functions_), socket_(other.socket_) {
        other.request_queue_ = RIO_INVALID_RQ;
        other.functions_ = nullptr;
        other.socket_ = INVALID_SOCKET;
    }
    RIORequestQueue& operator=(RIORequestQueue&& other) noexcept {
        if (this != &other) {
            request_queue_ = other.request_queue_;
            functions_ = other.functions_;
            socket_ = other.socket_;
            other.request_queue_ = RIO_INVALID_RQ;
            other.functions_ = nullptr;
            other.socket_ = INVALID_SOCKET;
        }
        return *this;
    }

    RIORequestQueue(const RIORequestQueue&) = delete;
    RIORequestQueue& operator=(const RIORequestQueue&) = delete;

    std::expected<void, std::string> Create(DWORD max_pending_recvs, DWORD max_pending_sends,
                                              RIO_CQ recv_cq, RIO_CQ send_cq) {
        if (!functions_ || socket_ == INVALID_SOCKET) {
            return std::unexpected("RIO 함수 테이블이 초기화되지 않았거나 소켓이 유효하지 않습니다");
        }
        if (request_queue_ != RIO_INVALID_RQ) {
            return std::unexpected("요청 큐는 소켓마다 한 번만 생성할 수 있습니다");
        }
        if (max_pending_recvs == 0 || max_pending_sends == 0 ||
            recv_cq == RIO_INVALID_CQ || send_cq == RIO_INVALID_CQ) {
            return std::unexpected("요청 큐 생성 인자가 유효하지 않습니다");
        }

        request_queue_ = functions_->RIOCreateRequestQueue(
            socket_, max_pending_recvs, 1, max_pending_sends, 1, recv_cq, send_cq, NULL
        );
        if (request_queue_ == RIO_INVALID_RQ) {
            return std::unexpected(std::format("RIO 요청 큐 생성 실패: {}", WSAGetLastError()));
        }
        std::print("RIO 요청 큐 생성 성공 - 최대 수신: {}, 최대 송신: {}\n", max_pending_recvs, max_pending_sends);
        return {};
    }

    std::expected<void, std::string> Send(RIO_BUF buffer, void* context = nullptr) {
        if (request_queue_ == RIO_INVALID_RQ || !functions_) {
            return std::unexpected("요청 큐가 유효하지 않거나 함수 테이블이 초기화되지 않았습니다");
        }
        if (!functions_->RIOSend(request_queue_, &buffer, 1, 0, context)) {
            return std::unexpected(std::format("데이터 전송 실패: {}", WSAGetLastError()));
        }
        return {};
    }

    std::expected<void, std::string> Receive(RIO_BUF buffer, void* context = nullptr) {
        if (request_queue_ == RIO_INVALID_RQ || !functions_) {
            return std::unexpected("요청 큐가 유효하지 않거나 함수 테이블이 초기화되지 않았습니다");
        }
        if (!functions_->RIOReceive(request_queue_, &buffer, 1, 0, context)) {
            return std::unexpected(std::format("데이터 수신 실패: {}", WSAGetLastError()));
        }
        return {};
    }

    RIO_RQ Get() const { return request_queue_; }
    bool IsValid() const { return request_queue_ != RIO_INVALID_RQ; }
};

6.2 템플릿을 활용한 유연한 버퍼 관리

지금까지의 버퍼는 항상 char 배열이었습니다 — 게임 패킷 구조체를 직접 담을 수 있게 확장합니다.

"바이트로 다룰 수 있는 타입"을 concept으로 제약하기

RIORegisterBuffer()는 결국 메모리를 바이트 단위로 다룹니다. 아무 타입이나 이 방식으로 다뤄도 안전한 것은 아닙니다 — 예를 들어 std::string이나 가상 함수가 있는 클래스는 내부에 포인터를 가지고 있어, 그 메모리를 통째로 네트워크로 복사하면 의미가 깨집니다. C++20의 concept을 사용하면 "이런 성질을 가진 타입만 허용한다"는 제약을 컴파일 타임에 걸 수 있습니다. 

// 바이트로 다룰 수 있는 데이터 타입 개념 정의
template<typename T>
concept ByteData = std::is_trivially_copyable_v<T>;

std::is_trivially_copyable_v<T>는 "이 타입의 객체 표현을 memcpy로 복사해도 생성자·소멸자·가상 함수 테이블 등이 깨지지 않는가"를 검사합니다. 순수하게 값만 담은 구조체 (POD에 가까운 타입)는 통과하고, std::string이나 std::vector를 멤버로 가진 타입은 통과하지 못합니다. 다만 원시 포인터를 가진 구조체는 통과할 수 있으므로, 이를 다른 프로세스나 다른 버전에 그대로 전송 가능한 패킷이라고 보장하지는 않습니다. 이 조건을 ByteData라는 이름의 concept으로 정의해두면, 아래처럼 템플릿 매개변수에 제약을 걸어 잘못된 타입을 쓰면 실행이 아니라 컴파일 시점에 바로 오류가 나게 만들 수 있습니다.

템플릿화된 RIO 버퍼 클래스

template<ByteData T>
class RIOTypedBuffer {
private:
    std::vector<T> elements_;
    RIO_BUFFERID buffer_id_ = RIO_INVALID_BUFFERID;
    const RIO_EXTENSION_FUNCTION_TABLE* functions_ = nullptr;

public:
    RIOTypedBuffer() = default;

    RIOTypedBuffer(const RIO_EXTENSION_FUNCTION_TABLE& functions, size_t element_count)
        : elements_(element_count), functions_(&functions) {
        if (element_count == 0 || element_count > (std::numeric_limits<DWORD>::max)() / sizeof(T)) {
            throw std::invalid_argument("RIO 형식 버퍼 크기가 DWORD 범위를 벗어났습니다");
        }
    }

    ~RIOTypedBuffer() { Deregister(); }

    RIOTypedBuffer(RIOTypedBuffer&&) = delete;
    RIOTypedBuffer& operator=(RIOTypedBuffer&&) = delete;

    RIOTypedBuffer(const RIOTypedBuffer&) = delete;
    RIOTypedBuffer& operator=(const RIOTypedBuffer&) = delete;

    std::expected<void, std::string> Register() {
        if (buffer_id_ != RIO_INVALID_BUFFERID) return {};
        if (!functions_ || elements_.empty()) return std::unexpected("형식 버퍼가 초기화되지 않았습니다");
        buffer_id_ = functions_->RIORegisterBuffer(
            reinterpret_cast<char*>(elements_.data()), static_cast<DWORD>(GetByteSize()));
        if (buffer_id_ == RIO_INVALID_BUFFERID) {
            return std::unexpected(std::format("RIO 형식 버퍼 등록 실패: {}", WSAGetLastError()));
        }
        return {};
    }

    void Deregister() {
        if (buffer_id_ != RIO_INVALID_BUFFERID && functions_) {
            functions_->RIODeregisterBuffer(buffer_id_);
            buffer_id_ = RIO_INVALID_BUFFERID;
        }
    }

    T* GetData() { return elements_.data(); }
    const T* GetData() const { return elements_.data(); }
    size_t GetElementCount() const { return elements_.size(); }
    size_t GetByteSize() const { return elements_.size() * sizeof(T); }
    RIO_BUFFERID GetId() const { return buffer_id_; }

    T& operator[](size_t index) {
        if (index >= elements_.size()) throw std::out_of_range("버퍼 인덱스 범위 초과");
        return GetData()[index];
    }
    const T& operator[](size_t index) const {
        if (index >= elements_.size()) throw std::out_of_range("버퍼 인덱스 범위 초과");
        return GetData()[index];
    }

    RIO_BUF CreateRIOBuf() const { return CreateRIOBuf(0, elements_.size()); }

    RIO_BUF CreateRIOBuf(size_t offset_elements, size_t length_elements) const {
        if (buffer_id_ == RIO_INVALID_BUFFERID || offset_elements > elements_.size() ||
            length_elements > elements_.size() - offset_elements) {
            throw std::out_of_range("버퍼 범위 초과");
        }
        return RIO_BUF{buffer_id_, static_cast<ULONG>(offset_elements * sizeof(T)),
                       static_cast<ULONG>(length_elements * sizeof(T))};
    }
};

// 게임 패킷 예시 — 고정 크기, 포인터 없음 → ByteData 조건을 만족
struct GamePacket {
    uint32_t packet_id;

    float position_x;
    float position_y;

이제 char 버퍼가 아니라 구조체 배열입니다

RIOTypedBuffer<GamePacket>는 std::vector<GamePacket>으로 정렬된 객체 배열을 만들고 그 저장 공간을 등록합니다. 따라서 바깥에서는 packet_buffer[0].position_x처럼 구조체 필드에 직접 접근할 수 있습니다. 4장까지 계속 등장했던 "받은 char*를 원하는 구조체로 캐스팅"하는 작업을 클래스 내부로 감춘 것입니다.

메모리 풀을 이용한 유연한 버퍼 관리

RIOBufferPool은 4장의 RIOBufferRing과 비슷하게 고정 개수의 슬롯을 재사용합니다. 모든 슬롯이 사용 중이면 이미 I/O에 사용 중일 수 있는 메모리를 절대 재사용하지 않고 실패를 반환합니다. 슬롯은 해당 RIO 완료를 처리한 뒤에만 반납해야 합니다. 

template<ByteData T, size_t PoolSize>
class RIOBufferPool {
private:
    struct BufferInfo {
        bool in_use = false;
    };

    RIOTypedBuffer<T> buffer_;
    std::array<BufferInfo, PoolSize> buffer_info_;
    std::mutex mutex_;

public:
    RIOBufferPool(const RIO_EXTENSION_FUNCTION_TABLE& functions)
        : buffer_(functions, PoolSize) {
        static_assert(PoolSize > 0);
        if (auto registered = buffer_.Register(); !registered) {
            throw std::runtime_error(registered.error());
        }
        std::print("RIO 버퍼 풀 생성 - 크기: {} 요소\n", PoolSize);
    }

    std::expected<std::pair<T*, size_t>, std::string> Allocate() {
        std::lock_guard<std::mutex> lock(mutex_);

        for (size_t i = 0; i < PoolSize; ++i) {
            if (!buffer_info_[i].in_use) {
                buffer_info_[i].in_use = true;
                return std::pair(buffer_.GetData() + i, i);
            }
        }

        return std::unexpected("사용 가능한 RIO 버퍼 슬롯이 없습니다");
    }

    std::expected<void, std::string> Release(size_t index) {
        if (index >= PoolSize) return std::unexpected("버퍼 풀 인덱스 범위 초과");
        std::lock_guard<std::mutex> lock(mutex_);
        if (!buffer_info_[index].in_use) return std::unexpected("이미 반납된 버퍼 슬롯입니다");
        buffer_info_[index].in_use = false;
        return {};
    }

    RIO_BUF CreateRIOBuf(size_t index) {
        if (index >= PoolSize) throw std::out_of_range("버퍼 풀 인덱스 범위 초과");
        return buffer_.CreateRIOBuf(index, 1);
    }

    RIO_BUFFERID GetBufferId() const { return buffer_.GetId(); }
    size_t GetPoolSize() const { return PoolSize; }
};

완료 전에는 절대 재사용하지 않는다

RIOSend()나 RIOReceive()가 성공해도 I/O는 아직 진행 중이다. 따라서 해당 슬롯은 연결이 끊기거나 오류가 나도 그 요청의 완료를 회수하기 전에는 반납할 수 없다. 풀이 가득 찼을 때 Allocate()가 실패하는 것은 데이터 손상을 막는 의도된 backpressure다. 완료 콜백에서 요청 컨텍스트를 통해 정확한 슬롯을 확인한 뒤 Release()한다.

6.3 std::span을 이용한 버퍼 뷰

등록된 버퍼 전체가 아니라, 그 일부를 가리키는 가벼운 "뷰"를 만듭니다.

1장에서 소개했던 std::span을 이번에는 RIO 버퍼 전용으로 응용합니다. RIOBufferView는 (버퍼 ID, 오프셋, 길이) 세 값만 들고 있는 아주 가벼운 클래스로, 등록된 버퍼의 소유권은 전혀 갖지 않습니다 — 그저 "그 버퍼의 이 구간을 이렇게 쓰겠다"는 좌표만 표현합니다. 

class RIOBufferView {
private:
    RIO_BUFFERID buffer_id_;
    ULONG offset_;
    ULONG length_;

public:
    RIOBufferView(RIO_BUFFERID buffer_id, ULONG offset, ULONG length)
        : buffer_id_(buffer_id), offset_(offset), length_(length) {}

    explicit RIOBufferView(const RIOBuffer& buffer)
        : buffer_id_(buffer.GetId()), offset_(0), length_(static_cast<ULONG>(buffer.GetSize())) {
        if (buffer_id_ == RIO_INVALID_BUFFERID) throw std::logic_error("등록되지 않은 RIO 버퍼입니다");
    }

    RIOBufferView(const RIOBuffer& buffer, ULONG offset, ULONG length)
        : buffer_id_(buffer.GetId()), offset_(offset), length_(length) {
        if (buffer_id_ == RIO_INVALID_BUFFERID || offset > buffer.GetSize() ||
            length > buffer.GetSize() - offset) {
            throw std::out_of_range("RIO 버퍼 뷰 범위 초과");
        }
    }

    RIO_BUF CreateRIOBuf() const {
        RIO_BUF rio_buf{};
        rio_buf.BufferId = buffer_id_;
        rio_buf.Offset = offset_;
        rio_buf.Length = length_;
        return rio_buf;
    }

    RIO_BUFFERID GetBufferId() const { return buffer_id_; }
    ULONG GetOffset() const { return offset_; }
    ULONG GetLength() const { return length_; }

    // 뷰의 부분 구간을 다시 뷰로 — 슬라이싱
    RIOBufferView Slice(ULONG slice_offset, ULONG slice_length) const {
        if (slice_offset > length_ || slice_length > length_ - slice_offset) {
            throw std::out_of_range("버퍼 뷰 슬라이스 범위 초과");
        }
        return RIOBufferView(buffer_id_, offset_ + slice_offset, slice_length);
    }
};

Slice()가 이 클래스의 핵심입니다. "전체 버퍼의 뷰"에서 "그중 앞부분 128바이트만 가리키는 뷰"를 만들 때, 실제 메모리를 복사하지도, 새 버퍼를 등록하지도 않습니다 — 그저 오프셋과 길이를 다시 계산한 새 RIOBufferView 값을 반환할 뿐입니다.

std::span과 함께 사용하기

원시 RIOBuffer는 바이트 단위로만 뷰를 만듭니다. 임의의 T로 캐스팅하면 정렬과 객체 수명 규칙을 깨뜨릴 수 있기 때문입니다. 구조체 배열이 필요하면 앞 절의 RIOTypedBuffer<T>를 사용합니다. 

std::expected<void, std::string> SendView(
    RIORequestQueue& request_queue, const RIOBufferView& view, void* context = nullptr) {
    // view는 실제 등록 버퍼의 좌표다. 임의의 span 주소를 RIO에 전달할 수는 없다.
    return request_queue.Send(view.CreateRIOBuf(), context);
}

std::span<std::byte> CreateBufferSpan(RIOBuffer& buffer, size_t offset = 0, size_t count = 0) {
    if (offset > buffer.GetSize()) throw std::out_of_range("버퍼 span 오프셋 범위 초과");
    size_t available = buffer.GetSize() - offset;
    size_t actual_count = (count == 0) ? available : count;
    if (actual_count > available) throw std::out_of_range("버퍼 span 길이 범위 초과");
    return {reinterpret_cast<std::byte*>(buffer.GetData() + offset), actual_count};
}

void SpanExample(RIORequestQueue& request_queue, RIOBuffer& buffer) {
    auto bytes = CreateBufferSpan(buffer, 0, sizeof(GamePacket));
    std::memset(bytes.data(), 0, bytes.size());        // 등록 버퍼 안에 데이터를 채운다
    RIOBufferView packet_view(buffer, 0, static_cast<ULONG>(bytes.size()));
    auto sent = SendView(request_queue, packet_view);
    if (!sent) throw std::runtime_error(sent.error());

    std::print("std::span을 이용한 버퍼 관리 및 전송 예시 완료\n");
}

RIOBufferView와 std::span, 언제 무엇을 쓸까

std::span은 등록 버퍼 안에 있는 바이트 범위를 안전하게 가리킬 때 쓰고, RIOBufferView는 RIO에 전달할 (버퍼 ID, 오프셋, 길이) 좌표 그 자체를 값으로 들고 다니거나 Slice()로 잘라 재사용할 때 씁니다. 실전에서는 보통 std::span으로 데이터를 채운 뒤, 마지막에 RIOBufferView로 같은 범위를 지정해 전송을 요청하는 흐름을 씁니다. 어느 경우든 완료를 회수할 때까지 원본 버퍼와 뷰의 소유 버퍼를 파괴하거나 덮어쓰면 안 됩니다.

6.4 C++23 기능 활용

지금까지 흩어져 있던 오류 처리·로깅 방식을 통일합니다.

std::expected를 활용한 오류 처리

지금까지 오류는 대부분 std::string으로만 표현했습니다. 어떤 종류의 오류인지 (타임아웃인지, 큐 손상인지, 잘못된 인자인지) 코드로 분기하려면 문자열을 파싱해야 했는데, 이는 취약하고 느립니다. RIOErrorCode는 오류의 "종류"를, RIOError는 그 종류에 사람이 읽을 메시지와 시스템 오류 코드를 더한 값을 표현합니다. 

enum class RIOErrorCode {
    Success,
    WSAInitFailed,
    SocketCreationFailed,
    BufferRegistrationFailed,
    CompletionQueueCreationFailed,
    RequestQueueCreationFailed,
    SendFailed,
    ReceiveFailed,
    Timeout,
    Cancelled,
    QueueCorrupted,
    InvalidParameter,
    SystemError
};

struct RIOError {
    RIOErrorCode code;
    std::string message;
    int system_error_code = 0;

    std::string ToString() const {
        if (system_error_code != 0) {
            return std::format("RIO 오류 [{}]: {} (시스템 오류 코드: {})",
                              static_cast<int>(code), message, system_error_code);
        }
        return std::format("RIO 오류 [{}]: {}", static_cast<int>(code), message);
    }
};

RIOResultProcessor는 완료 큐에서 결과를 꺼내오는 방식 세 가지 — 즉시 한 번만 조회, 이벤트로 대기했다가 조회, 콜백으로 결과 전달 — 를 정적 메서드로 제공합니다. 5장의 여러 프로세서 클래스가 하던 일을 함수 호출 하나로 압축한 것입니다. 

class RIOResultProcessor {
public:
    using ResultCallback = std::function<void(const RIORESULT&)>;

    static std::expected<std::vector<RIORESULT>, RIOError> ProcessCompletions(
        RIOCompletionQueue& completion_queue, ULONG max_results = 32) {

        if (max_results == 0) {
            return std::unexpected(RIOError{RIOErrorCode::InvalidParameter, "완료 결과 개수는 1 이상이어야 합니다"});
        }

        std::vector<RIORESULT> results(max_results);
        auto dequeue_result = completion_queue.DequeueCompletions(results.data(), max_results);
        if (!dequeue_result) {
            return std::unexpected(RIOError{RIOErrorCode::QueueCorrupted, dequeue_result.error(), WSAGetLastError()});
        }

        ULONG num_results = *dequeue_result;
        results.resize(num_results);
        return results;
    }

    static std::expected<std::vector<RIORESULT>, RIOError> WaitForCompletions(
        RIOCompletionQueue& completion_queue, DWORD timeout_ms = INFINITE, ULONG max_results = 32) {

        if (!completion_queue.IsUsingEventNotification()) {
            return std::unexpected(RIOError{RIOErrorCode::InvalidParameter, "완료 큐가 이벤트 알림을 사용하도록 구성되지 않았습니다"});
        }
        if (!completion_queue.RequestNotification()) {
            return std::unexpected(RIOError{RIOErrorCode::SystemError, "알림 요청 실패", WSAGetLastError()});
        }

        DWORD wait_result = WaitForSingleObject(completion_queue.GetNotificationEvent(), timeout_ms);
        if (wait_result == WAIT_TIMEOUT) {
            // 이 시점에는 RIONotify가 아직 걸려 있다. 같은 CQ에 다시 RIONotify를 호출하지 말고
            // 기존 이벤트를 계속 기다리거나, 알림 상태를 별도로 추적해야 한다.
            return std::unexpected(RIOError{RIOErrorCode::Timeout, "완료 대기 타임아웃(알림은 계속 대기 중)"});
        } else if (wait_result != WAIT_OBJECT_0) {
            return std::unexpected(RIOError{RIOErrorCode::SystemError, "이벤트 대기 실패", static_cast<int>(GetLastError())});
        }

        return ProcessCompletions(completion_queue, max_results);
    }

    static std::expected<void, RIOError> ProcessWithCallback(
        RIOCompletionQueue& completion_queue, const ResultCallback& callback, ULONG max_results = 32) {

        auto results = ProcessCompletions(completion_queue, max_results);
        if (!results) return std::unexpected(results.error());

        for (const auto& result : *results) callback(result);
        return {};
    }
};

print 및 format 라이브러리 활용

RIOLogger는 로그 레벨별로 Debug()/Info()/Warning()/ Error()/Fatal() 메서드를 제공합니다. 각 메서드는 가변 인자 템플릿(Args&&... args)으로 std::format()과 똑같은 방식의 형식 문자열을 받습니다. 

class RIOLogger {
public:
    enum class LogLevel { Debug, Info, Warning, Error, Fatal };

private:
    std::atomic<LogLevel> current_level_{LogLevel::Info};
    std::mutex log_mutex_;

public:
    void SetLogLevel(LogLevel level) { current_level_.store(level, std::memory_order_relaxed); }
    LogLevel GetLogLevel() const { return current_level_.load(std::memory_order_relaxed); }

    template<typename... Args>
    void Debug(std::format_string<Args...> fmt, Args&&... args) {
        if (GetLogLevel() <= LogLevel::Debug) Log("[디버그]", fmt, std::forward<Args>(args)...);
    }
    template<typename... Args>
    void Info(std::format_string<Args...> fmt, Args&&... args) {
        if (GetLogLevel() <= LogLevel::Info) Log("[정보]", fmt, std::forward<Args>(args)...);
    }
    template<typename... Args>
    void Warning(std::format_string<Args...> fmt, Args&&... args) {
        if (GetLogLevel() <= LogLevel::Warning) Log("[경고]", fmt, std::forward<Args>(args)...);
    }
    template<typename... Args>
    void Error(std::format_string<Args...> fmt, Args&&... args) {
        if (GetLogLevel() <= LogLevel::Error) Log("[오류]", fmt, std::forward<Args>(args)...);
    }
    template<typename... Args>
    void Fatal(std::format_string<Args...> fmt, Args&&... args) {
        if (GetLogLevel() <= LogLevel::Fatal) Log("[심각]", fmt, std::forward<Args>(args)...);
    }

private:
    template<typename... Args>
    void Log(std::string_view prefix, std::format_string<Args...> fmt, Args&&... args) {
        std::lock_guard<std::mutex> lock(log_mutex_);

        auto now = std::chrono::system_clock::now();
        auto now_time_t = std::chrono::system_clock::to_time_t(now);
        std::tm now_tm{};
        localtime_s(&now_tm, &now_time_t);

        std::string time_str = std::format("{:04d}-{:02d}-{:02d} {:02d}:{:02d}:{:02d}",
            now_tm.tm_year + 1900, now_tm.tm_mon + 1, now_tm.tm_mday,
            now_tm.tm_hour, now_tm.tm_min, now_tm.tm_sec);

        std::string message = std::format(fmt, std::forward<Args>(args)...);
        std::print("{} {} {}\n", time_str, prefix, message);
    }
};

std::format_string<Args...>를 매개변수 타입으로 쓰면, 형식 문자열의 {} 개수와 실제 인자 개수가 맞는지를 컴파일 타임에 검사합니다 — 런타임에야 발견되는 printf 스타일 형식 문자열 버그를 원천 차단합니다. 또한 FormatRIOResult()는 result.RequestContext를 포인터로 명시해 포맷팅합니다. RIORESULT::RequestContext의 형식은 PVOID이며, 요청을 넣을 때 전달한 식별자다. 포인터를 컨텍스트로 썼다면 실제 타입으로 되돌리기 전에 그 객체가 완료 처리 때까지 살아 있음을 보장해야 한다.

통합 RIO 관리자 클래스

RIOManager는 Winsock·리스닝 소켓·함수 테이블·공유 완료 큐의 수명을 묶습니다. 리스닝 소켓에는 RIO 요청 큐를 만들지 않습니다. TCP 요청 큐와 송수신 버퍼는 accept한 연결 소켓마다 세션이 소유합니다. Initialize()는 아래 공용 기반만 준비합니다.

그림 6-1. Initialize()는 리스너와 공용 완료 큐를 준비한다. 연결별 요청 큐와 버퍼는 accept 성공 뒤 세션이 만든다

class RIOManager {
private:
    WSAManager wsa_manager_;
    Socket socket_;
    RIOFunctionTable rio_functions_;
    std::unique_ptr<RIOCompletionQueue> completion_queue_;
    mutable std::mutex completion_queue_mutex_;
    std::jthread worker_thread_;
    std::atomic<bool> running_ = false;
    bool initialized_ = false;

public:
    struct Config {
        uint16_t port = 8888;
        DWORD completion_queue_size = 1024;
        DWORD max_outstanding_sends = 1024;
        DWORD max_outstanding_recvs = 1024;
        bool use_event_notification = true;
        std::chrono::milliseconds poll_interval{10};
    };

private:
    Config config_;
    using CompletionCallback = std::function<void(const RIORESULT&)>;
    CompletionCallback completion_callback_;

public:
    explicit RIOManager(Config config = Config{}) : config_(config) {}
    ~RIOManager() { Stop(); }

    // 이 클래스는 이동도, 복사도 되지 않습니다 — 바로 아래에서 그 이유를 설명합니다
    RIOManager(RIOManager&&) = delete;
    RIOManager& operator=(RIOManager&&) = delete;
    RIOManager(const RIOManager&) = delete;
    RIOManager& operator=(const RIOManager&) = delete;

    std::expected<void, std::string> Initialize() {
        if (initialized_) return {};
        if (!wsa_manager_.IsInitialized()) return std::unexpected("WSA 초기화 실패");

        auto socket_result = socket_.Create();
        if (!socket_result) return std::unexpected(socket_result.error());

        auto rio_init_result = rio_functions_.Initialize(socket_.Get());
        if (!rio_init_result) return std::unexpected(rio_init_result.error());

        completion_queue_ = std::make_unique<RIOCompletionQueue>(
            rio_functions_.Get(), config_.completion_queue_size, config_.use_event_notification);

        auto bind_result = socket_.BindAndListen(config_.port);
        if (!bind_result) return std::unexpected(bind_result.error());

        g_logger.Info("RIO 관리자 초기화 완료 - 포트: {}", config_.port);
        initialized_ = true;
        return {};
    }

    void SetCompletionCallback(CompletionCallback callback) { completion_callback_ = std::move(callback); }

    std::expected<void, std::string> Start() {
        if (!initialized_ || !completion_queue_ || !completion_queue_->IsValid()) {
            return std::unexpected("RIO 관리자가 초기화되지 않았습니다");
        }
        if (running_.exchange(true)) return {};
        worker_thread_ = std::jthread([this](std::stop_token stop_token) { this->ProcessCompletions(stop_token); });
        g_logger.Info("RIO 관리자 시작됨");
        return {};
    }

    void Stop() {
        if (!running_.exchange(false)) return;
        if (worker_thread_.joinable()) {
            worker_thread_.request_stop();
            if (completion_queue_ && completion_queue_->IsUsingEventNotification()) {
                if (completion_queue_->GetNotificationEvent() != NULL) {
                    SetEvent(completion_queue_->GetNotificationEvent());
                }
            }
            worker_thread_.join();
        }
        g_logger.Info("RIO 관리자 중지됨");
    }

    std::expected<std::unique_ptr<RIORequestQueue>, std::string> CreateRequestQueue(
        SOCKET connected_socket, DWORD max_pending_recvs, DWORD max_pending_sends) const {
        // 이 CQ를 쓰는 완료 스레드와 RIOCreateRequestQueue 호출을 직렬화한다.
        std::lock_guard<std::mutex> lock(completion_queue_mutex_);
        if (!completion_queue_ || !completion_queue_->IsValid()) {
            return std::unexpected("완료 큐가 초기화되지 않았습니다");
        }
        try {
            return std::make_unique<RIORequestQueue>(
                rio_functions_.Get(), connected_socket, max_pending_recvs, max_pending_sends,
                completion_queue_->Get());
        } catch (const std::exception& e) {
            return std::unexpected(e.what());
        }
    }

    Socket& GetSocket() { return socket_; }
    RIOCompletionQueue* GetCompletionQueue() { return completion_queue_.get(); }
    const RIO_EXTENSION_FUNCTION_TABLE& GetRIOFunctions() const { return rio_functions_.Get(); }

private:
    void ProcessCompletions(std::stop_token stop_token) {
        while (!stop_token.stop_requested() && running_) {
            if (config_.use_event_notification) {
                {   // RIONotify와 RIOCreateRequestQueue가 같은 CQ를 동시에 건드리지 않게 한다.
                    std::lock_guard<std::mutex> lock(completion_queue_mutex_);
                    if (!completion_queue_->RequestNotification()) {
                        g_logger.Error("완료 알림 요청 실패: {}", WSAGetLastError());
                        continue;
                    }
                }
                if (WaitForSingleObject(completion_queue_->GetNotificationEvent(), INFINITE) != WAIT_OBJECT_0) {
                    g_logger.Error("완료 이벤트 대기 실패: {}", GetLastError());
                    continue;
                }
                std::expected<std::vector<RIORESULT>, RIOError> results;
                {
                    std::lock_guard<std::mutex> lock(completion_queue_mutex_);
                    results = RIOResultProcessor::ProcessCompletions(*completion_queue_);
                }
                if (!results) {
                    g_logger.Error("완료 처리 실패: {}", results.error().ToString());
                    continue;
                }
                for (const auto& result : *results) {
                    if (completion_callback_) completion_callback_(result);
                }
            } else {
                std::expected<std::vector<RIORESULT>, RIOError> results;
                {
                    std::lock_guard<std::mutex> lock(completion_queue_mutex_);
                    results = RIOResultProcessor::ProcessCompletions(*completion_queue_);
                }
                if (!results) {
                    g_logger.Error("완료 처리 실패: {}", results.error().ToString());
                    continue;
                }
                for (const auto& result : *results) {
                    if (completion_callback_) completion_callback_(result);
                }
                if (results->empty()) std::this_thread::sleep_for(config_.poll_interval);
            }
        }
    }
};

중요 — std::atomic 멤버가 있으면 클래스는 이동조차 되지 않습니다

RIOManager에는 std::atomic<bool> running_이 있습니다. std::atomic은 복사 생성자와 이동 생성자가 모두 명시적으로 삭제되어 있는 타입입니다 — 원자적 연산의 정합성을 보장하려면 "값만 슬쩍 복사"하는 방식이 근본적으로 성립하지 않기 때문입니다. 그런데 C++ 규칙상, 멤버 중 하나라도 이동/복사가 불가능하면 그 멤버를 담은 클래스 전체의 이동·복사 생성자도 자동으로 암묵적으로 삭제됩니다. std::jthread 멤버 역시 이동은 되지만 복사는 안 되므로, 이 클래스는 결국 암묵 이동이 삭제된 타입이 됩니다. 실행 중인 워커가 있는 관리자는 자원과 콜백이 이미 자신의 주소를 참조할 수 있으므로, 억지로 이동을 구현하기보다 이동·복사를 명시적으로 금지하는 편이 안전합니다. 필요한 설정값은 RIOManager를 생성하기 전에 준비해 생성자에 전달합니다.

6.5 세션 조립: 에코 서버의 안전 조건

완결된 에코 루프는 다음 장에서 구현한다. 여기서는 잘못된 공유 구조를 피하는 세션의 소유 관계를 확정한다.

RIO는 연결 소켓마다 요청 큐 하나를 만들어야 한다. 리스닝 소켓의 요청 큐를 클라이언트가 공유하거나, 전송 완료 전에 같은 버퍼 조각에 다음 수신 데이터를 쓰면 안 된다. 또한 RIO 요청 큐의 기반 소켓은 WSASocket에서 WSA_FLAG_REGISTERED_IO로 만든 소켓이어야 한다. 단순 accept()로 얻은 소켓을 여기서 RIO 소켓으로 간주하면 안 되며, 실전 TCP 수락은 미리 RIO 플래그로 만든 accept 소켓을 사용하는 AcceptEx 흐름이 필요하다. 다음 세션은 각 연결의 소켓·요청 큐·송수신 버퍼를 한 묶음으로 소유한다.

1) accept 뒤 세션을 만들기

struct ClientSession;

struct OperationContext {
    enum class Type { Receive, Send };
    ClientSession* session = nullptr;
    Type type;
    size_t buffer_slot;
};

struct ClientSession {
    Socket socket;                              // accept한 연결 소켓의 유일한 소유자
    std::unique_ptr<RIORequestQueue> request_queue;
    RIOBuffer recv_buffer;
    RIOBuffer send_buffer;
    OperationContext receive{this, OperationContext::Type::Receive, 0};
    OperationContext send{this, OperationContext::Type::Send, 0};
    size_t outstanding_operations = 0;
    bool closing = false;

    ClientSession(const RIO_EXTENSION_FUNCTION_TABLE& functions, SOCKET accepted_socket,
                  std::unique_ptr<RIORequestQueue> queue, size_t buffer_size)
        : socket(accepted_socket), request_queue(std::move(queue)),
          recv_buffer(functions, buffer_size), send_buffer(functions, buffer_size) {
        if (auto r = recv_buffer.Register(); !r) throw std::runtime_error(r.error());
        if (auto r = send_buffer.Register(); !r) throw std::runtime_error(r.error());
    }

    ClientSession(const ClientSession&) = delete;
    ClientSession& operator=(const ClientSession&) = delete;
    ClientSession(ClientSession&&) = delete;            // OperationContext가 this를 가리킨다
    ClientSession& operator=(ClientSession&&) = delete;
};

std::expected<std::unique_ptr<ClientSession>, std::string> MakeSession(
    RIOManager& manager, SOCKET accepted_rio_socket, size_t buffer_size = 4096) {
    auto queue = manager.CreateRequestQueue(accepted_rio_socket, 1, 1);
    if (!queue) {
        closesocket(accepted_rio_socket);       // 이 함수는 전달받은 소켓 소유권을 항상 소비한다
        return std::unexpected(queue.error());
    }
    try {
        return std::make_unique<ClientSession>(
            manager.GetRIOFunctions(), accepted_rio_socket, std::move(*queue), buffer_size);
    } catch (const std::exception& e) {
        closesocket(accepted_rio_socket);       // 아직 Socket 소유권을 넘기기 전의 실패 경로
        return std::unexpected(e.what());
    }
}

세션보다 오래 살아야 하는 것

RIOManager의 함수 테이블과 완료 큐는 모든 ClientSession보다 오래 살아야 한다. 요청 큐는 별도 close 함수가 없고 기반 소켓을 닫을 때 함께 해제된다. 따라서 종료는 새 요청 중단 → 완료 drain → 세션 파괴(버퍼 등록 해제·소켓 close) → 완료 큐 파괴 순서로 진행한다.

MakeSession()의 소유권 이전

MakeSession()는 요청 큐를 먼저 만들고, 성공했을 때만 그 큐와 accept한 소켓의 소유권을 ClientSession으로 옮긴다. RIO 요청 큐의 기반 소켓은 세션보다 먼저 닫히면 안 되며, 세션 버퍼도 모든 요청 완료를 회수한 뒤에만 등록 해제할 수 있다.

2) 종료 순서

// 서버 종료 시에는 accept를 깨운 뒤 accept 스레드를 join하고,
// 각 세션의 새 I/O 제출을 막은 다음 모든 완료를 회수한다.
// outstanding_operations가 0인 세션만 컨테이너에서 제거할 수 있다.
bool CanDestroy(const ClientSession& session) {
    return session.closing && session.outstanding_operations == 0;
}

3) 연결 수락과 수신 예약

AcceptEx가 완료된 RIO 소켓을 MakeSession()에 넘기면 세션별 요청 큐와 독립 버퍼가 만들어진다. 아래 함수는 종료 중이 아닐 때 수신 하나를 예약한다. 

std::expected<void, std::string> PostReceive(ClientSession& session) {
    if (session.closing) return std::unexpected("종료 중인 세션에는 수신을 예약할 수 없습니다");
    auto result = session.request_queue->Receive(
        session.recv_buffer.CreateRIOBuf(), &session.receive);
    if (!result) return std::unexpected(result.error());
    ++session.outstanding_operations;
    return {};
}

4) 완료 처리 — 전송 완료 뒤에만 다음 수신을 예약하기

std::expected<void, std::string> HandleCompletion(const RIORESULT& result) {
    auto* operation = static_cast<OperationContext*>(result.RequestContext);
    if (!operation || !operation->session) return std::unexpected("유효하지 않은 요청 컨텍스트");
    ClientSession& session = *operation->session;
    if (session.outstanding_operations == 0) return std::unexpected("완료 수 카운터 불일치");
    --session.outstanding_operations;

    if (result.Status != NO_ERROR || result.BytesTransferred == 0) {
        session.closing = true;                 // 즉시 파괴하지 말고 남은 완료를 기다린다
        return {};
    }
    if (operation->type == OperationContext::Type::Receive) {
        std::memcpy(session.send_buffer.GetData(), session.recv_buffer.GetData(), result.BytesTransferred);
        auto sent = session.request_queue->Send(
            session.send_buffer.CreateRIOBuf(0, result.BytesTransferred), &session.send);
        if (!sent) { session.closing = true; return std::unexpected(sent.error()); }
        ++session.outstanding_operations;
        return {};
    }
    auto next_receive = PostReceive(session);   // 송신 버퍼를 다시 쓰기 안전한 시점
    if (!next_receive) session.closing = true;
    return next_receive;
}

요청별 컨텍스트와 세션 수명

RequestContext에는 세션 포인터만이 아니라 수신/송신 종류를 포함한 OperationContext의 주소를 넣는다. 그래야 완료 처리에서 다음 상태 전이를 정확히 선택할 수 있다. 더 중요한 규칙은 완료 콜백 안에서 세션을 즉시 삭제하지 않는 것이다. 남은 요청이 그 세션과 컨텍스트를 계속 가리킬 수 있으므로, CanDestroy()가 참일 때만 세션 소유 컨테이너에서 제거한다.

5) 다음 장에서 완성할 부분

이 절은 안전한 세션 조립과 완료 상태 전이만 다룬다. accept 루프, 세션 컨테이너의 동기화, 오류·취소 완료의 drain, graceful shutdown을 하나의 실행 가능한 서버로 묶는 작업은 7장에서 다룬다. 따라서 이 장의 코드만 빌드해 텔넷 에코 서버가 완성된다고 주장하면 안 된다.

생성자 예외와 std::expected의 경계

이 장의 생성자는 부분 생성 상태를 남기지 않기 위해 실패 시 std::runtime_error를 던지고, I/O 제출처럼 정상 제어 흐름에서 실패할 수 있는 작업은 std::expected로 돌려준다. 실제 프로그램의 최상위 경계에서는 두 방식을 모두 처리해야 한다.

6.6 요약

  1. 이동 전용 RAII — 소켓·버퍼·완료 큐·요청 큐를 "복사 금지, 이동만 허용" 패턴으로 감싸, 핸들 이중 해제를 원천 차단했습니다.
  2. concept으로 제약된 템플릿 — ByteData concept으로 안전하게 바이트로 다룰 수 있는 타입만 버퍼에 담을 수 있게 했습니다.
  3. 버퍼 풀의 수명 규칙 — 용량 초과 시 실패를 반환하고, 요청 완료를 회수한 뒤에만 슬롯을 반납해야 함을 확인했습니다.
  4. std::span 기반 뷰 — 원시 등록 버퍼는 바이트 span으로 다루고, RIO에는 정확한 버퍼 좌표를 가진 view만 전달해야 함을 확인했습니다.
  5. std::expected·std::print — 오류를 종류별로 구분하고, 형식 문자열을 컴파일 타임에 검증하는 로깅 체계를 갖췄습니다.
  6. 세션별 RIO 소유권 — 리스너가 아닌 연결 소켓마다 요청 큐와 버퍼를 두고, 모든 완료를 회수한 뒤 세션을 파괴해야 함을 확인했습니다.
