# 5장. 등급제 가챠 구현 — 2단계 추첨

3장에서 본 등급(Tier) → 아이템의 2단계 구조를 코드로 만든다. 이 패턴은 거의 모든 수집형 RPG가 쓰고 있어서, 한 번 잘 만들어두면 두고두고 재사용할 수 있다.

---

## 5.1 1단계: 등급을 먼저 뽑는다 (SSR/SR/R)

### 데이터 모델

```csharp
public enum Tier
{
    SSR = 1,
    SR  = 2,
    R   = 3,
}

public sealed record TierProbability(Tier Tier, double Probability);

public sealed record GachaItem(
    long ItemId,
    string Code,
    Tier Tier,
    double WeightInTier,   // 같은 등급 내에서의 가중치
    bool IsPickup);
```

### 등급 추첨기

```csharp
public sealed class TierPicker
{
    private readonly RouletteWheelPicker<Tier> _picker;

    public TierPicker(IEnumerable<TierProbability> probabilities, IRandomProvider rng)
    {
        var sum = probabilities.Sum(x => x.Probability);
        if (Math.Abs(sum - 1.0) > 1e-6)
            throw new InvalidOperationException(
                $"등급 확률 합은 1.0이어야 하는데 {sum}이다");

        _picker = new RouletteWheelPicker<Tier>(
            probabilities.Select(x => (x.Tier, x.Probability)),
            rng);
    }

    public Tier Pick() => _picker.Pick();
}
```

### 사용 예시

```csharp
var tiers = new[]
{
    new TierProbability(Tier.SSR, 0.007),
    new TierProbability(Tier.SR,  0.18),
    new TierProbability(Tier.R,   0.813),
};
var picker = new TierPicker(tiers, new ThreadSafeRandomProvider());

var tier = picker.Pick();  // SSR / SR / R
```

## 5.2 2단계: 등급 안에서 아이템을 뽑는다

### 등급별 풀

```csharp
public sealed class TieredItemPool
{
    private readonly Dictionary<Tier, CumulativeBinarySearchPicker<GachaItem>> _pickers;

    public TieredItemPool(IEnumerable<GachaItem> items, IRandomProvider rng)
    {
        _pickers = items
            .GroupBy(i => i.Tier)
            .ToDictionary(
                g => g.Key,
                g => new CumulativeBinarySearchPicker<GachaItem>(
                    g.Select(item => (item, item.WeightInTier)),
                    rng));
    }

    public GachaItem Pick(Tier tier)
    {
        if (!_pickers.TryGetValue(tier, out var picker))
            throw new InvalidOperationException($"풀에 {tier} 등급이 없다");
        return picker.Pick();
    }
}
```

### 합쳐서 가챠 추첨기 만들기

```csharp
public sealed class TieredGachaService
{
    private readonly TierPicker _tierPicker;
    private readonly TieredItemPool _itemPool;

    public TieredGachaService(
        IEnumerable<TierProbability> tierProbs,
        IEnumerable<GachaItem> items,
        IRandomProvider rng)
    {
        _tierPicker = new TierPicker(tierProbs, rng);
        _itemPool = new TieredItemPool(items, rng);
    }

    public GachaItem Draw()
    {
        var tier = _tierPicker.Pick();
        return _itemPool.Pick(tier);
    }
}
```

## 5.3 픽업(Pick-up) 캐릭터 확률 처리하기

### 50/50 모델 (원신/스타레일식)

```
[SSR이 떴을 때]
  → 50% 확률로 픽업 캐릭
  → 50% 확률로 일반 SSR 풀에서 추첨
```

### 구현

```csharp
public sealed class PickupSsrPolicy
{
    private readonly GachaItem _pickupItem;
    private readonly TieredItemPool _normalPool;  // 픽업 제외 일반 SSR 풀
    private readonly IRandomProvider _rng;
    private readonly double _pickupRate;  // 0.5 = 50/50

    public PickupSsrPolicy(
        GachaItem pickupItem,
        TieredItemPool normalPool,
        IRandomProvider rng,
        double pickupRate = 0.5)
    {
        _pickupItem = pickupItem;
        _normalPool = normalPool;
        _rng = rng;
        _pickupRate = pickupRate;
    }

    public GachaItem PickSsr()
    {
        return _rng.NextDouble() < _pickupRate
            ? _pickupItem
            : _normalPool.Pick(Tier.SSR);
    }
}
```

### 풀에 직접 픽업 가중치를 박는 방식

```csharp
// SSR 풀 = 픽업(가중치 50) + 야엘(가중치 5) + 메이(가중치 5) + ...
// 결과: 픽업이 더 자주 나옴

// 50/50 시스템과 다른 점:
//   - 가중치 방식: SSR 100번 떠도 픽업이 안 나올 수도 있다 (분산 큼)
//   - 50/50: SSR이 뜨면 정확히 절반은 픽업
```

50/50 시스템이 **유저 체감 만족도**가 더 높다. 분산이 작기 때문이다.

### 등급별 풀과 결합

```csharp
public sealed class GachaWithPickupService
{
    private readonly TierPicker _tierPicker;
    private readonly TieredItemPool _normalPool;
    private readonly PickupSsrPolicy _pickupPolicy;

    public GachaItem Draw()
    {
        var tier = _tierPicker.Pick();
        return tier switch
        {
            Tier.SSR => _pickupPolicy.PickSsr(),
            _        => _normalPool.Pick(tier),
        };
    }
}
```

## 5.4 [실습] 등급제 가챠 클래스 완전 구현

지금까지 만든 조각을 실제로 사용하는 코드를 보자.

### 풀 정의 (DB나 JSON에서 로드한다고 가정)

```csharp
// 배너 정의
var bannerTiers = new[]
{
    new TierProbability(Tier.SSR, 0.007),
    new TierProbability(Tier.SR,  0.18),
    new TierProbability(Tier.R,   0.813),
};

// 픽업 캐릭터
var pickupItem = new GachaItem(
    ItemId: 1001, Code: "PERO", Tier: Tier.SSR, WeightInTier: 0, IsPickup: true);

// 일반 풀 (픽업 제외)
var allItems = new List<GachaItem>
{
    new(2001, "YAEL", Tier.SSR, 1.0, false),
    new(2002, "MAY",  Tier.SSR, 1.0, false),
    new(3001, "AOI",  Tier.SR,  1.0, false),
    new(3002, "BORA", Tier.SR,  3.0, false),  // SR이지만 더 자주 나옴
    new(4001, "DAVE", Tier.R,   1.0, false),
    new(4002, "ED",   Tier.R,   1.0, false),
};

var rng = new ThreadSafeRandomProvider();
var tierPicker = new TierPicker(bannerTiers, rng);
var normalPool = new TieredItemPool(allItems, rng);
var pickupPolicy = new PickupSsrPolicy(pickupItem, normalPool, rng, 0.5);

var service = new GachaWithPickupService(tierPicker, normalPool, pickupPolicy);

// 실행
for (int i = 0; i < 10; i++)
{
    var result = service.Draw();
    Console.WriteLine($"{i+1}회: {result.Tier} {result.Code} (pickup={result.IsPickup})");
}
```

3회: SR BORA (pickup=False)

## 5.5 [함정] 확률 합산이 100%가 안 될 때 생기는 버그

### 사례 1: 0.999998 = 100%로 처리됐다가...

기획자가 엑셀에서 정한 확률을 그대로 받았는데, 합이 0.999998이 되는 경우가 있다.

```csharp
var bad = new[]
{
    new TierProbability(Tier.SSR, 0.007),
    new TierProbability(Tier.SR,  0.18),
    new TierProbability(Tier.R,   0.812998),  // 누군가 잘못 입력
};
// 합: 0.999998

var picker = new TierPicker(bad, rng);
// → InvalidOperationException 던지도록 만들어두면 사고 예방
```

### 사례 2: 하한 처리 누락

```csharp
// ❌ 부동소수점 오차로 마지막에 무한 루프 가능
public T Pick()
{
    var r = _rng.NextDouble() * _total;
    double cum = 0;
    foreach (var (item, w) in _items)
    {
        cum += w;
        if (r < cum) return item;
    }
    throw new Exception("여기 도달하면 안 됨");  // ← 가끔 도달함
}

// ✅ 마지막 아이템 fallback
public T Pick()
{
    var r = _rng.NextDouble() * _total;
    double cum = 0;
    foreach (var (item, w) in _items)
    {
        cum += w;
        if (r < cum) return item;
    }
    return _items[^1].Item;  // 부동소수점 오차 흡수
}
```

`NextDouble()`은 `[0.0, 1.0)`을 반환하지만, 부동소수점 누적합이 정확히 안 떨어진다. **마지막에 fallback을 두는 게 표준**이다.

### 사례 3: 가중치를 확률로 착각

```csharp
// 가중치를 그대로 넣었는데 합이 1을 넘어버림
var weights = new[]
{
    new TierProbability(Tier.SSR, 7),     // 7% 의도였으나
    new TierProbability(Tier.SR,  18),
    new TierProbability(Tier.R,   75),
};
// 합 = 100, 의도는 정규화된 확률이었는데 그대로 들어감
```

이 경우 룰렛 휠은 합으로 정규화하므로 결과는 같지만, **검증 단계에서 합이 1.0인지 체크**하기로 했다면 예외가 터진다.

### 권장: 검증 + 정규화

```csharp
public static TierProbability[] Validate(TierProbability[] tiers, double tolerance = 1e-6)
{
    if (tiers.Any(t => t.Probability <= 0))
        throw new InvalidOperationException("0 이하 확률이 있다");

    var sum = tiers.Sum(t => t.Probability);
    if (Math.Abs(sum - 1.0) > tolerance)
        throw new InvalidOperationException($"등급 확률 합이 1.0이 아니다: {sum}");

    return tiers;
}
```

## 5장 요약

- 등급제 가챠 = 1단계 등급 추첨 + 2단계 풀 내 아이템 추첨이다.
- 픽업은 50/50 시스템으로 구현하면 분산이 작아 유저 만족도가 좋다.
- 확률 합 검증과 마지막 fallback은 반드시 넣는다. 부동소수점 오차로 사고 난다.
- 인터페이스(`IWeightedPicker<T>`)로 추첨 알고리즘을 추상화하면 등급별로 다른 알고리즘 적용도 쉽다.

다음 장에서는 **천장 시스템(Pity System)**을 구현한다. 이게 들어가면 코드가 갑자기 복잡해진다.
