# 13장. 확률 표기와 법규 — 틀리면 소송 나온다

기술적으로 완벽한 가챠도 **공시(disclosure) 표기를 잘못하면 소송**을 받는다. 한국은 2024년 3월부터 확률 공시가 법적 의무다. 일본·중국도 자율규제·법규로 가이드라인이 있다. 이 장에서는 신입 프로그래머가 알아야 할 핵심만 추려서 정리한다.

> 본 장은 법률 자문이 아니다. 정확한 법적 판단은 사내 법무팀이나 외부 변호사와 상의해야 한다. 이 책은 일반적인 기술 가이드의 범위에서만 다룬다.

## 13.1 한국 게임산업법 확률 공시 의무 (2024.3 시행) 핵심 요약

### 법적 근거

- 게임산업진흥에 관한 법률 제33조 (확률 정보 공개 등)
- 시행령 제19조의2 (확률형 아이템 정보 표시 방법 등)
- 2024년 3월 22일 시행

### 공시해야 할 항목 (요약)

```
1. 가챠 종류와 명칭
2. 등장 가능한 모든 아이템 목록
3. 아이템별 확률 (백분율, 소수점 포함 가능)
4. 천장 시스템이 있다면 그 조건과 보장 내용
5. 컬렉션·세트 효과 등 부가 보상 조건
```

### 어디에 표시해야 하나

- **게임 내**: 가챠 화면에 1차 표시 또는 즉시 접근 가능한 위치
- **공식 홈페이지**: 별도의 확률 공시 페이지
- **광고/홍보**: 가챠를 광고할 때도 확률 정보 명시

### 위반 시 처벌

- 시정명령
- 영업정지
- 형사처벌(2년 이하 징역 또는 2천만원 이하 벌금)

자세한 처벌 수준은 부록 C-4 표 참조.

### 예외

소형 게임(연 매출 1억 이하)은 일부 면제 조항이 있지만, 대부분의 상용 게임은 적용 대상이다.

## 13.2 일본 JOGA / 중국 명시 의무 — 해외 서비스 시 체크리스트

### 일본 — JOGA 가이드라인

JOGA(Japan Online Game Association)는 **자율규제**다. 강제는 아니지만 사실상 표준이다.

핵심 항목:
- 콤플리트 가챠 금지 (2012년부터)
- 유료 가챠 확률 표기 의무
- 천장 시스템 도입 권장 (일정 회차 후 보장)
- 기간한정 표기 명확화

위반 시 JOGA 회원사 자격 박탈, 플랫폼(Apple/Google) 심사 영향.

### 중국 — 게임 운영 관리 판법

- 모든 가챠 아이템의 확률을 정확히 명시
- 중국 내 서비스 시 외자판호(외국 게임 라이선스) 필수
- 사회주의 핵심 가치관과 충돌하지 않을 것 등의 추가 규제

### 해외 서비스 체크리스트

| 항목 | 한국 | 일본 | 중국 |
|------|------|------|------|
| 확률 공시 의무 | ●️ 법규 | ●️ JOGA | ●️ 법규 |
| 콤플리트 가챠 금지 | △ 변형 가능 | ●️ 금지 | △ 변형 가능 |
| 천장 명시 의무 | ●️ | △ 권장 | ●️ |
| 광고 시 확률 표기 | ●️ | △ | ●️ |
| 미성년자 결제 한도 | ●️ | △ | ●️ (월 200~400위안) |

해외 서비스를 시작하기 전에 반드시 **현지 법무 검토**가 필요하다.

## 13.3 [실전] 공시 페이지에 어떻게 표기해야 하는가 — 예시 포함

### 좋은 공시 예시 (요약 형식)

```
== 페로 픽업 배너 ==
기간: 2026.05.01 ~ 2026.05.21

[등급별 확률]
SSR: 0.700%
SR : 18.000%
R  : 81.300%

[픽업 캐릭터]
페로 (SSR)
- 픽업 확률: 0.350% (SSR 등장 시 50% 확률)

[일반 SSR 캐릭터]
야엘: 0.175%
메이: 0.175%

[일반 SR 캐릭터]
... (전부 명시)

[일반 R 캐릭터]
... (전부 명시)

[천장 시스템]
- 90회 천장: 90회 안에 SSR 1개 보장
- 50/50 보장: 픽업이 아닌 SSR을 받았다면, 다음 SSR은 100% 픽업

[추가 정보]
- 같은 캐릭터 중복 획득 시: 동일 캐릭 카드 1장으로 변환
- 박스 구조 아님 (일반 가챠)
```

### 나쁜 공시 예시 (사고 유발)

```
== 페로 픽업 배너 ==

SSR: 약 0.7% (소수점 둘째자리까지 비공개)
픽업: 별도 확률 비공개 ("기획 비밀")

* 천장: 있을 수 있음
```

이런 형태로 표기하면 위법 가능성이 높다. **모든 아이템과 정확한 확률**이 표시되어야 한다.

### "약" 표기는 가능한가

- 부동소수점 누적 오차로 정확히 표시할 수 없는 경우가 있다.
- 이때는 **소수점 N자리까지 명시**하고 "이하 절사" 등의 주석을 단다.
- 그래도 합이 100%가 되어야 한다.

### 자동 생성 권장

공시 페이지를 사람이 매번 작성하면 사고가 난다. **DB에서 직접 생성**하는 것이 안전하다.

```csharp
public sealed class DisclosureGenerator
{
    public string Generate(BannerData data)
    {
        var sb = new StringBuilder();
        sb.AppendLine($"== {data.Banner.Name} ==");
        sb.AppendLine($"기간: {data.Banner.StartAt:yyyy.MM.dd} ~ {data.Banner.EndAt:yyyy.MM.dd}");
        sb.AppendLine();

        sb.AppendLine("[등급별 확률]");
        foreach (var t in data.TierRates.OrderBy(x => x.Tier))
            sb.AppendLine($"{t.Tier}: {t.Probability * 100:F3}%");
        sb.AppendLine();

        sb.AppendLine("[아이템별 확률]");
        foreach (var item in data.Items.OrderBy(i => i.Tier).ThenBy(i => i.Code))
        {
            // 등급 확률 × 등급 안에서의 가중치 비율
            var tierRate = data.TierRates.First(t => t.Tier == item.Tier).Probability;
            var totalWeight = data.Items.Where(i => i.Tier == item.Tier).Sum(i => i.WeightInTier);
            var actualRate = tierRate * (item.WeightInTier / totalWeight);
            sb.AppendLine($"{item.Code} ({item.Tier}): {actualRate * 100:F4}%{(item.IsPickup ? " [픽업]" : "")}");
        }

        sb.AppendLine();
        sb.AppendLine("[천장 시스템]");
        sb.AppendLine($"- 하드 천장: {data.PityConfig.HardPity}회");
        if (data.PityConfig.SoftPityStart < data.PityConfig.HardPity)
            sb.AppendLine($"- 소프트 천장: {data.PityConfig.SoftPityStart}회부터 확률 상승");
        if (data.PityConfig.FiftyFiftyEnabled)
            sb.AppendLine("- 50/50 보장: 픽업이 아닌 SSR 수령 시, 다음 SSR은 픽업 확정");

        return sb.ToString();
    }
}
```

이렇게 만들어두면 **DB와 공시가 자동 일치**한다.

## 13.4 [함정] 개별 확률 vs 등급 확률 — 잘못 표기한 실제 사례

### 사례 (이름 변경)

A사는 출시 시 다음과 같이 공시했다.

```
SSR: 0.7%
SR : 18%
R  : 81.3%
```

이게 끝이었다. **개별 캐릭터 확률은 명시하지 않았다**. 유저가 데이터마이닝으로 캐릭터 가중치를 분석하니, 픽업이 아닌 일반 SSR 안에서도 등장 확률이 다른 것으로 드러났다.

> "야엘이 메이보다 더 자주 나오는데 왜 똑같다고 표기했냐"

이 일로 시정명령 + 과징금이 부과됐다.

### 핵심 교훈

- **등급 확률만 표시 = 부족**
- 같은 등급 안에서 가중치가 다르면 개별 표시 필수
- 가중치가 같으면 "균등 분배"라고 명시 가능
- 픽업은 별도 명시

### 안전한 표기 원칙

```
1. 등급 확률 표시
2. 등급 안에서 균등이면 "균등 분배" 명시
3. 가중치가 다르면 개별 확률 표시
4. 픽업 여부 별도 명시
5. 천장·보장 시스템 별도 표시
```

### 자동 검증 — CI에서 돌리기

```csharp
[Fact]
public void DisclosurePage_Matches_DatabaseConfig()
{
    var data = LoadActiveBanner();
    var disclosurePage = LoadDisclosureFromCms();

    var generated = _generator.Generate(data);

    disclosurePage.Should().Be(generated);
}
```

DB 확률을 바꿨는데 공시를 안 바꿨거나, 공시만 바꾸고 DB가 그대로면 이 테스트가 깨진다.

## 13장 요약

- 한국은 2024년 3월부터 확률 공시가 법적 의무다.
- 일본·중국 등 해외 서비스에는 별도의 가이드라인이 있다.
- 모든 아이템 확률, 천장 조건, 픽업 여부를 명확히 표시한다.
- 공시 페이지는 사람이 만들지 말고 DB에서 자동 생성한다.
- 등급 확률만 표기하면 부족하다. 같은 등급 안 가중치 차이가 있으면 개별 표시.

다음 장에서는 **확률이 의도대로 동작하는지** 자동 검증하는 법(카이제곱 검정, 몬테카를로)을 다룬다.
