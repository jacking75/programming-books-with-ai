# 6장. 천장 시스템 — Pity System 구현

수집형 RPG의 핵심 차별점이자, **유저가 가챠를 계속 돌리게 만드는 강력한 장치**가 천장 시스템이다. 단순 확률만 있으면 100번 뽑아도 0.7% SSR이 안 나올 수 있다(74% 확률로 못 뽑는다). 천장이 있으면 "최소한 N번이면 보장된다"는 안전망이 생긴다.

---

## 6.1 하드 천장(Hard Pity) — N번째엔 무조건 나온다

### 정의

> 카운터 N에 도달하면 100% 확률로 SSR이 나온다.

```
1회:  0.7% SSR
2회:  0.7% SSR
...
89회: 0.7% SSR
90회: 100% SSR  ← 하드 천장
```

### 가장 단순한 구현

```csharp
public sealed class HardPityState
{
    public int Counter { get; set; } = 0;
}

public sealed class HardPityGachaService
{
    private readonly TieredGachaService _baseService;
    private readonly int _hardPityAt;

    public HardPityGachaService(TieredGachaService baseService, int hardPityAt = 90)
    {
        _baseService = baseService;
        _hardPityAt = hardPityAt;
    }

    public GachaItem Draw(HardPityState state)
    {
        state.Counter++;

        if (state.Counter >= _hardPityAt)
        {
            // 천장 발동: 강제 SSR
            var ssr = _baseService.DrawSsrOnly();  // SSR 풀에서만 추첨
            state.Counter = 0;
            return ssr;
        }

        var result = _baseService.Draw();
        if (result.Tier == Tier.SSR) state.Counter = 0;
        return result;
    }
}
```

### 핵심 규칙

1. **카운터는 매 추첨마다 +1**한다.
2. **SSR이 나오면 카운터 리셋**한다(천장이든 일반 추첨이든).
3. **카운터는 영속**해야 한다. 서버 재시작/유저 재접속과 무관하게 유지된다.

### 카운터 리셋 시점 — 함정

```csharp
// ❌ 흔한 실수: 천장에서만 리셋
if (state.Counter >= _hardPityAt) { state.Counter = 0; return ssr; }
return _baseService.Draw();
// → 80번째에 자연 SSR이 나와도 카운터가 안 리셋됨
// → 91번째에 또 천장 → 11번 만에 두 번째 SSR

// ✅ SSR이 나올 때마다 리셋
if (result.Tier == Tier.SSR) state.Counter = 0;
```

이걸 놓치면 **1주일 뒤 데이터 분석에서 SSR이 너무 많이 나온다**는 보고가 올라온다.

## 6.2 소프트 천장(Soft Pity) — 확률이 점점 올라간다

### 정의

> 카운터 M부터 SSR 확률이 점점 올라가서, 하드 천장 N에서 100%에 도달한다.

```
1~73회:  0.7% (기본)
74회:    7.0%  ← 소프트 천장 시작
75회:    13.3%
76회:    19.6%
...
89회:   100.0% (실질적으로)
90회:   100%   (하드 천장)
```

원신은 74부터 +6% 정도씩 증가한다. 정확한 공식은 데이터마이닝으로 추정된 값이지만, 우리는 비슷한 패턴을 직접 만들 수 있다.

### 구현

```csharp
public sealed class SoftPityCurve
{
    private readonly double _baseRate;
    private readonly int _softStart;
    private readonly int _hardPity;
    private readonly double _stepIncrease;

    public SoftPityCurve(double baseRate, int softStart, int hardPity, double stepIncrease = 0.06)
    {
        _baseRate = baseRate;
        _softStart = softStart;
        _hardPity = hardPity;
        _stepIncrease = stepIncrease;
    }

    /// <summary>현재 카운터에서의 SSR 확률</summary>
    public double SsrRate(int counter)
    {
        if (counter >= _hardPity) return 1.0;
        if (counter < _softStart) return _baseRate;
        var steps = counter - _softStart + 1;
        return Math.Min(1.0, _baseRate + steps * _stepIncrease);
    }
}
```

### 적용 서비스

```csharp
public sealed class SoftPityGachaService
{
    private readonly SoftPityCurve _curve;
    private readonly TieredItemPool _pool;
    private readonly TieredGachaService _baseService;
    private readonly IRandomProvider _rng;

    public GachaItem Draw(HardPityState state)
    {
        state.Counter++;

        // 1) 동적 SSR 확률 계산
        var ssrRate = _curve.SsrRate(state.Counter);

        // 2) SSR / 그 외 추첨
        if (_rng.NextDouble() < ssrRate)
        {
            state.Counter = 0;
            return _pool.Pick(Tier.SSR);
        }

        // 3) SR/R 추첨 (SSR 제외 풀)
        return _baseService.DrawSrOrR();
    }
}
```

## 6.4 원신·스타레일식 50/50 보장 시스템 구현하기

### 규칙

1. SSR이 떴을 때 50% 확률로 **픽업**, 50%로 **일반 SSR**.
2. 일반 SSR이 떴으면(50/50 미스) **다음 SSR은 100% 픽업** (보장 플래그 ON).
3. 픽업이 떴으면 보장 플래그는 OFF로 리셋.

### 상태 모델

```csharp
public sealed class GachaPityState
{
    public int Counter { get; set; } = 0;
    public bool GuaranteedNextSsrIsPickup { get; set; } = false;
}
```

### 구현

```csharp
public sealed class FiftyFiftyPickupPolicy
{
    private readonly GachaItem _pickup;
    private readonly TieredItemPool _normalPool;
    private readonly IRandomProvider _rng;

    public FiftyFiftyPickupPolicy(GachaItem pickup, TieredItemPool normalPool, IRandomProvider rng)
    {
        _pickup = pickup;
        _normalPool = normalPool;
        _rng = rng;
    }

    public GachaItem PickSsr(GachaPityState state)
    {
        bool isPickup;
        if (state.GuaranteedNextSsrIsPickup)
        {
            isPickup = true;
            state.GuaranteedNextSsrIsPickup = false;
        }
        else
        {
            isPickup = _rng.NextDouble() < 0.5;
            // 일반 SSR이 나오면 다음번엔 보장
            if (!isPickup) state.GuaranteedNextSsrIsPickup = true;
        }

        return isPickup ? _pickup : _normalPool.Pick(Tier.SSR);
    }
}
```

### 전체 통합 서비스

```csharp
public sealed class FullGachaService
{
    private readonly SoftPityCurve _curve;
    private readonly FiftyFiftyPickupPolicy _pickupPolicy;
    private readonly TieredGachaService _baseService;
    private readonly IRandomProvider _rng;

    public GachaItem Draw(GachaPityState state)
    {
        state.Counter++;
        var ssrRate = _curve.SsrRate(state.Counter);

        if (_rng.NextDouble() < ssrRate)
        {
            state.Counter = 0;
            return _pickupPolicy.PickSsr(state);
        }

        return _baseService.DrawSrOrR();
    }
}
```

### 실제 흐름 예시

```
유저 A의 천장 상태
─────────────────────────────────────────
1~73:  카운터 증가, R/SR만 나옴
74:    SSR 0.7% → 일반 풀 SR (실패), 카운터=74
75:    SSR 13.3% → SSR (Yael, 일반)
       → 50/50 미스, 보장 ON, 카운터=0
─────────────────────────────────────────
76 (다음 풀 시작): 카운터=0
...
80:    SSR 7% → SSR
       → 보장 ON이라 무조건 픽업 → Pero
       → 보장 OFF, 카운터=0
```

### 핵심: 카운터와 보장 플래그는 다른 라이프사이클

| 상태 | 리셋 시점 |
|------|---------|
| 카운터 | SSR 등장 시 |
| 보장 플래그 | 픽업 SSR 등장 시 |
| 50/50 결과 | 매 SSR마다 새로 결정 |

## 6.5 [실습] 천장 카운터를 DB에 저장하고 리셋하는 법

### MySQL 테이블

```sql
CREATE TABLE user_gacha_pity (
    user_id BIGINT NOT NULL,
    banner_id INT NOT NULL,
    counter INT NOT NULL DEFAULT 0,
    guaranteed_next_ssr_is_pickup TINYINT(1) NOT NULL DEFAULT 0,
    last_drawn_at DATETIME(3) NULL,
    updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                                  ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (user_id, banner_id)
) ENGINE=InnoDB;
```

### Repository (SqlKata)

```csharp
using SqlKata;
using SqlKata.Execution;

public sealed class GachaPityRepository
{
    private readonly QueryFactory _db;

    public GachaPityRepository(QueryFactory db) => _db = db;

    public async Task<GachaPityState> GetOrCreateAsync(long userId, int bannerId, CancellationToken ct = default)
    {
        var row = await _db.Query("user_gacha_pity")
            .Where("user_id", userId)
            .Where("banner_id", bannerId)
            .FirstOrDefaultAsync<dynamic?>(cancellationToken: ct);

        if (row is null)
        {
            await _db.Query("user_gacha_pity").InsertAsync(new
            {
                user_id = userId,
                banner_id = bannerId,
                counter = 0,
                guaranteed_next_ssr_is_pickup = 0,
            }, cancellationToken: ct);
            return new GachaPityState();
        }

        return new GachaPityState
        {
            Counter = (int)row.counter,
            GuaranteedNextSsrIsPickup = ((sbyte)row.guaranteed_next_ssr_is_pickup) == 1,
        };
    }

    public async Task SaveAsync(long userId, int bannerId, GachaPityState state, CancellationToken ct = default)
    {
        await _db.Query("user_gacha_pity")
            .Where("user_id", userId)
            .Where("banner_id", bannerId)
            .UpdateAsync(new
            {
                counter = state.Counter,
                guaranteed_next_ssr_is_pickup = state.GuaranteedNextSsrIsPickup ? 1 : 0,
                last_drawn_at = DateTime.UtcNow,
            }, cancellationToken: ct);
    }

    /// <summary>관리 도구: 특정 유저 천장 강제 리셋</summary>
    public async Task ResetAsync(long userId, int bannerId, CancellationToken ct = default)
    {
        await _db.Query("user_gacha_pity")
            .Where("user_id", userId)
            .Where("banner_id", bannerId)
            .UpdateAsync(new
            {
                counter = 0,
                guaranteed_next_ssr_is_pickup = 0,
            }, cancellationToken: ct);
    }
}
```

### Redis 캐싱(CloudStructures)

천장 카운터는 **읽기·쓰기가 매우 잦다**. Redis로 hot path를 캐시하고, 주기적으로 DB에 동기화하는 것이 일반적이다.

```csharp
using CloudStructures;
using CloudStructures.Structures;

public sealed class GachaPityCache
{
    private readonly RedisConnection _conn;

    public GachaPityCache(RedisConnection conn) => _conn = conn;

    private RedisDictionary<string, int> Hash(long userId, int bannerId)
        => new(_conn, $"pity:{userId}:{bannerId}", TimeSpan.FromDays(30));

    public async Task<GachaPityState?> GetAsync(long userId, int bannerId)
    {
        var hash = Hash(userId, bannerId);
        var entries = await hash.GetAllAsync();
        if (entries.Count == 0) return null;

        return new GachaPityState
        {
            Counter = entries.GetValueOrDefault("counter", 0),
            GuaranteedNextSsrIsPickup = entries.GetValueOrDefault("guaranteed", 0) == 1,
        };
    }

    public async Task SaveAsync(long userId, int bannerId, GachaPityState state)
    {
        var hash = Hash(userId, bannerId);
        await hash.SetAsync(new Dictionary<string, int>
        {
            ["counter"] = state.Counter,
            ["guaranteed"] = state.GuaranteedNextSsrIsPickup ? 1 : 0,
        });
    }
}
```

### 통합 사용 패턴

```csharp
public async Task<GachaItem> DrawAsync(long userId, int bannerId)
{
    // 1) 캐시 → 미스 시 DB
    var state = await _cache.GetAsync(userId, bannerId)
             ?? await _repo.GetOrCreateAsync(userId, bannerId);

    // 2) 추첨
    var item = _service.Draw(state);

    // 3) 캐시 + DB 양쪽 갱신
    await _cache.SaveAsync(userId, bannerId, state);
    await _repo.SaveAsync(userId, bannerId, state);   // 트랜잭션은 11장에서

    return item;
}
```

### 배너 종료 시 리셋

배너가 끝나도 카운터를 **승계할지 / 리셋할지**는 게임마다 다르다.

| 게임 | 정책 |
|------|------|
| 원신 | 한정 캐릭터 배너 간 카운터 승계 |
| 스타레일 | 동일 |
| 블루아카이브 | 픽업 종료 시 천장 리셋 |

기획자와 합의한 정책을 **`banner.transition_policy`** 같은 컬럼으로 두면 변경에 유연해진다.

## 6.6 [버그 사례] 천장 카운터가 초기화되지 않는 실수

### 사례 — 야엘 사건

서비스 출시 1주일 후, 데이터 분석에서 보고가 들어왔다.

> "SSR 등장률이 1.4%로 의도(0.7%)의 두 배다."

원인 추적:

```csharp
// 출시 시 코드
public GachaItem Draw(PityState state)
{
    state.Counter++;
    if (state.Counter >= 90)
    {
        state.Counter = 0;
        return PickSsr();
    }
    var result = _baseService.Draw();
    return result;
    // ← SSR이 자연 발생해도 카운터 안 리셋
}
```

자연 발생 SSR에서 카운터가 리셋되지 않으니, 천장이 너무 자주 발동했다.

### 수정 후

```csharp
public GachaItem Draw(PityState state)
{
    state.Counter++;
    if (state.Counter >= 90)
    {
        state.Counter = 0;
        return PickSsr();
    }
    var result = _baseService.Draw();
    if (result.Tier == Tier.SSR) state.Counter = 0;  // ← 추가
    return result;
}
```

### 교훈

- **천장 시스템은 단위 테스트 필수**다. "1회차에 SSR 떴을 때 카운터=0이 되는가" 같은 케이스를 미리 작성한다.
- **카이제곱 검정**(14장)으로 출시 전에 100만 회 시뮬레이션을 돌려봤다면 잡혔을 버그다.
- 라이브 모니터링(15장) — 의도 확률 ±10% 이상 벗어나면 알람.

---

## 6장 요약

- 하드 천장은 N번째에 무조건 SSR이 나오는 안전장치다.
- 소프트 천장은 M번째부터 확률이 점진 증가하여 도파민 곡선을 부드럽게 한다.
- 50/50 보장 시스템은 픽업/일반을 번갈아가며, 미스 시 다음을 보장한다.
- 카운터/보장 플래그는 DB(MySQL)에 영속하고, Redis로 hot 캐시한다.
- **SSR 발생 시 카운터 리셋**을 빠뜨리면 의도 확률의 두 배가 발생한다.

다음 장에서는 비복원 추첨인 박스 가챠를 다룬다.
