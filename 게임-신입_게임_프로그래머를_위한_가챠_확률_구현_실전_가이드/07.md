# 7장. 박스 가챠 — 비복원 추첨

이번 장에서는 **박스(Box) 가챠**를 다룬다. 일반 가챠와 다른 점은 단 하나다. **뽑은 아이템은 박스에서 사라진다**(비복원). 그래서 풀이 점점 줄어들고, 마지막엔 반드시 모든 아이템을 얻게 된다.

---

## 7.1 복원 추첨 vs 비복원 추첨 — 왜 박스가 더 공정한가

### 복원 추첨 (일반 가챠)

```
박스 안 100개 = SSR 1 + SR 5 + R 94

100번 뽑으면?
  - SSR 0~5개 (가능)
  - 평균 1개지만 분산이 큼
  - 0개 확률 = 0.99^100 ≈ 36.6%
```

같은 박스를 100번 흔들어 본다고 생각하면 된다. 매번 같은 분포에서 추첨한다.

### 비복원 추첨 (박스 가챠)

```
박스 안 100개 = SSR 1 + SR 5 + R 94

100번 뽑으면?
  - SSR: 정확히 1개
  - SR : 정확히 5개
  - R  : 정확히 94개
  - 분산 = 0
```

뽑힌 아이템은 박스에서 빠진다. 결과는 무작위지만, **"몇 개가 나올지"는 결정**되어 있다.

### 그림으로 비교

```
[복원]
시도1: ●●●●● (SSR 1번 등장 가능)
시도2: ○○○○○ (SSR 0번)
시도3: ●●○○○ (SSR 2번)
... 매번 다름

[비복원]
시도1: SSR 1, SR 5, R 94 (확정)
시도2: 박스 새로 깐 거라면 또 동일
... 항상 같음
```

### 유저 입장

| 비교 | 복원 | 비복원 |
|------|------|--------|
| 운 | 크게 작용 | 거의 안 작용 |
| 보상 예측 | 어려움 | 정확 |
| 천장 필요 | 있음 | 박스 자체가 천장 |
| 결제 유도 | 강함 | 약함 |

박스 가챠는 **공정성이 강조되는 컨텐츠**(이벤트 보상함, 한정 아이템 보상)에 잘 어울린다.

## 7.2 Fisher-Yates 셔플 알고리즘 이해와 구현

### 아이디어

박스 안의 아이템을 미리 모두 펼쳐 두고, 무작위로 섞은 뒤 앞에서부터 하나씩 뽑는다.

```
[박스]                          [셔플 후]
[A, A, A, B, B, C, D, D, D, D]  →  [B, D, A, C, A, D, A, B, D, D]
                                                ↑
                                          뽑기 인덱스

뽑을 때마다 인덱스를 1 증가
```

### Fisher-Yates 알고리즘

```
for i = n-1 down to 1:
  j = random(0, i+1)   // 0 ≤ j ≤ i
  swap(arr[i], arr[j])
```

각 위치를 무작위 위치와 한 번씩 교환한다. 결과적으로 **모든 순열이 균등 분포**로 나온다.

### 구현

```csharp
public static class FisherYates
{
    public static void Shuffle<T>(IList<T> list, IRandomProvider rng)
    {
        for (int i = list.Count - 1; i > 0; i--)
        {
            int j = rng.NextInt(i + 1);
            (list[i], list[j]) = (list[j], list[i]);
        }
    }
}
```

### 함정 — 잘못된 셔플

```csharp
// ❌ 비균등: 일부 순열이 더 자주 나옴
public static void NaiveShuffle<T>(IList<T> list, IRandomProvider rng)
{
    for (int i = 0; i < list.Count; i++)
    {
        int j = rng.NextInt(list.Count);  // ← 0 ~ N-1 (틀림)
        (list[i], list[j]) = (list[j], list[i]);
    }
}
```

이 코드는 N^N 가지 결과를 만든다. 실제 순열은 N! 가지뿐이라 **균등하지 않다**. 게임 안에서 카드 셔플 등에 이걸 쓰면 특정 패턴이 더 자주 나오는 사고가 발생한다.

## 7.3 [실습] 박스 가챠 전체 구현 — 뽑기·리필·리셋

### 박스 정의

```csharp
public sealed record BoxItem(long ItemId, string Code, Tier Tier);

public sealed class BoxState
{
    /// <summary>박스 안에 남아있는 아이템 (셔플된 순서)</summary>
    public List<BoxItem> Remaining { get; set; } = new();

    /// <summary>박스 ID (기획 데이터 키)</summary>
    public int BoxDefId { get; set; }

    /// <summary>이 박스를 몇 번째 리필했는가</summary>
    public int RefillCount { get; set; }
}
```

### 박스 정의 (기획 데이터)

```csharp
public sealed record BoxDefinition(
    int BoxDefId,
    string Name,
    IReadOnlyList<(BoxItem Item, int Count)> Contents);

// 예시: 다이아 박스
var boxDef = new BoxDefinition(
    BoxDefId: 1,
    Name: "다이아 박스",
    Contents: new[]
    {
        (new BoxItem(1001, "PERO", Tier.SSR), 1),
        (new BoxItem(2001, "YAEL", Tier.SR ), 5),
        (new BoxItem(3001, "AOI",  Tier.R  ), 94),
    });
```

### 박스 가챠 서비스

```csharp
public sealed class BoxGachaService
{
    private readonly IRandomProvider _rng;

    public BoxGachaService(IRandomProvider rng) => _rng = rng;

    /// <summary>새 박스 생성 (또는 리필)</summary>
    public BoxState OpenNewBox(BoxDefinition def, int refillCount = 0)
    {
        var items = new List<BoxItem>();
        foreach (var (item, count) in def.Contents)
            for (int i = 0; i < count; i++) items.Add(item);

        FisherYates.Shuffle(items, _rng);

        return new BoxState
        {
            BoxDefId = def.BoxDefId,
            Remaining = items,
            RefillCount = refillCount,
        };
    }

    /// <summary>1회 뽑기</summary>
    public BoxItem DrawOne(BoxState state)
    {
        if (state.Remaining.Count == 0)
            throw new InvalidOperationException("박스가 비어있다");

        // 셔플은 이미 되어 있으니 마지막 원소를 빼는 게 O(1)
        var lastIdx = state.Remaining.Count - 1;
        var item = state.Remaining[lastIdx];
        state.Remaining.RemoveAt(lastIdx);
        return item;
    }

    /// <summary>박스가 비었으면 리필</summary>
    public BoxState DrawWithAutoRefill(BoxState state, BoxDefinition def, out BoxItem item)
    {
        if (state.Remaining.Count == 0)
        {
            state = OpenNewBox(def, state.RefillCount + 1);
        }
        item = DrawOne(state);
        return state;
    }
}
```

### 사용

```csharp
var rng = new ThreadSafeRandomProvider();
var service = new BoxGachaService(rng);
var state = service.OpenNewBox(boxDef);

for (int i = 0; i < 100; i++)
{
    var item = service.DrawOne(state);
    Console.WriteLine($"{i+1}회: {item.Tier} {item.Code}");
}
// → 정확히 SSR 1개, SR 5개, R 94개가 나옴
```

### DB 저장 (SqlKata)

박스 상태는 **JSON으로 직렬화**해서 한 컬럼에 저장하는 게 편하다.

```sql
CREATE TABLE user_box_state (
    user_id BIGINT NOT NULL,
    box_def_id INT NOT NULL,
    remaining_json JSON NOT NULL,
    refill_count INT NOT NULL DEFAULT 0,
    updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                                  ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (user_id, box_def_id)
) ENGINE=InnoDB;
```

```csharp
using System.Text.Json;

public sealed class BoxStateRepository
{
    private readonly QueryFactory _db;

    public async Task<BoxState?> GetAsync(long userId, int boxDefId, CancellationToken ct = default)
    {
        var row = await _db.Query("user_box_state")
            .Where("user_id", userId).Where("box_def_id", boxDefId)
            .FirstOrDefaultAsync<dynamic?>(cancellationToken: ct);
        if (row is null) return null;

        var remaining = JsonSerializer.Deserialize<List<BoxItem>>((string)row.remaining_json)!;
        return new BoxState
        {
            BoxDefId = boxDefId,
            Remaining = remaining,
            RefillCount = (int)row.refill_count,
        };
    }

    public async Task UpsertAsync(long userId, BoxState state, CancellationToken ct = default)
    {
        var json = JsonSerializer.Serialize(state.Remaining);
        // MySQL UPSERT
        var sql = @"
            INSERT INTO user_box_state (user_id, box_def_id, remaining_json, refill_count)
            VALUES (?, ?, ?, ?)
            ON DUPLICATE KEY UPDATE
              remaining_json = VALUES(remaining_json),
              refill_count = VALUES(refill_count)";
        await _db.StatementAsync(sql, new object[] {
            userId, state.BoxDefId, json, state.RefillCount
        }, cancellationToken: ct);
    }
}
```

## 7.4 [주의] 서버 재시작 시 박스 상태 동기화 문제

### 사례 — 박스가 다시 새 걸로 갈렸다

운영 중 서버 핫픽스를 위해 재시작했다. 그 직후 컴플레인이 들어왔다.

> "방금 99번 뽑았는데 SSR이 안 나왔어요. 다음에 나와야 하는데 다시 100개짜리 새 박스가 됐어요."

원인:

```csharp
// ❌ 박스 상태를 메모리에만 보관
public class BoxGachaService
{
    private static readonly Dictionary<long, BoxState> _states = new();

    public BoxItem Draw(long userId)
    {
        if (!_states.ContainsKey(userId))
            _states[userId] = OpenNewBox();   // 서버 재시작 시 새 박스
        return DrawOne(_states[userId]);
    }
}
```

서버가 재시작되면 메모리는 다 날아간다. **박스 상태는 반드시 영속해야 한다**.

### 해결책

```csharp
// ✅ DB(영속) + Redis(캐시) 패턴
public async Task<BoxItem> DrawAsync(long userId, int boxDefId)
{
    // 1) Redis 캐시
    var state = await _cache.GetBoxAsync(userId, boxDefId);
    state ??= await _repo.GetAsync(userId, boxDefId);
    state ??= _service.OpenNewBox(_def);

    // 2) 추첨
    var item = _service.DrawOne(state);

    // 3) 양쪽 동기화
    await _cache.SaveBoxAsync(userId, boxDefId, state);
    await _repo.UpsertAsync(userId, state);

    return item;
}
```

### 결정론적 셔플 — 시드 기반 박스

박스 상태를 매번 통째로 저장하기 부담스러우면, **시드와 인덱스만 저장**하는 방법도 있다.

```csharp
public sealed class SeededBoxState
{
    public int BoxDefId { get; set; }
    public int Seed { get; set; }
    public int NextIndex { get; set; }  // 다음 뽑을 위치
}

public BoxItem Draw(SeededBoxState state, BoxDefinition def)
{
    var items = ExpandContents(def);
    var rng = new SeededRandomProvider(state.Seed);
    FisherYates.Shuffle(items, rng);

    var item = items[state.NextIndex];
    state.NextIndex++;
    return item;
}
```

장점: DB 컬럼이 가볍다. 단점: 매 추첨마다 셔플을 다시 해야 해서 박스가 큰 경우 느릴 수 있다.

### 하이브리드 권장

박스가 **100개 이내**면 통째로 JSON으로 저장하는 게 단순하고 빠르다. 박스가 **수천 개**라면 시드 + 인덱스 방식이 유리하다. 게임 컨텐츠 특성에 맞춰 고른다.

## 7장 요약

- 박스 가챠는 비복원 추첨이라 결과 분산이 0이고 공정성이 강조된다.
- Fisher-Yates 셔플로 박스를 섞는 게 표준이다. 잘못된 셔플은 균등하지 않아 사고가 난다.
- 박스 상태는 메모리에만 두면 안 된다. DB(MySQL JSON) + Redis 캐시로 영속한다.
- 박스가 크면 시드 + 인덱스 방식, 작으면 통째로 JSON 저장.
