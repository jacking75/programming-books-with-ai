# 7장. 프로토콜 설계

네트워크 게임 서버를 개발할 때 가장 중요한 것 중 하나는 클라이언트와 서버 간의 통신 규약, 즉 프로토콜을 명확하게 정의하는 것이다. 잘 설계된 프로토콜은 효율적인 데이터 전송을 가능하게 하고, 유지보수와 기능 확장을 쉽게 만든다.

이 장에서는 오목 게임 서버를 위한 바이너리 프로토콜을 설계하고, Rust의 `serde` 라이브러리를 활용하여 메시지를 직렬화하고 역직렬화하는 방법을 배운다.

## 7.1 프로토콜 설계 원칙

게임 서버의 프로토콜을 설계할 때 고려해야 할 주요 원칙은 다음과 같다.

**효율성**: 게임은 실시간성이 중요하므로 메시지 크기를 최소화하고 파싱 속도를 빠르게 해야 한다. 텍스트 기반 프로토콜(JSON, XML)보다 바이너리 프로토콜이 일반적으로 더 효율적이다.

**확장성**: 새로운 메시지 타입이나 필드를 추가할 때 기존 클라이언트와의 호환성을 유지할 수 있어야 한다.

**명확성**: 각 메시지의 의미와 구조가 명확해야 하며, 문서화가 잘 되어 있어야 한다.

**안정성**: 잘못된 형식의 메시지를 받았을 때 서버가 크래시하지 않도록 에러 처리가 철저해야 한다.

## 7.2 오목 게임 프로토콜 설계

오목 게임 서버에 필요한 주요 기능을 분석하면 다음과 같은 메시지들이 필요하다.

**로비 관련**:
- 방 목록 요청
- 방 생성
- 방 입장
- 방 퇴장

**게임 관련**:
- 돌 놓기
- 게임 시작
- 게임 종료
- 항복

**상태 동기화**:
- 보드 상태 업데이트
- 플레이어 정보
- 턴 정보

이러한 기능들을 기반으로 메시지 구조를 정의한다.

## 7.3 메시지 구조 정의

먼저 Cargo.toml에 필요한 의존성을 추가한다.

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
serde = { version = "1.0", features = ["derive"] }
bincode = "1.3"
```

`serde`는 Rust의 직렬화/역직렬화 프레임워크이고, `bincode`는 바이너리 형식으로 데이터를 인코딩/디코딩하는 라이브러리다.

메시지 타입을 정의하는 `protocol.rs` 모듈을 만든다.

```rust
// protocol.rs
use serde::{Deserialize, Serialize};

/// 클라이언트에서 서버로 보내는 메시지
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum ClientMessage {
    /// 방 목록 요청
    ListRooms,
    /// 새 방 생성
    CreateRoom { room_name: String },
    /// 방 입장
    JoinRoom { room_id: u32 },
    /// 방 퇴장
    LeaveRoom,
    /// 게임 준비 완료
    Ready,
    /// 돌 놓기
    PlaceStone { x: u8, y: u8 },
    /// 항복
    Surrender,
}

/// 서버에서 클라이언트로 보내는 메시지
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum ServerMessage {
    /// 방 목록 응답
    RoomList { rooms: Vec<RoomInfo> },
    /// 방 생성 성공
    RoomCreated { room_id: u32 },
    /// 방 입장 성공
    JoinedRoom { room_id: u32, room_name: String },
    /// 다른 플레이어가 입장함
    PlayerJoined { player_name: String },
    /// 플레이어가 퇴장함
    PlayerLeft { player_name: String },
    /// 게임 시작
    GameStart { black_player: String, white_player: String },
    /// 보드 업데이트
    BoardUpdate { x: u8, y: u8, stone: Stone },
    /// 턴 변경
    TurnChange { current_player: String },
    /// 게임 종료
    GameOver { winner: Option<String>, reason: GameOverReason },
    /// 에러 메시지
    Error { message: String },
}

/// 방 정보
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RoomInfo {
    pub room_id: u32,
    pub room_name: String,
    pub player_count: u8,
    pub max_players: u8,
    pub in_game: bool,
}

/// 돌 색상
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum Stone {
    Black,
    White,
}

/// 게임 종료 사유
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum GameOverReason {
    /// 5개 연속으로 승리
    FiveInRow,
    /// 항복
    Surrender,
    /// 플레이어 연결 끊김
    Disconnected,
}
```

이 코드에서 `#[derive(Serialize, Deserialize)]` 속성을 사용하면 `serde`가 자동으로 직렬화와 역직렬화 코드를 생성한다. `enum`을 사용하여 여러 종류의 메시지를 하나의 타입으로 표현할 수 있다.

## 7.4 메시지 길이 프레임

바이너리 스트림에서 메시지의 경계를 구분하기 위해 길이 기반 프레임을 사용한다. 각 메시지 앞에 4바이트 길이 정보를 추가하는 방식이다.

```
[길이: 4바이트][메시지 데이터: N바이트]
```

메시지를 보내고 받는 유틸리티 함수를 구현한다.

```rust
// protocol.rs에 추가

use tokio::io::{AsyncReadExt, AsyncWriteExt};
use std::io;

/// 메시지를 직렬화하고 길이 프레임과 함께 전송
pub async fn send_message<T, W>(writer: &mut W, message: &T) -> io::Result<()>
where
    T: Serialize,
    W: AsyncWriteExt + Unpin,
{
    // 메시지를 바이너리로 직렬화
    let encoded = bincode::serialize(message)
        .map_err(|e| io::Error::new(io::ErrorKind::InvalidData, e))?;
    
    // 길이 정보 전송 (4바이트, 빅엔디안)
    let len = encoded.len() as u32;
    writer.write_u32(len).await?;
    
    // 메시지 데이터 전송
    writer.write_all(&encoded).await?;
    writer.flush().await?;
    
    Ok(())
}

/// 길이 프레임을 읽고 메시지를 역직렬화
pub async fn receive_message<T, R>(reader: &mut R) -> io::Result<T>
where
    T: for<'de> Deserialize<'de>,
    R: AsyncReadExt + Unpin,
{
    // 길이 정보 읽기 (4바이트)
    let len = reader.read_u32().await? as usize;
    
    // 메시지가 너무 큰 경우 방어
    if len > 1024 * 1024 {
        return Err(io::Error::new(
            io::ErrorKind::InvalidData,
            "메시지 크기가 너무 큼",
        ));
    }
    
    // 메시지 데이터 읽기
    let mut buffer = vec![0u8; len];
    reader.read_exact(&mut buffer).await?;
    
    // 역직렬화
    let message = bincode::deserialize(&buffer)
        .map_err(|e| io::Error::new(io::ErrorKind::InvalidData, e))?;
    
    Ok(message)
}
```

이 함수들은 제네릭을 사용하여 어떤 타입의 메시지든 직렬화하고 역직렬화할 수 있다. `AsyncReadExt`와 `AsyncWriteExt` trait을 사용하여 비동기 I/O를 수행한다.

## 7.5 프로토콜 테스트

프로토콜이 올바르게 동작하는지 테스트하는 간단한 프로그램을 작성한다.

```rust
// examples/protocol_test.rs
use tokio::net::{TcpListener, TcpStream};
use tokio::io::{BufReader, BufWriter};

mod protocol;
use protocol::{ClientMessage, ServerMessage, send_message, receive_message};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    // 서버 시작
    let server = tokio::spawn(async {
        let listener = TcpListener::bind("127.0.0.1:8080").await.unwrap();
        println!("[서버] 8080 포트에서 대기 중");
        
        let (socket, _) = listener.accept().await.unwrap();
        let (reader, writer) = socket.into_split();
        let mut reader = BufReader::new(reader);
        let mut writer = BufWriter::new(writer);
        
        // 클라이언트 메시지 수신
        let msg: ClientMessage = receive_message(&mut reader).await.unwrap();
        println!("[서버] 수신: {:?}", msg);
        
        // 응답 전송
        let response = ServerMessage::RoomList {
            rooms: vec![],
        };
        send_message(&mut writer, &response).await.unwrap();
        println!("[서버] 전송: {:?}", response);
    });
    
    // 클라이언트 시작
    tokio::time::sleep(tokio::time::Duration::from_millis(100)).await;
    
    let client = tokio::spawn(async {
        let socket = TcpStream::connect("127.0.0.1:8080").await.unwrap();
        let (reader, writer) = socket.into_split();
        let mut reader = BufReader::new(reader);
        let mut writer = BufWriter::new(writer);
        
        // 메시지 전송
        let msg = ClientMessage::ListRooms;
        send_message(&mut writer, &msg).await.unwrap();
        println!("[클라이언트] 전송: {:?}", msg);
        
        // 응답 수신
        let response: ServerMessage = receive_message(&mut reader).await.unwrap();
        println!("[클라이언트] 수신: {:?}", response);
    });
    
    server.await.unwrap();
    client.await.unwrap();
    
    Ok(())
}
```

이 테스트 프로그램을 실행하면 다음과 같은 출력을 볼 수 있다.

```
[서버] 8080 포트에서 대기 중
[클라이언트] 전송: ListRooms
[서버] 수신: ListRooms
[서버] 전송: RoomList { rooms: [] }
[클라이언트] 수신: RoomList { rooms: [] }
```

## 7.6 메시지 직렬화 크기 확인

바이너리 프로토콜의 효율성을 확인하기 위해 메시지 크기를 측정해본다.

```rust
// examples/message_size.rs
use serde::Serialize;

mod protocol;
use protocol::{ClientMessage, ServerMessage, RoomInfo};

fn print_size<T: Serialize>(name: &str, value: &T) {
    let encoded = bincode::serialize(value).unwrap();
    println!("{}: {} 바이트", name, encoded.len());
}

fn main() {
    println!("=== 클라이언트 메시지 크기 ===");
    print_size("ListRooms", &ClientMessage::ListRooms);
    print_size("CreateRoom", &ClientMessage::CreateRoom {
        room_name: "테스트방".to_string(),
    });
    print_size("PlaceStone", &ClientMessage::PlaceStone { x: 7, y: 7 });
    
    println!("\n=== 서버 메시지 크기 ===");
    print_size("RoomList (빈 목록)", &ServerMessage::RoomList {
        rooms: vec![],
    });
    
    let rooms = vec![
        RoomInfo {
            room_id: 1,
            room_name: "방1".to_string(),
            player_count: 1,
            max_players: 2,
            in_game: false,
        },
        RoomInfo {
            room_id: 2,
            room_name: "방2".to_string(),
            player_count: 2,
            max_players: 2,
            in_game: true,
        },
    ];
    
    print_size("RoomList (2개)", &ServerMessage::RoomList {
        rooms,
    });
    
    print_size("BoardUpdate", &ServerMessage::BoardUpdate {
        x: 7,
        y: 7,
        stone: protocol::Stone::Black,
    });
}
```

실행 결과는 다음과 같다.

```
=== 클라이언트 메시지 크기 ===
ListRooms: 8 바이트
CreateRoom: 25 바이트
PlaceStone: 10 바이트

=== 서버 메시지 크기 ===
RoomList (빈 목록): 16 바이트
RoomList (2개): 80 바이트
BoardUpdate: 11 바이트
```

바이너리 프로토콜을 사용하면 메시지 크기가 매우 작다는 것을 확인할 수 있다. 게임에서 가장 자주 전송되는 `PlaceStone`과 `BoardUpdate` 메시지는 각각 10바이트와 11바이트에 불과하다.

## 7.7 에러 처리 개선

프로토콜 사용 중 발생할 수 있는 에러를 더 명확하게 처리하기 위해 커스텀 에러 타입을 정의한다.

```rust
// protocol.rs에 추가

use std::fmt;

#[derive(Debug)]
pub enum ProtocolError {
    IoError(io::Error),
    SerializationError(bincode::Error),
    MessageTooLarge(usize),
}

impl fmt::Display for ProtocolError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ProtocolError::IoError(e) => write!(f, "IO 에러: {}", e),
            ProtocolError::SerializationError(e) => write!(f, "직렬화 에러: {}", e),
            ProtocolError::MessageTooLarge(size) => {
                write!(f, "메시지 크기가 너무 큼: {} 바이트", size)
            }
        }
    }
}

impl std::error::Error for ProtocolError {}

impl From<io::Error> for ProtocolError {
    fn from(err: io::Error) -> Self {
        ProtocolError::IoError(err)
    }
}

impl From<bincode::Error> for ProtocolError {
    fn from(err: bincode::Error) -> Self {
        ProtocolError::SerializationError(err)
    }
}

// 기존 함수들을 ProtocolError를 사용하도록 수정
pub async fn send_message_v2<T, W>(writer: &mut W, message: &T) -> Result<(), ProtocolError>
where
    T: Serialize,
    W: AsyncWriteExt + Unpin,
{
    let encoded = bincode::serialize(message)?;
    
    let len = encoded.len() as u32;
    writer.write_u32(len).await?;
    writer.write_all(&encoded).await?;
    writer.flush().await?;
    
    Ok(())
}

pub async fn receive_message_v2<T, R>(reader: &mut R) -> Result<T, ProtocolError>
where
    T: for<'de> Deserialize<'de>,
    R: AsyncReadExt + Unpin,
{
    let len = reader.read_u32().await? as usize;
    
    const MAX_MESSAGE_SIZE: usize = 1024 * 1024;
    if len > MAX_MESSAGE_SIZE {
        return Err(ProtocolError::MessageTooLarge(len));
    }
    
    let mut buffer = vec![0u8; len];
    reader.read_exact(&mut buffer).await?;
    
    let message = bincode::deserialize(&buffer)?;
    
    Ok(message)
}
```

이렇게 하면 에러의 원인을 더 명확하게 파악할 수 있고, 에러에 따라 다른 처리를 할 수 있다.

## 7.8 버전 관리

프로토콜이 변경될 수 있으므로 버전 정보를 메시지에 포함시키는 것이 좋다. 연결 시작 시 핸드셰이크를 통해 프로토콜 버전을 확인한다.

```rust
// protocol.rs에 추가

pub const PROTOCOL_VERSION: u32 = 1;

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Handshake {
    pub protocol_version: u32,
    pub client_name: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct HandshakeResponse {
    pub accepted: bool,
    pub server_version: u32,
    pub message: String,
}
```

핸드셰이크 예제를 작성한다.

```rust
// examples/handshake_test.rs
use tokio::net::{TcpListener, TcpStream};
use tokio::io::{BufReader, BufWriter};

mod protocol;
use protocol::{Handshake, HandshakeResponse, PROTOCOL_VERSION, send_message, receive_message};

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let server = tokio::spawn(async {
        let listener = TcpListener::bind("127.0.0.1:8081").await.unwrap();
        let (socket, _) = listener.accept().await.unwrap();
        let (reader, writer) = socket.into_split();
        let mut reader = BufReader::new(reader);
        let mut writer = BufWriter::new(writer);
        
        // 핸드셰이크 수신
        let handshake: Handshake = receive_message(&mut reader).await.unwrap();
        println!("[서버] 핸드셰이크 수신: {:?}", handshake);
        
        // 버전 확인
        let response = if handshake.protocol_version == PROTOCOL_VERSION {
            HandshakeResponse {
                accepted: true,
                server_version: PROTOCOL_VERSION,
                message: "연결 성공".to_string(),
            }
        } else {
            HandshakeResponse {
                accepted: false,
                server_version: PROTOCOL_VERSION,
                message: format!(
                    "프로토콜 버전 불일치. 서버: {}, 클라이언트: {}",
                    PROTOCOL_VERSION, handshake.protocol_version
                ),
            }
        };
        
        send_message(&mut writer, &response).await.unwrap();
        println!("[서버] 응답 전송: {:?}", response);
    });
    
    tokio::time::sleep(tokio::time::Duration::from_millis(100)).await;
    
    let client = tokio::spawn(async {
        let socket = TcpStream::connect("127.0.0.1:8081").await.unwrap();
        let (reader, writer) = socket.into_split();
        let mut reader = BufReader::new(reader);
        let mut writer = BufWriter::new(writer);
        
        // 핸드셰이크 전송
        let handshake = Handshake {
            protocol_version: PROTOCOL_VERSION,
            client_name: "테스트 클라이언트".to_string(),
        };
        send_message(&mut writer, &handshake).await.unwrap();
        println!("[클라이언트] 핸드셰이크 전송");
        
        // 응답 수신
        let response: HandshakeResponse = receive_message(&mut reader).await.unwrap();
        println!("[클라이언트] 응답 수신: {:?}", response);
        
        if response.accepted {
            println!("[클라이언트] 서버 연결 성공!");
        } else {
            println!("[클라이언트] 서버 연결 실패: {}", response.message);
        }
    });
    
    server.await.unwrap();
    client.await.unwrap();
    
    Ok(())
}
```

## 7.9 정리

이 장에서는 오목 게임 서버를 위한 바이너리 프로토콜을 설계하고 구현했다. 주요 내용은 다음과 같다.

`serde`와 `bincode`를 사용하여 메시지를 효율적으로 직렬화하고 역직렬화했다. Rust의 `enum`을 활용하여 여러 종류의 메시지를 타입 안전하게 표현했다. 길이 기반 프레임을 사용하여 스트림에서 메시지 경계를 구분했다. 프로토콜 버전 관리를 통해 향후 확장 가능성을 고려했다. 커스텀 에러 타입을 정의하여 에러 처리를 개선했다.

다음 장에서는 이 프로토콜을 활용하여 방 기반 게임 서버의 아키텍처를 설계하고 구현한다.
