# 4장. Tokio 소개

## 4.1 Tokio란 무엇인가

Tokio는 Rust를 위한 비동기 런타임이다. 네트워크 애플리케이션을 구축하는 데 필요한 도구를 제공하며, 특히 고성능 게임 서버와 같이 많은 동시 연결을 처리해야 하는 경우에 적합하다.

Tokio를 사용하면 수천 개의 동시 연결을 효율적으로 처리할 수 있다. 전통적인 스레드 기반 접근 방식과 달리, Tokio는 적은 수의 OS 스레드로 많은 작업을 동시에 실행한다. 이는 컨텍스트 스위칭 비용을 줄이고 메모리 사용량을 최적화한다.

### Tokio의 주요 특징

Tokio는 크게 세 가지 핵심 기능을 제공한다.

첫째, 비동기 작업을 실행하는 멀티스레드 런타임이다. 런타임은 async 함수를 실제로 실행하고 스케줄링하는 역할을 담당한다.

둘째, 비동기 I/O를 위한 API를 제공한다. TCP, UDP 소켓뿐만 아니라 파일 I/O, 타이머 등 다양한 비동기 작업을 지원한다.

셋째, 비동기 프로그래밍을 위한 유틸리티를 제공한다. 채널, 뮤텍스, 세마포어 등 동시성 프로그래밍에 필요한 도구들이 포함되어 있다.

## 4.2 Tokio 런타임 구조

Tokio 런타임은 비동기 작업을 실제로 실행하는 엔진이다. 런타임 없이는 async 함수를 실행할 수 없다.

### 런타임의 작동 방식

Tokio 런타임은 워크 스틸링(work-stealing) 스케줄러를 사용한다. 여러 개의 워커 스레드가 작업 큐를 공유하며, 한 스레드가 유휴 상태가 되면 다른 스레드의 작업을 가져와 실행한다. 이를 통해 CPU 코어를 최대한 활용할 수 있다.

런타임은 크게 두 가지 타입이 있다. 멀티스레드 런타임과 싱글스레드 런타임이다. 대부분의 경우 멀티스레드 런타임을 사용하며, 이는 CPU 코어 수만큼 워커 스레드를 생성한다.

### 런타임 생성 방법

Tokio에서 런타임을 생성하는 가장 간단한 방법은 `#[tokio::main]` 매크로를 사용하는 것이다.

```rust
#[tokio::main]
async fn main() {
    println!("Hello from Tokio!");
}
```

이 매크로는 자동으로 멀티스레드 런타임을 생성하고 main 함수를 그 안에서 실행한다. 내부적으로는 다음과 같은 코드로 확장된다.

```rust
fn main() {
    tokio::runtime::Runtime::new()
        .unwrap()
        .block_on(async {
            println!("Hello from Tokio!");
        })
}
```

수동으로 런타임을 생성할 수도 있다. 이는 런타임의 설정을 세밀하게 제어하고 싶을 때 유용하다.

```rust
use tokio::runtime::Runtime;

fn main() {
    let runtime = Runtime::new().unwrap();
    
    runtime.block_on(async {
        println!("Hello from manually created runtime!");
    });
}
```

더 세밀한 제어가 필요하다면 `Runtime::builder()`를 사용한다.

```rust
use tokio::runtime::Builder;

fn main() {
    let runtime = Builder::new_multi_thread()
        .worker_threads(4)  // 워커 스레드 수 지정
        .thread_name("my-game-server")
        .enable_all()
        .build()
        .unwrap();
    
    runtime.block_on(async {
        println!("Custom runtime configuration");
    });
}
```

## 4.3 Tokio의 주요 컴포넌트

Tokio는 여러 하위 모듈로 구성되어 있으며, 각각 특정 기능을 담당한다.

### tokio::runtime

런타임 모듈은 비동기 작업을 실행하는 환경을 제공한다. 이미 앞서 살펴본 `Runtime` 타입이 여기에 포함된다.

`block_on` 함수는 비동기 함수를 동기적으로 실행하고 결과를 반환한다. 이는 주로 main 함수나 테스트 코드에서 사용된다.

```rust
use tokio::runtime::Runtime;

fn main() {
    let rt = Runtime::new().unwrap();
    
    let result = rt.block_on(async {
        // 비동기 작업 수행
        "작업 완료"
    });
    
    println!("{}", result);
}
```

### tokio::task

태스크 모듈은 비동기 작업을 생성하고 관리하는 기능을 제공한다. `spawn` 함수를 통해 새로운 비동기 태스크를 생성할 수 있다.

```rust
#[tokio::main]
async fn main() {
    let handle = tokio::spawn(async {
        println!("백그라운드에서 실행 중");
        42
    });
    
    // 태스크의 완료를 기다리고 결과를 받음
    let result = handle.await.unwrap();
    println!("결과: {}", result);
}
```

`spawn`으로 생성된 태스크는 별도의 스케줄링 단위로 실행된다. 즉, 런타임이 다른 워커 스레드에서 이 태스크를 실행할 수 있다.

여러 태스크를 동시에 실행하는 예제를 보자.

```rust
#[tokio::main]
async fn main() {
    let task1 = tokio::spawn(async {
        for i in 1..=3 {
            println!("태스크 1: {}", i);
            tokio::time::sleep(tokio::time::Duration::from_millis(100)).await;
        }
    });
    
    let task2 = tokio::spawn(async {
        for i in 1..=3 {
            println!("태스크 2: {}", i);
            tokio::time::sleep(tokio::time::Duration::from_millis(150)).await;
        }
    });
    
    // 두 태스크 모두 완료될 때까지 대기
    task1.await.unwrap();
    task2.await.unwrap();
}
```

### tokio::io

I/O 모듈은 비동기 읽기와 쓰기 작업을 위한 트레이트와 유틸리티를 제공한다. `AsyncRead`와 `AsyncWrite` 트레이트가 핵심이다.

이 트레이트들은 `std::io::Read`와 `std::io::Write`의 비동기 버전이라고 생각하면 된다. Tokio의 네트워크 타입들은 이 트레이트들을 구현한다.

```rust
use tokio::io::{AsyncReadExt, AsyncWriteExt};
use tokio::net::TcpStream;

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let mut stream = TcpStream::connect("127.0.0.1:8080").await?;
    
    // 데이터 쓰기
    stream.write_all(b"Hello").await?;
    
    // 데이터 읽기
    let mut buffer = [0u8; 1024];
    let n = stream.read(&mut buffer).await?;
    
    println!("받은 데이터: {:?}", &buffer[..n]);
    
    Ok(())
}
```

### tokio::net

네트워크 모듈은 비동기 네트워크 프로그래밍을 위한 타입들을 제공한다. TCP, UDP 소켓을 비동기 방식으로 사용할 수 있다.

주요 타입으로는 `TcpListener`, `TcpStream`, `UdpSocket` 등이 있다. 이들은 표준 라이브러리의 동기 버전과 유사한 API를 제공하지만 비동기로 작동한다.

```rust
use tokio::net::TcpListener;

#[tokio::main]
async fn main() -> std::io::Result<()> {
    let listener = TcpListener::bind("127.0.0.1:8080").await?;
    println!("서버가 127.0.0.1:8080에서 대기 중");
    
    loop {
        let (socket, addr) = listener.accept().await?;
        println!("새 연결: {}", addr);
        
        // 각 연결을 별도 태스크에서 처리
        tokio::spawn(async move {
            // 연결 처리 로직
        });
    }
}
```

### tokio::sync

동기화 모듈은 비동기 환경에서 사용할 수 있는 동기화 프리미티브를 제공한다. `Mutex`, `RwLock`, `Semaphore`, 그리고 다양한 채널 타입이 포함된다.

표준 라이브러리의 동기화 타입들과 달리, Tokio의 동기화 타입들은 lock을 기다리는 동안 다른 태스크가 실행될 수 있도록 await 포인트를 제공한다.

```rust
use tokio::sync::Mutex;
use std::sync::Arc;

#[tokio::main]
async fn main() {
    let data = Arc::new(Mutex::new(0));
    
    let mut handles = vec![];
    
    for _ in 0..10 {
        let data = Arc::clone(&data);
        let handle = tokio::spawn(async move {
            let mut lock = data.lock().await;
            *lock += 1;
        });
        handles.push(handle);
    }
    
    for handle in handles {
        handle.await.unwrap();
    }
    
    println!("최종 값: {}", *data.lock().await);
}
```

### tokio::time

시간 관련 모듈은 비동기 타이머와 시간 지연 기능을 제공한다. `sleep`, `interval`, `timeout` 등의 함수가 있다.

```rust
use tokio::time::{sleep, Duration, interval};

#[tokio::main]
async fn main() {
    // 1초 대기
    sleep(Duration::from_secs(1)).await;
    println!("1초 경과");
    
    // 주기적 실행
    let mut ticker = interval(Duration::from_millis(500));
    for _ in 0..5 {
        ticker.tick().await;
        println!("틱!");
    }
}
```

## 4.4 Tokio 설치 및 프로젝트 설정

### 프로젝트 생성

먼저 새로운 Rust 프로젝트를 생성한다.

```bash
cargo new tokio-game-server
cd tokio-game-server
```

### Cargo.toml 설정

Tokio를 사용하려면 `Cargo.toml` 파일에 의존성을 추가해야 한다.

```toml
[package]
name = "tokio-game-server"
version = "0.1.0"
edition = "2021"

[dependencies]
tokio = { version = "1.40", features = ["full"] }
```

`features = ["full"]`은 Tokio의 모든 기능을 활성화한다. 프로덕션 환경에서는 필요한 기능만 선택하는 것이 좋지만, 학습 단계에서는 전체 기능을 사용하는 것이 편리하다.

필요한 기능만 선택하려면 다음과 같이 작성한다.

```toml
[dependencies]
tokio = { version = "1.40", features = ["rt-multi-thread", "net", "io-util", "macros"] }
```

각 feature의 의미는 다음과 같다.

- `rt-multi-thread`: 멀티스레드 런타임
- `net`: TCP, UDP 네트워킹
- `io-util`: AsyncReadExt, AsyncWriteExt 등 I/O 유틸리티
- `macros`: #[tokio::main], #[tokio::test] 등 매크로
- `sync`: Mutex, RwLock, 채널 등 동기화 프리미티브
- `time`: sleep, interval, timeout 등 시간 관련 기능

### 첫 번째 Tokio 프로그램

설치가 완료되었으니 간단한 Tokio 프로그램을 작성해보자.

```rust
// src/main.rs
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    println!("Tokio 서버 시작!");
    
    // 여러 태스크를 동시에 실행
    let task1 = tokio::spawn(worker(1));
    let task2 = tokio::spawn(worker(2));
    let task3 = tokio::spawn(worker(3));
    
    // 모든 태스크 완료 대기
    task1.await.unwrap();
    task2.await.unwrap();
    task3.await.unwrap();
    
    println!("모든 작업 완료!");
}

async fn worker(id: u32) {
    for i in 1..=3 {
        println!("워커 {}: 작업 {} 실행 중", id, i);
        sleep(Duration::from_millis(500)).await;
    }
    println!("워커 {} 완료", id);
}
```

이 프로그램을 실행하면 세 개의 워커가 동시에 작업을 수행하는 것을 볼 수 있다.

```bash
cargo run
```

### 런타임 구성 확인

런타임이 실제로 어떻게 동작하는지 확인해보자.

```rust
use tokio::runtime::Builder;
use std::thread;

fn main() {
    let runtime = Builder::new_multi_thread()
        .worker_threads(4)
        .thread_name("game-server-worker")
        .enable_all()
        .build()
        .unwrap();
    
    runtime.block_on(async {
        println!("메인 스레드: {:?}", thread::current().id());
        
        for i in 1..=5 {
            tokio::spawn(async move {
                println!("태스크 {} 실행 중 - 스레드: {:?}", 
                    i, thread::current().id());
            });
        }
        
        // 태스크들이 완료될 시간을 줌
        tokio::time::sleep(tokio::time::Duration::from_millis(100)).await;
    });
}
```

이 프로그램을 실행하면 다양한 스레드에서 태스크들이 실행되는 것을 확인할 수 있다. 이는 Tokio가 워크 스틸링 스케줄러를 통해 작업을 여러 워커 스레드에 분산시키기 때문이다.

## 4.5 Tokio vs 스레드 기반 동시성

2장에서 스레드 기반 동시성을 다루었다. 이제 Tokio와 스레드 기반 접근 방식의 차이를 비교해보자.

### 리소스 사용량

스레드 기반 방식에서는 각 연결마다 하나의 OS 스레드를 생성한다. 각 스레드는 최소 수 MB의 스택 메모리를 필요로 한다. 1000개의 동시 연결을 처리하려면 1000개의 스레드가 필요하며, 이는 수 GB의 메모리를 소비할 수 있다.

Tokio는 태스크를 사용한다. 태스크는 스레드보다 훨씬 가볍다. 수천 개의 태스크를 적은 수의 OS 스레드에서 실행할 수 있다. 태스크의 메모리 오버헤드는 수십 바이트에 불과하다.

### 컨텍스트 스위칭

스레드 기반 시스템에서는 OS가 스레드 간 전환을 관리한다. 컨텍스트 스위칭은 비용이 크며, 스레드가 많을수록 오버헤드가 증가한다.

Tokio는 협력적 스케줄링을 사용한다. 태스크는 await 포인트에서만 제어권을 양보한다. 스케줄러가 유저스페이스에서 동작하므로 컨텍스트 스위칭 비용이 훨씬 적다.

### 성능 비교 예제

동일한 작업을 스레드와 Tokio로 구현하여 비교해보자.

스레드 기반 버전:

```rust
use std::thread;
use std::time::Duration;

fn main() {
    let start = std::time::Instant::now();
    
    let mut handles = vec![];
    for i in 0..1000 {
        let handle = thread::spawn(move || {
            thread::sleep(Duration::from_millis(10));
            i
        });
        handles.push(handle);
    }
    
    for handle in handles {
        handle.join().unwrap();
    }
    
    println!("스레드 기반: {:?}", start.elapsed());
}
```

Tokio 기반 버전:

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let start = std::time::Instant::now();
    
    let mut handles = vec![];
    for i in 0..1000 {
        let handle = tokio::spawn(async move {
            sleep(Duration::from_millis(10)).await;
            i
        });
        handles.push(handle);
    }
    
    for handle in handles {
        handle.await.unwrap();
    }
    
    println!("Tokio 기반: {:?}", start.elapsed());
}
```

Tokio 버전이 훨씬 빠르게 실행되고 적은 메모리를 사용하는 것을 확인할 수 있다.

### 언제 무엇을 사용할 것인가

스레드 기반 방식이 적합한 경우는 CPU 집약적인 작업을 수행할 때다. 예를 들어 복잡한 계산이나 이미지 처리 같은 작업은 스레드가 유리하다.

Tokio가 적합한 경우는 I/O 집약적인 작업을 수행할 때다. 네트워크 서버, 데이터베이스 쿼리, 파일 작업 등이 해당된다. 게임 서버는 대부분 I/O 집약적이므로 Tokio가 이상적이다.

두 방식을 혼합할 수도 있다. Tokio에서 CPU 집약적 작업이 필요하면 `tokio::task::spawn_blocking`을 사용하여 별도의 스레드 풀에서 실행할 수 있다.

```rust
#[tokio::main]
async fn main() {
    let result = tokio::task::spawn_blocking(|| {
        // CPU 집약적인 작업
        let mut sum = 0;
        for i in 0..1_000_000 {
            sum += i;
        }
        sum
    }).await.unwrap();
    
    println!("계산 결과: {}", result);
```

## 4.6 정리

이 장에서는 Tokio의 기본 개념과 구조를 살펴보았다. Tokio는 비동기 런타임으로서 효율적인 동시성 처리를 가능하게 한다. 런타임, 태스크, I/O, 네트워크, 동기화, 시간 관련 모듈이 핵심 컴포넌트다.

Tokio를 설치하고 기본적인 프로그램을 작성하는 방법을 배웠다. `#[tokio::main]` 매크로를 사용하면 간단하게 비동기 프로그램을 시작할 수 있다.

스레드 기반 동시성과 비교했을 때, Tokio는 리소스 효율성과 확장성 면에서 우수하다. 특히 많은 동시 연결을 처리해야 하는 게임 서버에 적합하다.
