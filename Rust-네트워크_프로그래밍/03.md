# 3장. Rust 비동기 프로그래밍 이해

2장에서 스레드 기반 동시성을 배웠지만, 수천 명의 동시 접속자를 처리하는 게임 서버에는 비효율적이다. 비동기 프로그래밍은 적은 리소스로 많은 동시 작업을 처리할 수 있는 효율적인 방법이다. 이 장에서는 Tokio를 사용하기 전에 Rust의 비동기 프로그래밍 개념을 이해한다.

## async/await 기본 개념

비동기 프로그래밍은 작업이 완료되기를 기다리는 동안 다른 작업을 수행할 수 있게 하는 프로그래밍 패러다임이다. Rust는 `async`/`await` 키워드를 통해 비동기 프로그래밍을 지원한다.

### 동기 함수 vs 비동기 함수

먼저 일반적인 동기 함수와 비동기 함수의 차이를 살펴본다.

```rust
// 동기 함수: 즉시 결과를 반환
fn synchronous_function() -> String {
    "Hello, World!".to_string()
}

// 비동기 함수: Future를 반환
async fn asynchronous_function() -> String {
    "Hello, Async World!".to_string()
}
```

비동기 함수는 `async fn` 키워드로 선언한다. 이 함수는 호출 시 즉시 실행되지 않고 `Future`라는 특별한 타입을 반환한다.

### Future란 무엇인가

`Future`는 아직 완료되지 않은 계산을 나타내는 타입이다. Future는 실행기(executor)에 의해 폴링(polling)되며, 준비가 되면 값을 생성한다.

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};

// Future의 간단한 예제
struct SimpleFuture {
    completed: bool,
}

impl Future for SimpleFuture {
    type Output = String;
    
    fn poll(mut self: Pin<&mut Self>, _cx: &mut Context<'_>) -> Poll<Self::Output> {
        if self.completed {
            Poll::Ready("작업 완료!".to_string())
        } else {
            self.completed = true;
            Poll::Pending
        }
    }
}
```

대부분의 경우 직접 Future를 구현할 필요는 없다. `async` 키워드를 사용하면 컴파일러가 자동으로 Future를 생성한다.

### await 키워드 사용하기

`await` 키워드는 비동기 함수 내에서 Future가 완료될 때까지 기다린다. 중요한 점은 대기하는 동안 스레드를 차단하지 않는다는 것이다.

```rust
async fn fetch_data() -> String {
    // 실제로는 네트워크 요청이나 파일 I/O 등
    "데이터".to_string()
}

async fn process_data() -> String {
    // await로 fetch_data가 완료될 때까지 기다림
    let data = fetch_data().await;
    
    format!("처리된 {}", data)
}
```

`await`는 오직 `async` 함수 또는 블록 내에서만 사용할 수 있다.

### 비동기 블록

`async` 블록을 사용하여 익명의 비동기 코드를 작성할 수 있다.

```rust
async fn example() {
    let future = async {
        let x = 1;
        let y = 2;
        x + y
    };
    
    let result = future.await;
    println!("결과: {}", result);
}
```

### 실행기(Executor)의 필요성

비동기 함수는 자동으로 실행되지 않는다. Future를 실행하려면 실행기가 필요하다. Rust 표준 라이브러리는 실행기를 제공하지 않으므로, 외부 크레이트를 사용해야 한다.

간단한 예제를 위해 `futures` 크레이트를 사용해본다.

먼저 `Cargo.toml`에 의존성을 추가한다.

```toml
[dependencies]
futures = "0.3"
```

그리고 다음과 같이 비동기 코드를 실행할 수 있다.

```rust
use futures::executor::block_on;

async fn hello_async() {
    println!("안녕, 비동기 세계!");
}

fn main() {
    // block_on은 Future가 완료될 때까지 현재 스레드를 차단
    block_on(hello_async());
}
```

### 비동기 함수의 실용적 예제

여러 작업을 동시에 처리하는 예제를 살펴본다.

```rust
use futures::executor::block_on;
use std::time::Duration;

// 비동기 대기 함수 (실제로는 tokio::time::sleep을 사용)
async fn async_sleep(seconds: u64) {
    println!("{}초 대기 시작", seconds);
    // 여기서는 시뮬레이션만 함
    println!("{}초 대기 완료", seconds);
}

async fn do_task(id: u32, seconds: u64) -> String {
    println!("작업 {} 시작", id);
    async_sleep(seconds).await;
    println!("작업 {} 완료", id);
    format!("작업 {} 결과", id)
}

async fn run_tasks() {
    let task1 = do_task(1, 2);
    let task2 = do_task(2, 1);
    let task3 = do_task(3, 3);
    
    // 순차 실행
    let result1 = task1.await;
    let result2 = task2.await;
    let result3 = task3.await;
    
    println!("{}, {}, {}", result1, result2, result3);
}

fn main() {
    block_on(run_tasks());
}
```

위 코드는 순차적으로 실행된다. 동시 실행을 위해서는 `futures::join!` 매크로를 사용할 수 있다.

```rust
use futures::executor::block_on;
use futures::join;

async fn run_tasks_concurrent() {
    let task1 = do_task(1, 2);
    let task2 = do_task(2, 1);
    let task3 = do_task(3, 3);
    
    // 모든 작업을 동시에 실행
    let (result1, result2, result3) = join!(task1, task2, task3);
    
    println!("{}, {}, {}", result1, result2, result3);
}

fn main() {
    block_on(run_tasks_concurrent());
}
```

## Future trait 이해

Future trait은 Rust 비동기 프로그래밍의 핵심이다. 이를 이해하면 비동기 코드가 어떻게 동작하는지 깊이 파악할 수 있다.

### Future trait 정의

Future trait의 핵심 정의는 다음과 같다.

```rust
pub trait Future {
    type Output;
    
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

pub enum Poll<T> {
    Ready(T),
    Pending,
}
```

- `Output`: Future가 완료되었을 때 생성하는 값의 타입
- `poll()`: Future의 상태를 확인하는 메서드
- `Poll::Ready(T)`: 작업이 완료되어 결과를 반환
- `Poll::Pending`: 작업이 아직 완료되지 않음

### 간단한 타이머 Future 구현

타이머 Future를 직접 구현하여 동작 원리를 이해해본다.

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};
use std::time::{Duration, Instant};

struct TimerFuture {
    deadline: Instant,
}

impl TimerFuture {
    fn new(duration: Duration) -> Self {
        TimerFuture {
            deadline: Instant::now() + duration,
        }
    }
}

impl Future for TimerFuture {
    type Output = ();
    
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output> {
        if Instant::now() >= self.deadline {
            println!("타이머 완료!");
            Poll::Ready(())
        } else {
            println!("타이머 대기 중...");
            
            // 실제 구현에서는 wake()를 호출하여 나중에 다시 폴링되도록 함
            cx.waker().wake_by_ref();
            
            Poll::Pending
        }
    }
}

// 사용 예제
async fn use_timer() {
    println!("타이머 시작");
    TimerFuture::new(Duration::from_secs(2)).await;
    println!("타이머 종료");
}
```

### Waker와 비동기 실행 흐름

`Context`의 `Waker`는 Future가 진행할 준비가 되었을 때 실행기에 알리는 역할을 한다.

```rust

// Waker의 역할:
// 1. Future가 Poll::Pending을 반환할 때 Waker를 저장
// 2. 작업이 준비되면 wake()를 호출하여 실행기에 알림
// 3. 실행기가 다시 poll()을 호출

async fn understanding_waker() {
    // I/O 작업이나 타이머가 완료되면
    // 내부적으로 waker.wake()가 호출되어
    // 실행기가 이 Future를 다시 폴링함
}
```

### 여러 Future 조합하기

복잡한 비동기 로직을 만들기 위해 여러 Future를 조합할 수 있다.

```rust
use futures::future::{join, select, FutureExt};
use futures::executor::block_on;

async fn task_a() -> i32 {
    println!("Task A 실행");
    42
}

async fn task_b() -> i32 {
    println!("Task B 실행");
    100
}

async fn combining_futures() {
    // 두 Future를 모두 기다림
    let (a, b) = join(task_a(), task_b()).await;
    println!("결과: {}, {}", a, b);
    
    // 먼저 완료되는 것을 선택
    let result = select(task_a().boxed(), task_b().boxed()).await;
    match result {
        futures::future::Either::Left((val, _)) => {
            println!("Task A가 먼저 완료: {}", val);
        }
        futures::future::Either::Right((val, _)) => {
            println!("Task B가 먼저 완료: {}", val);
        }
    }
}

fn main() {
    block_on(combining_futures());
}
```

### Pin과 Unpin

Future를 구현할 때 `Pin<&mut Self>`를 사용하는 이유는 자기 참조 구조체를 안전하게 다루기 위해서다.

```rust
use std::pin::Pin;

// Pin은 값이 메모리에서 이동하지 않도록 보장
// 비동기 함수 내부에서 자기 자신을 참조하는 경우 필요

async fn example_with_self_reference() {
    let mut x = 5;
    let x_ref = &x; // 자기 참조
    
    // await 포인트에서 Future가 suspend될 수 있음
    // 이때 x가 이동하면 x_ref가 무효화됨
    // Pin은 이를 방지함
    
    some_async_function().await;
    
    println!("{}", x_ref);
}

async fn some_async_function() {
    // 일부 비동기 작업
}
```

대부분의 경우 `async`/`await`를 사용하면 컴파일러가 자동으로 처리하므로 직접 Pin을 다룰 필요는 없다.

## 동기 vs 비동기 비교

동기 방식과 비동기 방식의 차이를 구체적인 예제로 비교해본다.

### 리소스 사용 비교

동기 방식에서는 각 연결마다 스레드가 필요하지만, 비동기 방식에서는 하나의 스레드로 여러 연결을 처리할 수 있다.

```rust
// 동기 방식: 10,000개 연결 = 10,000개 스레드 (약 10GB 메모리)
use std::thread;
use std::time::Duration;

fn synchronous_server_simulation() {
    let mut handles = vec![];
    
    for i in 0..10 {  // 실제로는 10,000개
        let handle = thread::spawn(move || {
            println!("클라이언트 {} 처리 중", i);
            thread::sleep(Duration::from_secs(1));
            println!("클라이언트 {} 완료", i);
        });
        handles.push(handle);
    }
    
    for handle in handles {
        handle.join().unwrap();
    }
}

// 비동기 방식: 10,000개 연결 = 작은 수의 스레드 (수십 MB 메모리)
use futures::executor::block_on;
use futures::future::join_all;

async fn asynchronous_server_simulation() {
    let mut futures = vec![];
    
    for i in 0..10000 {
        let future = async move {
            println!("클라이언트 {} 처리 중", i);
            // 비동기 sleep (실제로는 tokio::time::sleep)
            println!("클라이언트 {} 완료", i);
        };
        futures.push(future);
    }
    
    join_all(futures).await;
}
```

### I/O 대기 시간 비교

네트워크나 파일 I/O에서 비동기의 이점이 두드러진다.

```rust
use std::time::Instant;

// 동기 방식: 순차적으로 대기 (총 6초)
fn synchronous_io() {
    let start = Instant::now();
    
    // 각 작업이 2초씩 걸린다고 가정
    simulate_io_operation("작업 1", 2);
    simulate_io_operation("작업 2", 2);
    simulate_io_operation("작업 3", 2);
    
    println!("총 소요 시간: {:?}", start.elapsed());
    // 출력: 총 소요 시간: 6초
}

fn simulate_io_operation(name: &str, seconds: u64) {
    println!("{} 시작", name);
    std::thread::sleep(Duration::from_secs(seconds));
    println!("{} 완료", name);
}

// 비동기 방식: 동시에 실행 (총 2초)
async fn asynchronous_io() {
    let start = Instant::now();
    
    let task1 = simulate_async_io("작업 1", 2);
    let task2 = simulate_async_io("작업 2", 2);
    let task3 = simulate_async_io("작업 3", 2);
    
    // 모든 작업을 동시에 실행
    futures::join!(task1, task2, task3);
    
    println!("총 소요 시간: {:?}", start.elapsed());
    // 출력: 총 소요 시간: 2초
}

async fn simulate_async_io(name: &str, seconds: u64) {
    println!("{} 시작", name);
    // 실제로는 tokio::time::sleep 사용
    println!("{} 완료", name);
}
```

### 코드 복잡도 비교

비동기 코드는 동기 코드와 유사한 구조를 유지하면서도 높은 동시성을 제공한다.

```rust
// 동기 방식: 간단하지만 비효율적
fn sync_process() -> Result<String, std::io::Error> {
    let data1 = read_file("file1.txt")?;
    let data2 = read_file("file2.txt")?;
    let result = process_data(&data1, &data2);
    Ok(result)
}

// 비동기 방식: 효율적이면서도 읽기 쉬운 코드
async fn async_process() -> Result<String, std::io::Error> {
    let data1 = async_read_file("file1.txt").await?;
    let data2 = async_read_file("file2.txt").await?;
    let result = process_data(&data1, &data2);
    Ok(result)
}

// 비동기 방식 (병렬 실행)
async fn async_process_parallel() -> Result<String, std::io::Error> {
    let (data1, data2) = futures::try_join!(
        async_read_file("file1.txt"),
        async_read_file("file2.txt")
    )?;
    let result = process_data(&data1, &data2);
    Ok(result)
}

fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}

async fn async_read_file(path: &str) -> Result<String, std::io::Error> {
    // 실제로는 tokio::fs::read_to_string 사용
    Ok(format!("내용: {}", path))
}

fn process_data(data1: &str, data2: &str) -> String {
    format!("{} + {}", data1, data2)
}
```

### 게임 서버 시나리오 비교

실제 게임 서버 상황에서의 차이를 살펴본다.

```rust
// 동기 방식 게임 서버
use std::net::{TcpListener, TcpStream};
use std::io::{Read, Write};
use std::thread;

fn sync_game_server() {
    let listener = TcpListener::bind("127.0.0.1:8080").unwrap();
    
    for stream in listener.incoming() {
        match stream {
            Ok(stream) => {
                // 각 클라이언트마다 새 스레드 생성
                thread::spawn(|| {
                    handle_sync_client(stream);
                });
            }
            Err(e) => eprintln!("연결 실패: {}", e),
        }
    }
}

fn handle_sync_client(mut stream: TcpStream) {
    let mut buffer = [0; 1024];
    loop {
        match stream.read(&mut buffer) {
            Ok(0) => break,  // 연결 종료
            Ok(n) => {
                // 게임 로직 처리
                process_game_message(&buffer[..n]);
                
                // 응답 전송
                let _ = stream.write_all(b"OK");
            }
            Err(_) => break,
        }
    }
}

// 비동기 방식 게임 서버 (개념적 예제, 실제로는 Tokio 사용)
async fn async_game_server() {
    // 수천 개의 연결을 소수의 스레드로 처리
    // Tokio를 사용하면 다음 장에서 구현
}

fn process_game_message(data: &[u8]) {
    // 게임 메시지 처리 로직
    println!("메시지 처리: {} 바이트", data.len());
}
```

### 성능 특성 비교표

| 특성 | 동기 방식 | 비동기 방식 |
|------|-----------|-------------|
| 스레드 수 | 클라이언트 수와 동일 | 소수 (보통 CPU 코어 수) |
| 메모리 사용 | 높음 (스레드당 수 MB) | 낮음 (작업당 수 KB) |
| 컨텍스트 스위칭 | 많음 | 적음 |
| I/O 효율성 | 낮음 (대기 시 차단) | 높음 (대기 시 다른 작업 수행) |
| 코드 복잡도 | 낮음 | 중간 |
| CPU 집약적 작업 | 유리 | 불리 |
| I/O 집약적 작업 | 불리 | 유리 |

## 정리

이 장에서는 Rust 비동기 프로그래밍의 핵심 개념을 배웠다.

- `async`/`await` 키워드로 비동기 함수를 작성하는 방법
- Future trait의 동작 원리와 Poll의 의미
- 동기 방식과 비동기 방식의 근본적인 차이
- 게임 서버에서 비동기가 중요한 이유

비동기 프로그래밍은 I/O 집약적인 게임 서버에서 필수적이다. 수천 명의 플레이어를 동시에 처리하려면 각 연결마다 스레드를 생성하는 것은 비현실적이기 때문이다.

다음 장에서는 Rust 생태계에서 가장 인기 있는 비동기 런타임인 Tokio를 배우고, 실제로 고성능 게임 서버를 구축하는 방법을 익힌다.
