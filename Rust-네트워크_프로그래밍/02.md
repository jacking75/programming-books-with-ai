# 2장. 멀티 클라이언트 처리
1장에서 만든 Echo 서버는 한 번에 하나의 클라이언트만 처리할 수 있었다. 실제 게임 서버는 수백, 수천 명의 동시 접속자를 처리해야 하므로 동시성 처리가 필수다. 이 장에서는 스레드를 사용하여 여러 클라이언트를 동시에 처리하는 방법을 배운다.
  

## 스레드 기반 동시성
Rust는 `std::thread` 모듈을 통해 운영체제 수준의 네이티브 스레드를 제공한다. 각 클라이언트 연결마다 새로운 스레드를 생성하면 여러 클라이언트를 동시에 처리할 수 있다.

### 기본 스레드 사용법
먼저 Rust의 스레드 기본 사용법을 살펴본다.

```rust
use std::thread;
use std::time::Duration;

fn main() {
    // 새 스레드 생성
    let handle = thread::spawn(|| {
        for i in 1..10 {
            println!("스레드에서: {}", i);
            thread::sleep(Duration::from_millis(100));
        }
    });
    
    // 메인 스레드에서 실행
    for i in 1..5 {
        println!("메인에서: {}", i);
        thread::sleep(Duration::from_millis(100));
    }
    
    // 스레드가 종료될 때까지 대기
    handle.join().unwrap();
}
```

`thread::spawn()`은 클로저를 받아 새로운 스레드에서 실행한다. 반환된 `JoinHandle`을 통해 스레드의 완료를 기다리거나 결과를 받을 수 있다.
  

### 스레드 간 데이터 이동
스레드는 기본적으로 독립된 실행 컨텍스트를 가진다. 데이터를 스레드로 이동시키려면 소유권 규칙을 따라야 한다.

```rust
use std::thread;

fn main() {
    let data = vec![1, 2, 3, 4, 5];
    
    // move 키워드로 data의 소유권을 스레드로 이동
    let handle = thread::spawn(move || {
        println!("데이터: {:?}", data);
        data.iter().sum::<i32>()
    });
    
    // data는 이제 사용할 수 없음
    // println!("{:?}", data); // 컴파일 에러!
    
    let result = handle.join().unwrap();
    println!("합계: {}", result);
}
```
  

### 멀티스레드 Echo 서버
이제 각 클라이언트마다 별도의 스레드를 생성하는 Echo 서버를 만들어본다.

```rust
use std::net::{TcpListener, TcpStream};
use std::io::{Read, Write};
use std::thread;

fn handle_client(mut stream: TcpStream) {
    let peer_addr = stream.peer_addr().unwrap();
    println!("[{}] 클라이언트 연결됨", peer_addr);
    
    let mut buffer = [0; 512];
    
    loop {
        match stream.read(&mut buffer) {
            Ok(0) => {
                println!("[{}] 클라이언트 연결 종료", peer_addr);
                break;
            }
            Ok(n) => {
                let message = String::from_utf8_lossy(&buffer[..n]);
                println!("[{}] 받은 메시지: {}", peer_addr, message.trim());
                
                // Echo back
                if let Err(e) = stream.write_all(&buffer[..n]) {
                    eprintln!("[{}] 쓰기 실패: {}", peer_addr, e);
                    break;
                }
            }
            Err(e) => {
                eprintln!("[{}] 읽기 실패: {}", peer_addr, e);
                break;
            }
        }
    }
}

fn main() {
    let listener = TcpListener::bind("127.0.0.1:8080")
        .expect("주소 바인딩 실패");
    
    println!("멀티스레드 Echo 서버가 127.0.0.1:8080에서 실행 중...");
    
    for stream in listener.incoming() {
        match stream {
            Ok(stream) => {
                // 각 클라이언트마다 새 스레드 생성
                thread::spawn(move || {
                    handle_client(stream);
                });
            }
            Err(e) => {
                eprintln!("연결 실패: {}", e);
            }
        }
    }
}
```

이제 여러 클라이언트가 동시에 서버에 접속하여 통신할 수 있다. 각 클라이언트는 독립적인 스레드에서 처리되므로 서로 영향을 주지 않는다.
  

### 스레드 생성의 비용
스레드를 무제한으로 생성하는 것은 문제가 될 수 있다. 각 스레드는 메모리(일반적으로 수 MB의 스택)와 생성/해제 비용이 발생한다. 수천 개의 동시 연결이 있다면 수천 개의 스레드가 생성되어 시스템 자원을 고갈시킬 수 있다.

## 스레드 풀을 이용한 클라이언트 처리
스레드 풀(Thread Pool)은 미리 정해진 수의 스레드를 생성해두고 재사용하는 패턴이다. 이를 통해 스레드 생성 비용을 줄이고 동시 실행 스레드 수를 제한할 수 있다.

### 간단한 스레드 풀 구현
실무에서는 `threadpool` 크레이트 등을 사용하지만, 학습을 위해 간단한 스레드 풀을 직접 구현해본다.

```rust
use std::sync::{Arc, Mutex, mpsc};
use std::thread;

type Job = Box<dyn FnOnce() + Send + 'static>;

pub struct ThreadPool {
    workers: Vec<Worker>,
    sender: mpsc::Sender<Job>,
}

impl ThreadPool {
    pub fn new(size: usize) -> ThreadPool {
        assert!(size > 0);
        
        let (sender, receiver) = mpsc::channel();
        let receiver = Arc::new(Mutex::new(receiver));
        
        let mut workers = Vec::with_capacity(size);
        
        for id in 0..size {
            workers.push(Worker::new(id, Arc::clone(&receiver)));
        }
        
        ThreadPool { workers, sender }
    }
    
    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
        let job = Box::new(f);
        self.sender.send(job).unwrap();
    }
}

struct Worker {
    id: usize,
    thread: thread::JoinHandle<()>,
}

impl Worker {
    fn new(id: usize, receiver: Arc<Mutex<mpsc::Receiver<Job>>>) -> Worker {
        let thread = thread::spawn(move || {
            loop {
                let job = receiver.lock().unwrap().recv();
                
                match job {
                    Ok(job) => {
                        println!("Worker {} 작업 실행", id);
                        job();
                    }
                    Err(_) => {
                        println!("Worker {} 종료", id);
                        break;
                    }
                }
            }
        });
        
        Worker { id, thread }
    }
}
```

이 스레드 풀은 다음과 같이 동작한다.

1. 지정된 개수만큼 워커 스레드를 미리 생성한다.
2. 각 워커는 채널을 통해 작업을 받는다.
3. `execute()` 메서드로 작업을 제출하면 유휴 워커가 처리한다.
  

### 스레드 풀을 사용한 Echo 서버

```rust
use std::net::{TcpListener, TcpStream};
use std::io::{Read, Write};

fn handle_client(mut stream: TcpStream) {
    let peer_addr = stream.peer_addr().unwrap();
    println!("[{}] 클라이언트 연결됨", peer_addr);
    
    let mut buffer = [0; 512];
    
    loop {
        match stream.read(&mut buffer) {
            Ok(0) => {
                println!("[{}] 연결 종료", peer_addr);
                break;
            }
            Ok(n) => {
                let message = String::from_utf8_lossy(&buffer[..n]);
                println!("[{}] 메시지: {}", peer_addr, message.trim());
                
                if let Err(e) = stream.write_all(&buffer[..n]) {
                    eprintln!("[{}] 쓰기 실패: {}", peer_addr, e);
                    break;
                }
            }
            Err(e) => {
                eprintln!("[{}] 읽기 실패: {}", peer_addr, e);
                break;
            }
        }
    }
}

fn main() {
    let listener = TcpListener::bind("127.0.0.1:8080")
        .expect("주소 바인딩 실패");
    
    // 4개의 워커 스레드로 구성된 풀 생성
    let pool = ThreadPool::new(4);
    
    println!("스레드 풀 Echo 서버가 127.0.0.1:8080에서 실행 중...");
    println!("워커 스레드 수: 4");
    
    for stream in listener.incoming() {
        match stream {
            Ok(stream) => {
                // 스레드 풀에 작업 제출
                pool.execute(|| {
                    handle_client(stream);
                });
            }
            Err(e) => {
                eprintln!("연결 실패: {}", e);
            }
        }
    }
}
```

스레드 풀을 사용하면 동시에 실행되는 스레드 수를 제한하면서도 여러 클라이언트를 효율적으로 처리할 수 있다.

## 간단한 채팅 서버 구현 (스레드 기반)
이제 배운 내용을 활용하여 실제로 동작하는 채팅 서버를 만들어본다. 한 클라이언트가 보낸 메시지를 모든 연결된 클라이언트에게 브로드캐스트한다.

### 채팅 서버 아키텍처
채팅 서버는 다음과 같은 구조를 가진다.

1. 모든 클라이언트 연결을 추적한다.
2. 한 클라이언트로부터 메시지를 받으면 모든 클라이언트에게 전송한다.
3. 스레드 간 통신을 위해 채널을 사용한다.

### 채팅 서버 구현

```rust
use std::net::{TcpListener, TcpStream};
use std::io::{Read, Write, BufReader, BufRead};
use std::sync::{Arc, Mutex, mpsc};
use std::thread;
use std::collections::HashMap;

type ClientId = usize;

#[derive(Clone)]
enum ServerMessage {
    NewClient(ClientId, String),
    ClientLeft(ClientId, String),
    Broadcast(ClientId, String, String), // (발신자 ID, 닉네임, 메시지)
}

struct ChatServer {
    clients: Mutex<HashMap<ClientId, mpsc::Sender<String>>>,
    next_id: Mutex<ClientId>,
}

impl ChatServer {
    fn new() -> Self {
        ChatServer {
            clients: Arc::new(Mutex::new(HashMap::new())),
            next_id: Arc::new(Mutex::new(0)),
        }
    }
    
    fn add_client(&self, sender: mpsc::Sender<String>) -> ClientId {
        let mut next_id = self.next_id.lock().unwrap();
        let id = *next_id;
        *next_id += 1;
        
        self.clients.lock().unwrap().insert(id, sender);
        id
    }
    
    fn remove_client(&self, id: ClientId) {
        self.clients.lock().unwrap().remove(&id);
    }
    
    fn broadcast(&self, message: &str, sender_id: ClientId) {
        let clients = self.clients.lock().unwrap();
        
        for (id, sender) in clients.iter() {
            if *id != sender_id {
                let _ = sender.send(message.to_string());
            }
        }
    }
    
    fn broadcast_all(&self, message: &str) {
        let clients = self.clients.lock().unwrap();
        
        for (_, sender) in clients.iter() {
            let _ = sender.send(message.to_string());
        }
    }
}

fn handle_client(
    mut stream: TcpStream,
    server: Arc<ChatServer>,
    client_id: ClientId,
    receiver: mpsc::Receiver<String>,
) {
    let peer_addr = stream.peer_addr().unwrap();
    
    // 닉네임 받기
    let mut buffer = [0; 512];
    let nickname = match stream.read(&mut buffer) {
        Ok(n) if n > 0 => {
            String::from_utf8_lossy(&buffer[..n]).trim().to_string()
        }
        _ => {
            eprintln!("[{}] 닉네임 받기 실패", peer_addr);
            return;
        }
    };
    
    println!("[{}] {} 입장 (ID: {})", peer_addr, nickname, client_id);
    
    // 입장 메시지 브로드캐스트
    let join_msg = format!(">>> {} 님이 입장했습니다.\n", nickname);
    server.broadcast_all(&join_msg);
    
    // 환영 메시지 전송
    let welcome = format!("채팅방에 오신 것을 환영합니다, {}!\n", nickname);
    let _ = stream.write_all(welcome.as_bytes());
    
    // 쓰기 스레드: 다른 클라이언트의 메시지를 이 클라이언트로 전송
    let mut write_stream = stream.try_clone().unwrap();
    let write_nickname = nickname.clone();
    let write_handle = thread::spawn(move || {
        for message in receiver {
            if write_stream.write_all(message.as_bytes()).is_err() {
                break;
            }
        }
        println!("[{}] 쓰기 스레드 종료", write_nickname);
    });
    
    // 읽기 루프: 이 클라이언트의 메시지를 받아서 브로드캐스트
    let reader = BufReader::new(stream);
    for line in reader.lines() {
        match line {
            Ok(message) => {
                if message.trim().is_empty() {
                    continue;
                }
                
                println!("[{}] {}: {}", peer_addr, nickname, message);
                
                let broadcast_msg = format!("[{}] {}\n", nickname, message);
                server.broadcast(&broadcast_msg, client_id);
            }
            Err(e) => {
                eprintln!("[{}] 읽기 오류: {}", peer_addr, e);
                break;
            }
        }
    }
    
    // 연결 종료 처리
    server.remove_client(client_id);
    
    let leave_msg = format!("<<< {} 님이 퇴장했습니다.\n", nickname);
    server.broadcast_all(&leave_msg);
    
    println!("[{}] {} 퇴장 (ID: {})", peer_addr, nickname, client_id);
    
    drop(write_handle);
}

fn main() {
    let listener = TcpListener::bind("127.0.0.1:8080")
        .expect("주소 바인딩 실패");
    
    let server = Arc::new(ChatServer::new());
    
    println!("채팅 서버가 127.0.0.1:8080에서 실행 중...");
    
    for stream in listener.incoming() {
        match stream {
            Ok(stream) => {
                let server = Arc::clone(&server);
                
                thread::spawn(move || {
                    // 클라이언트별 메시지 채널 생성
                    let (sender, receiver) = mpsc::channel();
                    
                    // 클라이언트 등록
                    let client_id = server.add_client(sender);
                    
                    // 클라이언트 처리
                    handle_client(stream, server, client_id, receiver);
                });
            }
            Err(e) => {
                eprintln!("연결 실패: {}", e);
            }
        }
    }
}
```

### 채팅 클라이언트 구현
채팅 서버를 테스트하기 위한 간단한 클라이언트도 만들어본다.

```rust
use std::net::TcpStream;
use std::io::{self, Read, Write, BufRead, BufReader};
use std::thread;

fn main() {
    // 서버 연결
    let mut stream = TcpStream::connect("127.0.0.1:8080")
        .expect("서버 연결 실패");
    
    println!("채팅 서버에 연결되었습니다!");
    
    // 닉네임 입력
    print!("닉네임을 입력하세요: ");
    io::stdout().flush().unwrap();
    
    let stdin = io::stdin();
    let mut nickname = String::new();
    stdin.lock().read_line(&mut nickname).unwrap();
    
    // 닉네임 전송
    stream.write_all(nickname.as_bytes()).unwrap();
    
    // 읽기 스레드: 서버로부터 메시지 수신
    let read_stream = stream.try_clone().unwrap();
    let read_handle = thread::spawn(move || {
        let reader = BufReader::new(read_stream);
        for line in reader.lines() {
            match line {
                Ok(message) => println!("{}", message),
                Err(_) => {
                    println!("서버 연결이 끊어졌습니다.");
                    break;
                }
            }
        }
    });
    
    // 쓰기 루프: 사용자 입력을 서버로 전송
    for line in stdin.lock().lines() {
        let line = line.unwrap();
        
        if line.trim() == "/quit" {
            println!("채팅을 종료합니다.");
            break;
        }
        
        if stream.write_all(format!("{}\n", line).as_bytes()).is_err() {
            println!("메시지 전송 실패");
            break;
        }
    }
    
    drop(read_handle);
}
```

   ```bash

   ```

2. 별도의 터미널에서 여러 개의 클라이언트를 실행한다.
   ```bash
   cargo run --bin chat_client
   ```

3. 각 클라이언트에서 닉네임을 입력하고 메시지를 주고받는다.

### 스레드 기반 채팅 서버의 한계
이 채팅 서버는 동작하지만 몇 가지 한계가 있다.

1. **확장성 제한**: 각 클라이언트마다 2개의 스레드(읽기, 쓰기)가 필요하므로 수천 명의 동시 접속자를 처리하기 어렵다.

2. **리소스 소비**: 스레드는 메모리와 컨텍스트 스위칭 비용이 크다.

3. **복잡한 동기화**: `Arc<Mutex<>>` 등을 사용한 동기화 코드가 복잡하고 데드락 위험이 있다.

이러한 한계를 극복하기 위해 다음 장에서는 비동기 프로그래밍을 배우고, 이후 Tokio를 사용하여 더 효율적인 채팅 서버를 만들어본다.

## 스레드
Rust의 `std::thread` API는 크게 보면

1. 스레드 생성/종료
2. 스레드 간 동기화(데이터 공유)
3. 스레드 제어(슬립, park/unpark 등)

으로 나눌 수 있단다.
아래에서 핵심 개념 + 자주 쓰는 패턴 위주로 정리한다.


### 1. 기본 스레드 생성: `thread::spawn`

#### 1) 가장 기본적인 예제

```rust
use std::thread;
use std::time::Duration;

fn main() {
    // 새 스레드 생성
    let handle = thread::spawn(|| {
        for i in 1..=5 {
            println!("새 스레드: {i}");
            thread::sleep(Duration::from_millis(200));
        }
    });

    // 메인 스레드 작업
    for i in 1..=5 {
        println!("메인 스레드: {i}");
        thread::sleep(Duration::from_millis(200));
    }

    // 스레드 종료까지 대기
    handle.join().unwrap();
}
```

* `thread::spawn`

  * 새 OS 스레드를 만들고, 전달된 클로저를 실행한다.
  * 반환값은 `JoinHandle<T>`이다.
* `join()`

  * 해당 스레드가 끝날 때까지 현재 스레드를 블록한다.
  * 스레트 클로저의 리턴값 `T`를 `Result<T, Box<dyn Any + Send + 'static>>` 형태로 돌려준다(패닉 여부 포함).

### 2. 클로저 캡처와 `move` 키워드
스레드 클로저 안에서 바깥 변수를 쓰려면 보통 `move`를 많이 사용한다.

```rust
use std::thread;

fn main() {
    let message = String::from("hello");

    // message를 새 스레드로 소유권 이동
    let handle = thread::spawn(move || {
        println!("스레드에서: {message}");
    });

    handle.join().unwrap();
}
```

* 스레드는 메인 함수보다 오래 살 수 있기 때문에,
  **대부분의 경우 `'static + Send` 제약**이 필요하다.
  그래서 대출(borrow)보다는 **소유권 이동(move)** 형태가 기본 패턴이다.
  
### 3. 스레드 결과값 받기
스레드에서 값을 계산해서 리턴하고, `join`으로 받으면 된다.

```rust
use std::thread;

fn main() {
    let handle = thread::spawn(|| {
        // 어떤 계산
        40 + 2
    });

    let result = handle.join().unwrap(); // result: i32
    println!("결과: {result}");
}
```

* 스레드 함수의 리턴 타입이 `JoinHandle<T>`의 `T`가 된다.
* `join`이 패닉하면 `Err`가 나오기 때문에 `unwrap`이나 `match`로 처리한다.
  
### 4. 스레드 이름, 개수 제한 등: `thread::Builder`
스레드 이름을 붙이거나 스택 크기를 조정하고 싶을 때 `Builder`를 쓴다.

```rust
use std::thread;

fn main() {
    let builder = thread::Builder::new()
        .name("worker-1".to_string())
        .stack_size(4 * 1024 * 1024); // 4MB

    let handle = builder.spawn(|| {
        println!("스레드 이름: {:?}", thread::current().name());
    }).unwrap();

    handle.join().unwrap();
}
```

* `thread::current()`로 현재 스레드의 정보를 얻을 수 있다.
* 이름을 붙이면 디버깅/프로파일링 시에 보기 좋다.
  
### 5. 스레드 제어 관련 함수들

#### 1) `sleep`

```rust
use std::{thread, time::Duration};

fn main() {
    println!("1초 대기");
    thread::sleep(Duration::from_secs(1));
    println!("끝");
}
```

* OS 수준에서 해당 스레드를 슬립 시킨다.

#### 2) `yield_now`

```rust
use std::thread;

fn main() {
    // 현재 스레드의 남은 타임 슬라이스를 양보
    thread::yield_now();
}
```

* OS 스케줄러에게 “다른 스레드 먼저 돌려봐라” 정도의 힌트를 주는 용도다.

#### 3) `park` / `unpark`

* `park`는 스레드를 멈춰놓고, 다른 스레드에서 `unpark` 호출 시 다시 깨어난다.
* 간단한 신호/이벤트 구현에 사용한다.

```rust
use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        println!("park 호출 전");
        thread::park(); // 여기서 멈춤
        println!("unpark 후 실행");
    });

    // 잠시 대기
    thread::sleep(Duration::from_secs(1));
    println!("unpark 호출");
    handle.thread().unpark();

    handle.join().unwrap();
}
```

* `handle.thread()`로 해당 스레드 핸들(`Thread`)을 얻어 `unpark`를 호출한다.
  
### 6. 스레드 간 데이터 공유: `Arc<T>` + `Mutex<T>`
스레드 간에 데이터를 **공유**하면서 **수정**하려면 보통 `Arc<Mutex<T>>`를 사용한다.

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = Vec::new();

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("결과: {}", *counter.lock().unwrap());
}
```

* `Arc<T>`

  * 원자적 ref-counted 스마트 포인터
  * 여러 스레드에서 같은 데이터를 소유할 수 있게 한다(읽기/쓰기 모두는 아님, 단지 소유권 공유).
* `Mutex<T>`

  * 내부 데이터에 대한 배타적 접근을 제공하는 락이다.
  * `lock()`이 `MutexGuard`를 반환하고, 드롭될 때 락 해제된다.
* `Arc<Mutex<T>>`

  * 스레드 간에 안전하게 값 하나를 공유하고, 락 걸어가며 수정하는 가장 기본적인 패턴이다.
  
### 7. 메시지 기반 통신: 채널 (`mpsc`)
공유 메모리 대신 **메시지 패싱**으로 스레드 간 통신하기.

```rust
use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel::<String>();

    thread::spawn(move || {
        let msgs = vec![
            "하나".to_string(),
            "둘".to_string(),
            "셋".to_string(),
        ];

        for msg in msgs {
            tx.send(msg).unwrap();
            thread::sleep(Duration::from_millis(500));
        }
    });

    // 수신 스레드(여기서는 메인)
    for received in rx {
        println!("수신: {received}");
    }
}
```

* `mpsc::channel()`

  * `Sender<T>`와 `Receiver<T>`를 반환한다.
* `tx.send(T)`

  * 데이터를 소유권 이동해서 보낸다.
* `for v in rx`

  * 채널이 닫힐 때까지 블로킹하면서 메시지를 반복해서 받는다.

멀티 프로듀서를 원하면 `Sender`를 `clone()`해서 여러 스레드에 나눠주면 된다.
  
### 8. 스레드 수명과 `'static` 제약
`thread::spawn` 클로저는 기본적으로 `'static` 라이프타임 제약이 걸린다.

```rust
use std::thread;

fn main() {
    let s = String::from("hello");

    // 잘못된 예 (대부분의 경우 컴파일 오류)
    let handle = thread::spawn(|| {
        // 여기서 s를 빌림
        // println!("{s}");
    });

    handle.join().unwrap();
}
```

위와 같은 패턴은 스레드가 `main`보다 오래 살아 버릴 수 있기 때문에 안전하지 않다.

그래서 보통은:

* `move`로 **소유권을 통째로 넘기거나**,
* `'static` 데이터를 사용하거나(예: `'static` 상수)
* 혹은 `thread::scope`(아래 참고)를 사용한다.
  
### 9. 스코프 스레드: `thread::scope` (Rust 1.63+)
부모 스코프보다 오래 살지 않는 스레드를 만들고 싶을 때 `thread::scope`를 사용한다.
이 방식은 비 `'static` 참조를 안전하게 캡처할 수 있게 해준다.

```rust
use std::thread;

fn main() {
    let mut v = vec![1, 2, 3];

    thread::scope(|s| {
        // 여기서 v를 &mut로 빌려서 스레드에 넘길 수 있다.
        s.spawn(|| {
            // 불변 참조도 가능
            println!("v 길이: {}", v.len());
        });

        s.spawn(|| {
            // 다른 스레드에서도 참조 가능 (공유 참조 규칙을 만족해야 함)
            println!("첫 요소: {}", v[0]);
        });
    });

    // scope가 끝나면 여기까지 모든 스레드가 종료된 것이 보장된다.
    v.push(4);
}
```

* `thread::scope`는 스코프가 끝날 때까지 생성된 스레드들이 모두 종료됨을 보장한다.
* 그래서 `'static`이 아닌 참조를 스레드에 넘겨도 안전하다.
  
### 10. JoinHandle 드롭과 “detached” 스레드

```rust
use std::thread;

fn main() {
    thread::spawn(|| {
        // 뭔가 오래 걸리는 작업
    });

    // JoinHandle를 변수에 저장하지 않으면 곧바로 드롭된다.
    // 스레드는 백그라운드에서 계속 실행되지만, 더 이상 join할 수 없다.
}
```

* `JoinHandle`를 버리면 “detached”와 비슷한 상태가 된다.
* 실제로는 단지 핸들을 잃은 것일 뿐이고, OS 스레드는 계속 돈다.
* 대부분의 경우 종료를 기다리는 것이 안전하므로 핸들을 저장해 두고 `join`하는 패턴을 사용한다.

  
### 11. 정리 + 간단 사용 패턴 모음

#### 1) 가장 흔한 패턴들

1. **단순 병렬 작업**

   ```rust
   let handle = thread::spawn(|| 작업());
   handle.join().unwrap();
   ```

2. **데이터를 넘겨서 처리**

   ```rust
   let data = some_data;
   let handle = thread::spawn(move || f(data));
   let result = handle.join().unwrap();
   ```

3. **여러 워커 스레드 + 공유 카운터**

   ```rust
   Arc<Mutex<T>> + 여러 thread::spawn
   ```

4. **프로듀서–컨슈머**

   ```rust
   let (tx, rx) = mpsc::channel();
   // 여러 producer 스레드에서 tx.clone().send(...)
   // 한 컨슈머 스레드에서 for v in rx { ... }
   ```

5. **스코프 내에서만 사는 스레드 (비 'static 참조 사용)**

   ```rust
   thread::scope(|s| {
       s.spawn(|| { /* &v 사용 가능 */ });
   });
   ```
  
    
  
## `type Job = Box<dyn FnOnce() + Send + 'static>;` 

### 1. `FnOnce` – 한 번만 호출할 수 있는 “작업”
`FnOnce`는 **클로저/함수를 한 번만 호출할 수 있다**는 의미의 트레이트다.

* 어떤 클로저는 캡처한 값을 **소유권(move)** 으로 가져가기 때문에, 한 번 호출하면 더 이상 다시 호출할 수 없을 수 있다.
* 그런 클로저들이 구현하는 트레이트가 `FnOnce`다.
* 스레드 풀의 “작업(Job)”은 보통 **한 번만 실행하면 끝나는 작업**이기 때문에 `FnOnce`로 표현하는 것이 자연스럽다.

예시:

```rust
let x = String::from("hello");
let f = || drop(x); // x를 move로 캡처하고 drop
// f는 한 번만 호출 가능하므로 FnOnce에 해당함
```

### 2. `dyn FnOnce()` – “어떤 FnOnce든 받아들일 수 있는” 트레이트 객체
`dyn FnOnce()` 는

> “매개변수 없고 반환값 없는 `FnOnce`를 구현하는 **어떤 타입이든**”

이라는 뜻이다.

* 구체적인 타입(각 클로저 마다 타입이 다름)을 모르는 대신,
  **공통 인터페이스인 `FnOnce()`만 알고 싶을 때** `dyn FnOnce()` 같은 트레이트 객체를 쓴다.
* 즉, `Job`은 “정확한 타입은 모르지만, 호출(`()`)할 수 있는 작업”을 의미한다.
  
### 3. `Box<...>` – 힙에 올려서 “포인터”로 다루기
`Box<dyn FnOnce() + Send + 'static>` 에서 `Box`를 쓰는 이유는:

1. **트레이트 객체의 크기를 컴파일 타임에 알 수 없기 때문**이다.

   * `dyn FnOnce()` 자체는 사이즈가 미정(unsized type)이라 스택에 직접 둘 수 없다.
   * 그래서 힙에 할당하고 그 포인터(`Box`)로 다룬다.
2. 스레드 풀 큐(`VecDeque<Job>` 같은 곳)에 담거나, `mpsc` 채널로 주고받을 때
   “**같은 타입(Job)**”으로 다루려면 포인터 형태 하나로 고정하는 게 편하다.

즉,

* 실제 클로저의 타입은 제각각이지만,
* 힙에 올려서 `Box<dyn FnOnce()>`라는 **동일한 포인터 타입**으로 관리하는 구조다.
  
### 4. `+ Send` – 다른 스레드로 안전하게 보낼 수 있는 작업
`Send`는

> “이 값을 **스레드 간에 안전하게 이동(move)** 시킬 수 있다”

는 의미의 마커 트레이트다.

`Job`에 `+ Send`가 붙었다는 건:

* 이 작업(클로저 + 캡처된 데이터 전체)이 **다른 스레드로 이동해도 안전해야 한다**는 제약이다.
* 스레드 풀에서는 보통 메인 스레드에서 작업을 만들고,
  워커 스레드로 그 작업을 넘겨서 실행하므로 `Send`가 필수다.
  
### 5. `+ 'static` – 스레드보다 오래 사는(또는 소유권을 가진) 데이터만 캡처
`'static` 라이프타임은

> “이 값은 프로그램 전체 동안 유효하다”
> (혹은 “어떤 더 짧은 라이프타임에도 묶이지 않는다”)

는 의미다.

`Job`에 `+ 'static`이 붙었다는 건:

* 이 클로저가 **스택에 있는 지역 변수에 대한 참조를 캡처하면 안 된다**는 의미다.
* 대신

  * 값을 소유권으로 캡처(move) 하거나,
  * 원래부터 `'static`인 데이터(예: `&'static str`)만 사용할 수 있다.

왜냐하면:

* 작업 `Job`은 큐에 들어가 있다가,
  **나중에 워커 스레드에서 실행**될 수 있기 때문이다.
* 만약 원래 스코프가 먼저 종료됐는데, 그 스코프의 지역 변수를 참조하고 있다면
  **댕글링 참조** 문제가 생기므로, 이를 컴파일 타임에 막기 위해 `'static` 제약을 건다.

  
### 6. 결국 전체 의미 정리
`type Job = Box<dyn FnOnce() + Send + 'static>;`

이 의미하는 바는:

> “힙에 저장된,
> **한 번만 호출할 수 있는 작업(FnOnce)** 이고,
> **스레드 간에 안전하게 이동할 수 있으며(Send)**,
> **어떤 지역 스택 변수에도 의존하지 않는('static)**
> 그런 작업을 가리키는 포인터 타입”

이라고 요약할 수 있다.

스레드 풀 코드에서 자주 등장하는 패턴은 보통 이런 식이다.  
  
```rust
let (tx, rx) = mpsc::channel::<Job>();

// 작업 추가
tx.send(Box::new(|| {
    println!("작업 실행");
})).unwrap();

// 워커 스레드
thread::spawn(move || {
    while let Ok(job) = rx.recv() {
        job(); // FnOnce 호출
    }
});
```

이 구조 덕분에 스레드 풀은 “**구체 타입을 몰라도, 어떤 작업이든 큐에 넣고 워커에게 보내서 실행**”할 수 있게 된다.
